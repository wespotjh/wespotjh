## 왜 고치나 — 크롤러가 주문·결제 페이지를 마음껏 긁고 있었다

robots.txt 는 **전용 그룹이 있으면 `User-agent: *` 를 통째로 무시**한다.
`*` 그룹에는 `/order/` `/basket/` `/checkout/` 이 막혀 있지만, 전용 그룹에는 없었다.

| 그룹 | 수정 전 | 수정 후 |
|---|---|---|
| `*` | 차단 ✅ (26개) | 그대로 (26개) |
| `Googlebot` | **뚫림 ❌** (17개) | 차단 ✅ (21개) |
| **`Yeti`(네이버)** | **완전히 뚫림 ❌ (Disallow 0개)** | 차단 ✅ (21개) |
| `bingbot` | **뚫림 ❌** (17개) | 차단 ✅ (21개) |

**`Yeti` 가 가장 심했다.** `Crawl-delay: 2` 한 줄뿐이라 Disallow 가 **하나도 없었다**
→ 네이버 봇은 `/admin` `/order/` `/member/` `/protected/` 까지 **전부 크롤 가능**한 상태였다.
GA4 에 네이버 유입이 실제로 잡히므로(m.search.naver.com referral) 빈말이 아니다.

> ⚠️ 이건 **QA(문가온) 판정서가 놓친 부분**이다. 판정서 §6 지시 ① 은 Googlebot·bingbot 만
> 고치고 Yeti 는 `Crawl-delay: 2` 그대로 뒀다. 메인 세션이 라이브 원문을 파싱하다 발견해 보완했다.

## 그 외 정리

- `Sitemap:` 이 bingbot 그룹 **안**에 있었다 → 맨 위 전역으로 이동 (그룹 안에 있으면 무시될 수 있다)
- bingbot 에 `Crawl-delay` 가 **2개**(5, 10)였다 → `10` 하나로 정리 (둘이면 뒤가 무효)
- 4개 그룹 모두 `/login/` 추가

## 검수 결과 (4단계)

1. 그룹별 주문/결제 차단: Googlebot·Yeti·bingbot **뚫림 → 차단**
2. **상품·홈 경로 차단 규칙 0건** — 상품페이지가 막히면 큰일인데, 안 막았다
3. 잃어버린 규칙 **0건** — 기존 규칙은 4개 그룹 전부 그대로 유지
4. `Sitemap:` 1줄(맨 위) · 그룹별 `Crawl-delay` 각 1개
