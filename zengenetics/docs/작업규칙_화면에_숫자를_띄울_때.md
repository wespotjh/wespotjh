# 화면에 숫자를 띄울 때 — 작업 규칙

> **2026-09-11 상세페이지 「정가·할인금액」 작업 회고에서 나왔다.**
> 하루에 **7번 배포**했다 (09:37 → 23:47, 14시간). 그중 **6번은 되돌리기**였다.
> 같은 일을 두 번 겪지 않으려고 남긴다. 숫자·금액·수량을 화면에 띄우는 모든 작업에 적용한다.

---

## 0. 한 줄 요약

**7번 중 6번은 코드가 틀려서가 아니라, 「내가 맞는지 확인하는 방법」이 틀려서 돌아왔다.**

매번 나는 "확인했습니다"라고 보고했고, 매번 대표님이 폰으로 보시고 틀린 걸 찾으셨다.
고칠 것은 코드가 아니라 **검증 방법**이다.

## 1. 작업 시작 전 — 출처표 (5분, 생략 금지)

화면에 띄울 숫자를 **하나씩 적고, 그 값이 어디서 오는지** 먼저 쓴다.

| 화면에 뜰 것 | 출처 | 페이지에서 읽을 수 있나 |
|---|---|:--:|
| 정가 | ? | ? |
| 할인금액 | ? | ? |
| 상품 금액 | `#totalPrice` | O |
| 배송비 | `#freeShipGuide[data-delivery]` | O |
| 총 결제금액 | 상품금액 + 배송비 | O |

**「?」나 「X」가 하나라도 있으면 코드를 쓰지 않는다. 대표님께 먼저 묻는다.**

> 2026-09-11에 이걸 안 했다. 「옵션별 정상가는 페이지 어디에도 없다」는 사실을
> **5라운드째에** 알아냈다. 대표님이 가격표를 주시자 그 자리에서 끝났다.
> 첫날 물었으면 라운드 5·6은 아예 없었다.

### 물어야 할 것의 예
- 이 숫자의 정가/원가는 어디 있습니까? (관리자? 상세페이지 이미지? 대표님 머릿속?)
- 화면에 쓰인 할인율은 **무엇 기준**입니까? (쿠폰 전? 후?)
- 쿠폰은 자동 적용입니까, 고객이 직접 누릅니까?

## 2. 코드를 쓸 때 — 3가지 금지

### ① 추측 금지 · 조용한 기본값 금지
못 구하면 **모른다(0/null)를 돌려주고 화면에서 감춘다.** 지어내지 않는다.

```js
var packs = m ? parseInt(m[1],10) : 1;   // ❌ 못 읽으면 조용히 1
if (!packs) return 0;                     // ⭕ 모르면 모른다
```
> 이 한 줄 때문에 104에서 「정가 294,000(1개분) − 상품금액 255,000(6set분)」을 빼
> **가짜 할인 39,000원**이 떴다.

### ② 자기 자신과의 일관성은 검사가 아니다
`정가 − 할인 = 상품금액` 은 **틀린 정가를 넣어도 항상 성립한다.**
반드시 **바깥 기준**과 대조한다 — 페이지가 스스로 광고하는 할인율, 대표님 가격표, 관리자 값.

> 나는 63번을 「산식일치 ✅」로 보고했다. 실제로는 25%를 63%로 표시하고 있었다.

### ③ 이름에서 숫자를 줍지 않는다
행 텍스트에는 **상품명이 앞에 붙는다.** 「칼륨(2box) & 비컴(1box) SET」의 `2box`를 집어
어떤 옵션을 골라도 정가가 2배로 고정됐다.
옵션값만 있는 노드(`p.product span`)에서 읽거나, 아예 이름에 의존하지 않는다.

## 3. 검증할 때 — 고객 화면 기준으로만

아래 5개는 전부 **실제로 겪은 오판**이다. 하나라도 어기면 검증이 아니다.

| 하지 말 것 | 무슨 일이 났나 | 대신 |
|---|---|---|
| 소스 토큰 개수로 판정 | 페이지가 깨져 있는데 "전부 정상" 보고 | 렌더해서 눈으로 본다 |
| `hidden` 속성을 「숨김」으로 셈 | 속성은 붙었는데 CSS가 이겨 **화면엔 그대로 보임** | `getComputedStyle` + `getBoundingClientRect().height` |
| 시트를 안 열고 값 읽기 | 숨은 조상 안에서 읽어 **아무도 못 보는 상태**를 검사 | 고객 경로대로 열고 잰다 |
| 데스크톱 UA HTML을 모바일 폭으로 렌더 | 없는 겹침을 「결함」으로 오인, 고칠 뻔함 | 아이폰 UA로 받은 HTML |
| 외부 스크립트 막힌 미러로 판정 | jQuery가 안 붙어 **카페24 앱 주입이 아예 안 돎** → 카카오·네이버 버튼을 못 봄 | 앱이 실제로 도는 미러 |

### 합성 입력의 한계 (중요)
`Input.dispatchTouchEvent`(CDP 합성 터치)는 **`touch-action`을 제대로 타지 않는다.**
차단된 요소에서 끌어도 본문이 밀린다. **거짓 합격·거짓 불합격이 둘 다 난다.**
→ 터치·스크롤 동작은 **CSS 속성 자체를 계약으로 검사**하고, 실제 끌기는 라이브 미러에서 눈으로 본다.

### 반드시 넣는 상태 3가지
숫자를 띄우는 작업은 **이 세 상태를 전부** 본다. 하나만 봐서 여섯 번 돌아왔다.

1. **아무것도 안 골랐을 때** → 금액 줄이 안 보여야 한다
2. **골랐을 때** → 값이 정확해야 한다 (바깥 기준과 대조)
3. **골랐다 취소했을 때** → **지난 금액이 남으면 안 된다** ← 대표님이 찾아내신 것

## 4. 전달·배포할 때

| 규칙 | 이유 |
|---|---|
| 파일명에 **날짜·버전**을 넣는다 (`detail_css_0911_v5.css`) | 같은 이름으로 두 번 보내 **예전 파일이 올라갔다** |
| 저장소 파일에 **BOM 금지** (전달본에만) | 번들 **중간**에 U+FEFF가 들어가 CSS가 깨졌다 (검사 39건 동시 실패) |
| 라이브 확인은 **캐시 무력화** + 번들까지 | CDN 캐시를 라이브로 오인해 "안 올라갔다"고 **오진**했다 |
| 올린 뒤엔 **바이트 단위 대조** | 편집기가 큰 파일을 잘라먹을 수 있다 |

```bash
curl -sS -H "Cache-Control: no-cache" "https://.../ds/css/detail.css?cb=$(date +%s)"
```

## 6. 규칙 → 이걸 지키는 검사

말로만 남기면 또 잊는다. 아래는 **이미 코드에 박아둔** 검사다.

| 규칙 | 검사 ID | 무엇을 막나 |
|---|---|---|
| 안 골랐을 때 금액 줄 비노출 | `C8.sum.start` | 처음부터 「정가 —」가 떠 있던 것 |
| 취소 후 잔상 없음 | `C8.sum.untapped` · `C8.sum.empty` | **대표님이 찾으신 그 결함** |
| 그 검사가 헛돌지 않는가 | `C8.sum.live` | 시트를 안 열어 전부 공허하게 통과하던 것 |
| 계산 못 하면 정가 줄을 띄우지 않는다 | `C14b.*.list` | 지어낸 할인 금액 |
| 합계가 버튼에 안 깔린다 | `C13.*.covered` | 「할인금액」 줄 잘림 |
| 5줄 상태에서 잰다 | `C13.*.rows` | 3줄일 때만 봐서 못 잡던 것 |
| 간편결제·찜 비노출 | `C9.*.payvis` · `C13.*.appBox` | 앱이 런타임에 되살리는 버튼 |
| 스크롤 격리 계약 | `C14.*.tub*` | 시트 열고 스와이프 시 본문 밀림 |
| 저장소 파일 BOM 0개 | `B5.head.*` · `B5.any.*` | 번들 중간 BOM으로 CSS 붕괴 |

**검사를 고칠 때 주의** — 「탐지값(probe)」이 0이면 그 검사는 **아무것도 확인하지 못한 것**이다.
통과로 보이지만 거짓이다. 실제로 `E2.probe`가 404 개수를 탐지값으로 써서,
404가 0이 되자(정상 상태!) 스스로 실패했다.

**baseline 갱신 시 주의** — 갱신은 **깨진 값도 굳힌다.**
`a11y_select` 가 22/2 → 0/0 으로 굳으려 한 적이 **두 번** 있다. 갱신 후 반드시 의미 차이를 눈으로 본다.

## 7. 한 번에 끝내는 순서

```
① 출처표 작성 → 「?」 있으면 대표님께 질문 (여기서 안 물으면 나중에 5라운드 더 돈다)
② 코드 작성 — 추측 금지, 바깥 기준과 대조하는 검산 포함
③ 라이브 미러로 3상태 확인 (안 고름 / 고름 / 취소) × 전 상품 × 전 옵션 × 수량 1·2
④ 회귀 검사 전체 통과
⑤ 날짜·버전 박은 파일명으로 전달
⑥ 올라온 뒤 캐시 무력화해서 바이트 대조 + 라이브 미러로 재확인
```

③을 건너뛰고 ⑤로 가면 대표님이 ③을 대신 하시게 된다. **그게 7번의 이유였다.**
