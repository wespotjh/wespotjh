**성격** **시안이다. `cafe24-skin/` 에는 한 줄도 쓰지 않았다.** 대표님이 한 안을 고르시면 그때 개발이 이식한다.

## 2. 프레임을 몇 장까지 줄일 수 있나 — **실제로 열어 보고 판단했다**

24장을 전부 펼쳐 보고, 앞뒤 프레임의 평균 밝기차를 재서 어디가 진짜 변하는지 확인했다.

| 구간 | 프레임간 변화량(칼륨 / 마그네슘 / 비타민B) | 판정 |
|---|---|---|
| 01 → 02 | **0.47 / 0.31 / 0.25** | **사실상 같은 그림.** 둘 다 맹물 잔. **02는 버려도 아무도 모른다** |
| 03 → 10 | 2.0 ~ 3.6 | **여기가 전부다.** 가루가 떨어져 기둥이 생기는 구간 |
| 11 → 16 | 1.3 ~ 2.1 | 퍼짐. 절반만 남겨도 이어져 보인다 |
| 17 → 24 | **0.9 ~ 1.5, 계속 감소** | 바닥에 가라앉는 중. **20~24는 서로 거의 같다** |

그래서 **균등하게 자르지 않았다.** 변화가 큰 앞쪽을 촘촘히, 뒤쪽을 성기게 골랐다.

- **12장 (A안)** — 01, 03, 04, 05, 06, 07, 08, 09, 11, 14, 18, 24
- **8장 (B·D안)** — 01, 04, 06, 08, 10, 13, 18, 24
- **1장 (C안)** — 15번 (기둥이 가장 예쁘게 선 컷)

> **8장이 손익분기점**이라고 본다. 스크롤 구간이 140vh 로 짧아지므로 8장이면 약 17vh 마다 한 장 —
> 손가락 한 번 튕길 때 3~4장이 지나간다. 24장을 300vh 에 뿌리던 지금(12.5vh/장)과 체감 밀도가 거의 같다.
> **장수를 줄이는 게 아니라, 짧아진 스크롤에 맞춰 밀도를 유지하는 것이다.**

## 3. 안별 상세

### A안 — 좌우 분할 (대표님 안 그대로)

**한 줄:** 왼쪽 컵, 오른쪽에 제품명·문장·숫자·버튼을 전부 몰아넣는다.

| | |
|---|---|
| 스크롤 | 300vh → **160vh** (스크럽 60vh) |
| 프레임 | 24장 → **12장** |
| 용량 | 519KB → **239KB** |
| 모바일 390 | **좌우 포기 → 위 컵 / 아래 글** |

**삭제해도 되는 것 / 절대 안 되는 것**

| 대상 | 판정 | 이유 |
|---|---|---|
| 프레임 02번 | **삭제** | 01번과 같은 그림 (변화량 0.25~0.47) |
| 프레임 20·21·22·23 | **삭제** | 서로 거의 같다 |
| `.zg-hint` 「↓ 스크롤」 | **삭제** | 잠금 구간이 60vh 로 짧아져 안내가 필요 없다 |
| `.zg-plate::after` 하단 흰 페이드 12% | **삭제** | 컵이 왼쪽 칸에 갇혀 아래로 새지 않는다 |
| **별도 `.zg-phead` 한 화면** | **삭제(흡수)** | 제목을 오른쪽 칸으로 끌어들인다. **여기서 화면 하나가 통째로 없어진다** |
| **별도 `.zg-cta-wrap` 한 화면** | **삭제(흡수)** | 버튼을 스테이지 안으로 |
| 숫자 `525`·`20` 과 단위 문구 | **절대 유지** | 대표님 확정 |
| 캡션 4문장 | **절대 유지** | 대표님 확정. 문구를 새로 짓지 않았다 |
| `h2` 제목 · eyebrow · 설명문 · 주의문구 | **절대 유지** | 「*칼륨 스틱은 당류가공품입니다」, 「건강기능식품 · 질병의 예방 및 치료를 위한 의약품이 아닙니다」 포함 |
| CTA 3개 (`product_no=11/16/13`) | **절대 유지** | GA4 `select_item` 이 붙는 링크다 |

**좋은 점** — 대표님 아이디어 그대로다. 데스크톱에서 지금의 텅 빈 화면이 채워진다. 위험이 가장 낮다.
**아쉬운 점** — **얻는 게 데스크톱뿐이다.** 390px 에서는 좌우로 쪼갤 수 없어(각 180px/170px) 위아래로 돌아간다.
결국 모바일 손님이 보는 그림은 지금과 같고, 짧아지기만 한다.
**데스크톱·모바일 코드가 두 벌**이 되므로 나중에 손볼 때마다 두 번 손봐야 한다.

### B안 — 레이어형 (컵을 깔고 글을 얹는다) ★ 추천

**한 줄:** 좌우로 **쪼개는 대신 겹친다.** 컵 사진은 원래 좌우에 흰 여백이 26%씩 있는 사진이라,
그 여백 위에 글을 얹으면 어느 쪽도 좁아지지 않는다.

| | |
|---|---|
| 스크롤 | 300vh → **140vh** (스크럽 40vh) |
| 프레임 | 24장 → **8장** |
| 용량 | 519KB → **164KB** |
| 모바일 390 | **구조 그대로.** 컵을 화면 폭 가득 깔고 글을 아래에 겹친다 |

**삭제해도 되는 것 / 절대 안 되는 것**

| 대상 | 판정 | 이유 |
|---|---|---|
| 프레임 16장 (02·03·05·07·09·11·12·14~17·19~23) | **삭제** | 앞은 촘촘, 뒤는 성기게 8장을 남긴다 |
| `.zg-hint` 「↓ 스크롤」 | **삭제** | 위와 같음 |
| `.zg-plate::after` 12% 페이드 | **삭제(교체)** | 겹침용 흰 그라데이션(scrim)이 그 역할을 대신한다 |
| 별도 `.zg-phead` · `.zg-cta-wrap` 화면 | **삭제(흡수)** | 스테이지 안으로 |
| 데스크톱 `.sub` 설명문 | **유지** (오른쪽 칸 안) | |
| 모바일 `.sub`·주의문구 | **유지, 자리만 이동** | 스테이지 밖 바로 아래 한 줄로. 지우지 않았다 |
| 숫자·캡션 4문장·제목·주의문구·CTA 3개 | **절대 유지** | A안과 동일 |

**좋은 점**
- **데스크톱과 모바일이 같은 그림, 같은 코드 한 벌.** 앞으로 고칠 때 한 번만 고친다.
- 모바일에서 **컵이 지금보다 오히려 커진다** (약 460px → 약 620px). 칸을 나누지 않으니 세로를 다 쓴다.
- 대표님 방향(좌 컵 · 우 글)을 데스크톱에서 그대로 지킨다.

**아쉬운 점**
- 글이 사진 위에 놓이므로 **흰 그라데이션의 세기를 잘 맞춰야 한다.** 시안에서 맞춰 놓았지만 실기에서 한 번 확인이 필요하다.
- 모바일에서 컵 바닥 약 20%가 그라데이션에 덮인다. (제일 볼 것 없는 부분이라 일부러 그쪽을 덮었다)

### C안 — 정지형 카드 (스크롤 잠금 없음)

**한 줄:** 대표님 지적을 끝까지 밀어붙인 안. 잠금을 없애고, 컵은 정지 사진 1장, 문장 4줄은 한 번에 다 보여준다.

| | |
|---|---|
| 스크롤 | **sticky 0.** 블록 자연높이 모바일 100vh / 데스크톱 68vh (실측) |
| 프레임 | 24장 → **1장** |
| 용량 | 519KB → **24KB** |
| 모바일 390 | 위 사진 / 아래 글 (잠금이 없어 세로 비용이 안 든다) |

**삭제해도 되는 것 / 절대 안 되는 것**

| 대상 | 판정 | 이유 |
|---|---|---|
| 프레임 71장 | **삭제** | 15번 한 장만 남긴다 |
| sticky·스크럽 코드 전체 | **삭제** | `home-blocks.js` 의 스크롤 리스너가 통째로 필요 없어진다 |
| `.zg-hint` | **삭제** | |
| **캡션 4문장** | **절대 유지 — 다만 표현이 바뀐다** | 스크롤로 하나씩 갈아 끼우지 않고 **4줄을 세로로 함께** 보여준다. 문구는 그대로다 |

**좋은 점** — 가장 짧고 가장 가볍고 가장 안 깨진다. GA4 열독 지표 왜곡이 **완전히** 사라진다.
**아쉬운 점** — **「물에 녹는다」를 눈으로 증명하던 장면이 없어진다.** 분말 제품에서 그 장면은 제품 설명 그 자체다.
전부 버리는 건 과할 수 있다. **채택안이라기보다 비교 기준선으로 봐 주십시오.**

### D안 — 3제품 1스테이지 통합

**한 줄:** 제품 3개가 각각 300vh 를 쓰던 것을, **셋이 한 화면을 나눠 쓰게** 한다.
스크롤을 내리면 같은 자리에서 컵 색이 라임 → 포도 → 사과로 바뀌고 오른쪽 글·숫자·버튼이 그 제품 것으로 갈아 끼워진다.

| | |
|---|---|
| 스크롤 | 3제품 900vh → **3제품 합쳐 265vh** |
| 프레임 | 72장 → **24장** (제품당 8장) |
| 용량 | 519KB → **164KB** |
| 모바일 390 | B안과 같은 겹침 + 위에 제품 알약 3개 |

**삭제해도 되는 것 / 절대 안 되는 것**

| 대상 | 판정 | 이유 |
|---|---|---|
| 프레임 48장 | **삭제** | 제품당 8장 |
| **제품별 머리글 화면 3개 → 1개로 통합** | **삭제(통합)** | 여기서 절감이 가장 크게 난다 |
| **제품별 CTA 버튼 3개 → 자리 1개(내용이 바뀜)** | **⚠️ 구조 변경** | 링크 3개는 그대로 살아 있지만 **한 번에 하나만 보인다** |
| 숫자·캡션 4문장×3제품·제목·설명문·주의문구 | **절대 유지** | 설명문·주의문구는 스테이지 아래 한 벌로 모아 두었다 |

**좋은 점** — 페이지 절감이 압도적이다(−72%). 손님이 세 제품을 한자리에서 비교하게 된다.
**아쉬운 점** — **구조 변경 폭이 가장 크다.**
- 제품마다 서 있던 제목 화면과 버튼이 없어진다.
- CTA 링크가 스크롤에 따라 바뀌므로 **GA4 `select_item` 계측 방식을 배시우와 다시 맞춰야 한다**(설계로그 #9 N-H1 대상).
- 세 제품을 한 자리에 넣으면 각 제품의 인상이 옅어질 수 있다.

## 5. 내 추천 — **B안**

**이유 셋.**

1. **대표님 아이디어를 버리지 않으면서 모바일 문제를 실제로 푼다.**
   데스크톱은 대표님이 말씀하신 그대로 좌 컵 · 우 글이다. 390px 에서는 쪼개는 대신 겹쳐서,
   **컵이 오히려 지금보다 커진다**(약 460px → 약 620px). A안은 모바일에서 지금으로 되돌아갈 뿐이다.

2. **코드가 한 벌이다.** A안은 데스크톱용·모바일용 두 벌을 유지해야 한다.
   이 구간은 앞으로도 계속 손볼 곳인데, 두 벌이면 손볼 때마다 두 번 틀린다.

3. **버릴 걸 버리고 살릴 걸 살린다.** 페이지는 −57%, 이미지는 −69% 줄이면서
   **「물에 녹는다」 장면은 남긴다.** C안은 그걸 버리고, D안은 제품별 존재감을 걸고 도박한다.
   지금 대표님이 지적하신 건 **분량**이지 **그 장면 자체**가 아니라고 읽었다.

**덧붙임 —** D안(−72%)이 숫자로는 제일 좋다. 다만 구조 변경이 커서 **B안을 먼저 넣고 반응을 본 뒤
D안을 다음 단계로 검토**하는 순서를 권한다. B → D 는 이어붙이기 쉽고, D → B 는 되돌리기 어렵다.
