# cafe24 가격 백엔드 구조 — 관리자 입력 → 스킨 변수 → 화면

> 대표님 지시(2026-09-06): *"가격은 cafe24 상품 등록에서 설정하는 거고, 그걸 긁어오는 거라
> 너가 그 백엔드 구조를 이해해야 해."*
> 이 문서가 그 구조다. **가격은 우리가 쓰지 않는다. cafe24가 준 것을 받아 그리기만 한다.**
> 근거는 라이브 zengenetics.co.kr 렌더 결과 + 스킨 템플릿·JS 원문 대조 (2026-09-06).

---

## 0. 한 줄 요약

**cafe24는 「소비자가」와 「판매가」 두 숫자만 준다. 할인율(%)은 주지 않는다 — 스킨 JS가 그 자리에서 계산한다.**

칼륨 예: 소비자가 45,000 · 판매가 34,900 → 스킨이 `100 − (34900×100÷45000) = 22.4` → 반올림 **22%**

---

## 1. 관리자 입력란 → 스킨 변수 → DOM

| cafe24 관리자 (상품등록) | 스킨 변수 | 상세페이지 DOM | 상품리스트 카드 DOM |
|---|---|---|---|
| **소비자가** | `{$product_custom}` | `.price-spec__item.product_custom_css` → `#span_product_price_custom` `<strike>45,000원</strike>` | `li.product_custom` (취소선) · `<li data-custom="45000">` |
| **판매가** | `{$product_price}` | `.price-spec__item.product_price_css` → `#span_product_price_text` `34,900원` | `li.product_price` · `<li data-price="34900">` |
| **할인판매가**(기간할인) | `{$product_price_sale}` | `.prd_price_sale_css` → `#span_product_price_sale` (cafe24가 % 를 직접 줌) | `.prd_price_sale` |
| **상품명** | `{$name}` | `h1.prd-name` · `.product_name_css` | `li.name` |
| **상품요약설명** | `{$simple_desc}` | `.summary-info` · `.simple_desc_css` | `li.summary_desc` |
| **배송비** | `{$delivery_price}` | `.delivery_price_css` → "3,500원 (50,000원 이상 구매 시 무료)" | — |
| **추가항목1** | `{$custom_option1}` | `.custom_option1_css` (값 `1`) → 오늘출발 사용여부 | — |
| **추가항목2** | `{$custom_option2}` | `.custom_option2_css` (값 `14`) → 오늘출발 마감 **14시** | — |
| **쿠폰 적용가** | `{$c_dc_price_apply}` | `.infoArea[data-coupon]` | — |
| **상품번호** | `{$product_no}` | `.infoArea[data-prd-no]` · 알파리뷰 `data-value` | `li#anchorBoxId_11` |

상세페이지 최상단 `.infoArea` 가 이 값들의 **집합소**다 (스킨 JS가 여기서 읽는다):

```html
<div class="infoArea" data-name="{$name|striptag}" data-desc="{$summary_desc}"
     data-price="{$product_price}" data-custom="{$product_custom|replace:.00,}"
     data-coupon="{$c_dc_price_apply|numberformat}" data-prd-no="{$product_no}">
```

## 2. 할인율(%)은 스킨이 계산한다 — 하드코딩 금지

`moa/js/product/detail.js` → `calcDiscountPer()` 원문:

```js
var getPrice  = $('.infoArea').data('price');    // 판매가   34900
var getCustom = $('.infoArea').data('custom');   // 소비자가 45000

if ($('.prd_price_sale_css').length < 1) {            // 기간할인이 안 걸린 평상시
    if (Number(getPrice) < Number(getCustom)) {
        var calcPrice    = 100 - (Number(getPrice) * 100 / Number(getCustom));
        var discountRate = Math.round(calcPrice);     // 22
        infoArea.find('.price-spec__item.product_price_css')
                .prepend('<span class="discount-per">' + discountRate + '</span>');
    }
    if (Number(getPrice) == Number(getCustom)) {
        $('.price-spec__item.product_custom_css').addClass('displaynone');  // 정가=판매가면 정가 줄 숨김
    }
}
if ($('#span_product_price_sale').length > 0) {       // 기간할인이 걸린 경우
    var discountRate = $('#span_product_price_sale').find('span').text().replace('%','');
    $('.price-spec').addClass('is-sale');              // cafe24가 준 % 를 그대로 사용
    infoArea.find('.price-spec__item.prd_price_sale_css')
            .prepend('<span class="discount-per">' + discountRate + '</span>');
}
```

**따라서 우리 페이지가 지켜야 할 규칙**

1. `22%` 같은 숫자를 **직접 쓰지 않는다.** 정가·판매가 두 값만 자리를 잡아두면 %는 스킨이 채운다.
2. **정가 = 판매가면 정가 줄이 자동으로 사라진다.** 정가 줄을 CSS로 항상 보이게 강제하면 안 된다.
3. 기간할인을 걸면 마크업이 `prd_price_sale_css` 로 바뀌고 `.price-spec` 에 `is-sale` 이 붙는다.
   **우리 디자인은 이 두 경우를 모두 받아내야 한다.**
4. `.discount-per` 는 **JS가 나중에 prepend 하는 요소**다. 우리 CSS에 이 클래스 스타일이 있어야 한다.

> 참고: `moa/js/lib/calc_sale_rate.js` 도 같은 계산을 하지만 `data('product_price')`
> (= `data-product_price` 속성)를 읽는데 이 쇼핑몰 카드에는 그 속성이 없다 (`data-price`/`data-custom` 뿐).
> **즉 리스트 카드에서는 이 스크립트가 아무 일도 하지 않는다.** 리스트에 할인율 뱃지를 넣으려면
> 별도 처리가 필요하다 — 지금은 안 나온다.

## 4. 추가항목1·2 = 오늘출발 (가격 아님)

`product/detail.html`:
```html
<div class="shipping-today" data-hour="{$custom_option2}" data-run="{$custom_option1}">
```
- `custom_option1` = `1` → 오늘출발 **사용**
- `custom_option2` = `14` → 마감 **14시**

그리고 `moa/js/product/detail.js` 마지막 줄이
`$('.custom_option1_css, .custom_option2_css').remove()` 로 가격줄에서 이 두 항목을 **지운다.**
그래서 화면에 숫자 `1`·`14` 가 안 보인다. **이 remove 를 막으면 가격줄에 1과 14가 튀어나온다.**

## 5. 혜택가 카드(`.ds_benefit`) — 폐기 (2026-09-06 대표님 확정)

`custom_option3`(회원가) / `custom_option4`(플친가) 표시항목을 읽어 카드를 그리는 기능이었으나
**대표님이 "카드 혜택 안 쓰고 우리 걸로 가자" 확정.** 사유:

- **카카오 플러스친구 혜택은 "배송비 무료"뿐이고 가격 혜택은 없다.**
  `price-config.js` 의 플친 쿠폰 `20,100원` 은 **지금 하지 않는 이벤트**의 잔재다. (대표님 확인)
- 라이브에서도 이미 꺼져 있다 (`custom_option3/4` 미표시 → `detail.js` 가 즉시 return).

**조치**: `ds/css/price.css` 는 **라이브 원본 그대로 복원**했다 (스킨 미러 정합 유지).
우리 디자인으로 만든 대체안은 `_preview/price/` 에 보관만 한다.
`price.html`·`price-config.js`·`detail.js` 는 원본 유지 — 나중에 되살릴 수 있게 남겨둔다.

## 6. 우리 페이지가 cafe24로 이식될 때 (실행 규칙)

```html
<!-- 우리 상품페이지 가격 영역 -->
<div class="zg-price">
  <span class="zg-price__rate"></span>            <!-- ← 비워둔다. 스킨 JS가 .discount-per 로 채움 -->
  <span class="zg-price__now">{$product_price}</span>
  <span class="zg-price__was">{$product_custom}</span>
</div>
```
- 숫자·퍼센트를 절대 타이핑하지 않는다
- 정가 줄은 **없어질 수 있다**는 전제로 레이아웃을 짠다 (정가=판매가인 데이팩 60번이 실제 그렇다)
- 기간할인 상태(`.price-spec.is-sale` · `prd_price_sale_css`)에서도 깨지지 않게 한다
- 배송비 문구도 `{$delivery_price}` 를 그대로 받는다 (3,500원/5만원 무료를 우리가 쓰지 않는다)
