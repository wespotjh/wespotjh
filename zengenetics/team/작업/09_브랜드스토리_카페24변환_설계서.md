## 1-2. 근거 — 라이브에서 직접 확인한 사실

카페24가 어떤 경로를 서빙하는지, **추측하지 않고 실제로 받아 봤다.**

| 요청 경로 | 결과 | 이 경로가 증명하는 것 |
|---|---|---|

| `/ds/html/price.html` | **200 · 72,370 B** | `@import` 전용 조각 파일도 **경로만 맞으면 그대로 서빙된다** |

**⇒ 카페24 = 「URL 경로 → 스킨 파일」 단순 매핑.** 관리자에서 URL 을 따로 등록하는 절차가 없다. 파일을 만들면 그 경로가 곧 URL 이다.

**서빙 방식도 확인했다:** `/ds/html/price.html` 은 `@layout` 지시자가 없어서 **레이아웃 없이 알맹이만** 내려온다(`<html>` 0개, 헤더·푸터 0개). 즉 **`<!--@layout(...)-->` 한 줄이 헤더/푸터/GA4 를 붙이는 스위치**다. 우리 페이지는 반드시 이 줄을 첫 줄에 둔다.

## 1-3. 나머지 3안을 버린 이유 (전부 실측 근거)

### ❌ 안2. 게시판(`/board/...`)  ⚠ **이 문단의 기각 근거는 틀렸다 → §11-2 로 교체됨 (판정은 유지)**
- 실물: 「복용법」 = `/board/gallery/list.html?board_no=8`, 「고객센터」 = `/board/free/list.html?board_no=1`.
- **치명적:** 게시판 본문은 관리자 에디터가 입력하고, 카페24는 그 안의 `<img>` 를 **`ec-data-src` 로 바꿔 지연로딩**한다(이벤트 페이지 실측: `<img ec-data-src="/web/upload/NNEditor/...">` 6장).
  이 페이지는 `.cover{overflow:hidden}` 인 전면 커버가 **5장**이다. **칼륨 브리프가 경고한 바로 그 함정** — 잘린 영역 안에서는 IntersectionObserver 가 교차하지 않아 영영 안 뜬다.
- URL 이 `?board_no=8&no=NN` 형태라 브랜드 페이지로 쓸 주소가 못 된다.
- 게시글 본문에 `<style>`/`<script>` 를 넣는 것은 관리자 에디터의 필터링에 의존한다 — 우리가 통제할 수 없다.
- 게시판 껍데기(제목·작성자·목록/이전글 버튼·댓글)를 지울 수 없다.

### ❌ 안3. 상품 상세설명(관리자 콘텐츠)
- 더미 상품을 만들어야 한다 → 분류·가격·장바구니·구매하기 버튼·재고가 딸려온다. 실수로 노출되면 **판매 사고**다.
- 상세설명(NNEditor)도 `ec-data-src` 경로다(위와 동일한 함정).
- 칼륨 브리프 §3 「상세설명(NNEditor) 내용 수정 금지」와 충돌한다.

### ❌ 안4. 「추가 페이지」 기능
- 카페24 스마트디자인에 *디자인 관리의 별도 「추가 페이지」 메뉴* 는 없다. **「추가 페이지」에 해당하는 실체는 두 가지뿐**이고 둘 다 확인했다:
  1. **디자인 편집기의 [화면 추가]** — 결국 **안1과 같은 것**이다(스킨에 파일을 만드는 행위). 대표님이 이미 `ds/css/detail.css`·`ds/js/detail-ui.js` 를 이 방식으로 만들기로 되어 있다(QA 4차 체크리스트 ②③).
  2. **이벤트(기획전)** — 실물 확인: 「멤버십 혜택」이 `/event/detail.html?product_no=93&cate_no=61` 이다. 관리자에서 내용을 넣지만 **본문이 이미지 나열 + `ec-data-src`** 이고, 하단에 「이벤트 진행 상품」 슬라이드가 강제로 붙는다. 우리 페이지는 타이포그래피·다크모드·카운트업이 본체라 **전부 그림으로 눕히는 순간 페이지의 이유가 사라진다.**

### ✅ 안1을 고른 결정적 이유 3가지
1. **이미지가 `ec-data-src` 를 타지 않는다.** 스킨 템플릿 안의 `<img src>` 는 카페24가 건드리지 않는다(라이브 스킨 이미지 `/moa/img/default/flag_kr.svg` 가 평범한 `src` 로 나온다). `.cover{overflow:hidden}` 문제가 **원천적으로 발생하지 않는다.**
2. **버전관리·되돌리기가 칼륨과 같은 규칙 위에 놓인다.** 저장소 git ↔ 전달본 `.txt` ↔ md5 대조 체계를 그대로 쓴다. 관리자 콘텐츠는 이 체계 밖이라 되돌릴 수 없다.
3. **URL 이 사람이 읽을 수 있다** (`/brand-story.html`). 메뉴·광고·인스타 프로필에 그대로 쓴다.

## 1-4. 배포 시점 — 반드시 알아야 할 것

**작업본 스킨은 지금 적용되어 있지 않다.** 따라서 이 파일을 저장해도 라이브는 변하지 않고, **칼륨 상세 배포의 「⑨ 적용」 한 번에 브랜드 스토리도 같이 공개된다.**
→ 칼륨 배포와 **같은 판에 실을지, 다음 판으로 뺄지**는 팀장·대표님 결정 사항이다(§7 A-1).

## 1-5. 경로 선택 — 최상위 vs `ds/html/`

| | `/brand-story.html` (권장) | `/ds/html/brand-story.html` (차선) |
|---|---|---|
| URL 품질 | 좋음 | 나쁨 (내부 폴더가 노출) |
| 폴더 신설 | **없음** (최상위엔 `index.html`·`about.html` 이 이미 있다) | **없음** (`ds/html/` 존재) |
| [화면 추가] 확실성 | 최상위 폴더 선택 가능 여부를 **편집기에서 눈으로 봐야 함** | `ds/` 계열은 이미 같은 방식으로 파일을 만들기로 확정 |
| 이름 충돌 | `/brand-story.html` **현재 404** = 비어 있음(확인) | `/ds/html/brand-story.html` **현재 404** = 비어 있음(확인) |

> **폴더는 새로 만들지 않는다.** 지난 `ga4.js` 폴더 사고의 규칙(QA 체크리스트 ①)을 그대로 지킨다.
> 편집기에서 최상위에 [화면 추가]가 안 되면 **그 자리에서 멈추고 알려 주시면** 차선으로 전환한다(파일 안의 코드는 한 글자도 안 바뀐다. 이미지 경로만 그대로).

# 2. 라이브 조사 결과

## 2-1. 기존에 브랜드스토리 비슷한 페이지가 있는가 → **있다. `/about.html`**

```
GET /about.html  →  200 · 191,511 B
현재 위치: 홈 > 브랜드 소개
<div class="hero" df-banner-code="about-top" hidden> … </div>
<div class="about"   df-banner-code="about"     hidden> … </div>
```

- **모아스튜디오 스킨이 제공하는 「브랜드 소개」 페이지**다.
- 본문이 **전부 배너매니저 앱(`df-banner-code`) 슬롯**이고, 두 슬롯 다 `hidden` = **등록된 배너가 0건이라 화면에 아무것도 없다.**
- 진입점: **푸터 「회사소개」** (`policy__item display-m` — 모바일에서만 보임). 사이트맵에는 없다.

**판단:** 이 파일을 우리 페이지로 덮어쓰지 않는다.
① 덮으면 모아 배너매니저 연동이 사라져 되돌리기가 어렵다(원본 소스를 우리가 갖고 있지 않다).
② 「회사소개」(법인 정보 성격)와 「브랜드 스토리」(서사)는 성격이 다르다.
③ 우리 페이지는 새 URL 로 두고, 나중에 대표님이 원하시면 `/about.html` 을 `/brand-story.html` 로 리다이렉트/링크만 바꾸면 된다.

## 2-2. 사이트맵 — 정적 페이지가 무엇인지

`/sitemap.xml` 200 · 3,318 B · **URL 23개**뿐:
- 홈 1 · `shopinfo/company.html` · `member/agreement.html` · `member/privacy.html` · 게시판 1 · 분류 7 · 상품 12
- **`/about.html` 은 사이트맵에 없다.** → 카페24 사이트맵은 **관리자에 등록된 것(상품·분류·게시판·약관)만** 넣는다. **스킨 커스텀 페이지는 자동으로 안 들어간다.**
- **⇒ `/brand-story.html` 도 사이트맵에 자동 등록되지 않는다.** §7 E-3 에 대표님 작업으로 올린다.

## 2-3. 메뉴 구조 — 어디를 고쳐야 「웰니스 ▸ 브랜드 스토리」가 붙는가

메뉴는 **관리자 분류가 아니라 스킨 마크업**이다. 라이브 HTML 에 편집 안내 주석이 그대로 남아 있어 위치가 명확하다.

| 화면 | 스킨 파일 | 현재 마크업 | 하위메뉴 패턴 |
|---|---|---|---|
| 데스크톱 가로 nav | `moa/layout/header.html` | `<li class="category__item">` + `<!-- 🔽 리뷰 메뉴 -->` 주석쌍 | 「이벤트」가 `<div class="sub-category"><ul class="sub-category__list">` 로 **이미 드롭다운을 쓰고 있다** |
| 모바일 햄버거 패널 | `moa/layout/aside.html` (`xans-layout-slidepackage`) | `<li class="aside-category__item">` + 같은 주석쌍 | 「이벤트」가 `<a class="aside-category__toggle cate">` + `<ul class="aside-child">` 로 **이미 아코디언을 쓰고 있다** |

**⇒ 04 문서가 프로토타입에 새로 만든 드롭다운/아코디언을 라이브로 옮길 필요가 없다. 스킨에 이미 있는 「이벤트」 블록을 복제해 「웰니스」로 바꾸고, 「리뷰」 블록을 지우면 끝이다.**

### 04 문서 §6 「경로 확인 필요」 2건 — **여기서 해소됐다**

라이브 `aside` 마크업에서 실제 값을 읽었다:

| 메뉴 | 04 문서 | **라이브 실제 값 (확정)** |
|---|---|---|
| 멤버십 혜택 | `#` | `https://zengenetics.co.kr/event/detail.html?product_no=93&cate_no=61&display_group=1` |
| 고객센터 | `#` | `/board/free/list.html?board_no=1` |

프로토타입 `home.html` · `brand-story.html` 의 드로어 `href="#"` 2곳씩(총 4곳)을 이 값으로 바꾸면 04 문서 §6 이 닫힌다. (이번 과제 범위 밖 — §7 B-4 로 올린다.)

### 프로토타입이 가리키는 「브랜드 스토리」 링크가 틀려 있다

`site/brand-story.html` · `site/home.html` 의 드로어·nav 에서 「브랜드 스토리」가
`https://claude.ai/code/artifact/1fd7a5ca-973c-4731-b9db-af263ab98343` (아티팩트 미리보기)를 가리킨다.
**배포 후 `https://zengenetics.co.kr/brand-story.html` 로 바꿔야 한다.** (§7 B-3)

# 4. CSS / JS 충돌 분석 — 무엇을 어떻게 네임스페이스하는가

## 4-1. 실측한 충돌

- 전 페이지에 실리는 스킨 전역 CSS **17개 파일 · 188,912 B · `!important` 98개**
- 프로토타입이 쓰는 클래스 **75개**를 전수 대조:

| 충돌 클래스 | 스킨 셀렉터 수 | `!important` 포함 |
|---|--:|--:|
| `.spec` | 66 | **11** |
| `.wrap` | 11 | 0 |
| `.close` | 5 | 0 |
| `.aside` | 5 | 0 |
| `.top` | 4 | 0 |
| `.grid` | 1 | 0 |
| 나머지 69개 | 0 | 0 |

- **더 위험한 것은 요소 셀렉터다.** 스킨 전역 CSS 의 맨몸 셀렉터: `li` **71**, `img` **42**, `h2` **15**, `h3` **13**, `ul` **13**, `p` **10**, `table` **5**. 프로토타입은 `<h2> <p> <ul> <li> <img> <table>` 을 그대로 쓴다.
- **CSS 변수는 충돌 0.** `--paper --panel --ink --rule --deep --accent --serif --sans --mono` 전부 스킨에 0회 (`--m` 만 7회 — **이름을 `--zg-m` 으로 바꾼다**).

## 4-2. 방침 — 칼륨과 같은 규칙

1. **래퍼 `.zgbs` 1개**로 전부 감싸고 **모든 셀렉터에 `.zgbs` 를 접두**한다 → 구체도 +1 로 스킨을 이긴다.
   `.spec`(66개·`!important` 11개)도 `.zgbs .spec` 이면 `!important` 를 제외하고는 전부 이긴다. **`.spec` 는 아예 `.zg-spec` 으로 개명해 회피한다.**
2. **새 `!important` 0개.** (칼륨 정정 5 규칙 승계)
3. `body{}` · `*{}` · `:root{}` **전역 규칙 금지.** 프로토타입의 `body{margin:0;background:…;font-family:…;overflow-x:hidden}` 을 그대로 옮기면 **쇼핑몰 전 페이지가 바뀐다.** → `.zgbs{…}` 로 내린다. 변수는 `.zgbs{--zg-paper:…}` 에 선언한다(변수도 `--zg-` 접두).
4. 단문자 클래스(`.c .d .m .n .r .s .t .v .h`)는 **전부 `.zg-` 접두**로 개명한다. 지금은 충돌 0이지만 스킨이 갱신되면 즉시 깨진다.
5. `zgm-*` `zgb` `zgs*` (드로어) 클래스는 **파일에서 통째로 삭제**한다(B-02).
6. `viewport` 는 스킨이 `width=device-width, user-scalable=no` 로 고정 — 프로토타입의 `initial-scale=1` 은 **넣지 않는다**(head 는 우리 파일이 아니다).

## 4-3. 다크모드 — 결정 필요

- **스킨에 `prefers-color-scheme` 이 0회**다. 헤더·푸터·햄버거 패널은 **항상 라이트**다.
- 프로토타입은 완전한 다크 팔레트를 갖고 있다. 그대로 켜면 **본문만 검고 헤더·푸터는 흰** 화면이 된다.
- **권장(설계 기본값): 다크 팔레트를 삭제하지 않고 `.zgbs` 안에 그대로 두되 기본 비활성**으로 둔다. 한 줄(`@media (prefers-color-scheme:dark)` 블록 주석 해제)로 켤 수 있게 남긴다. → **대표님 결정 항목** (§7 A-2)

## 11-1. ★ C-1 — `<title>` · `og:*` 는 **해결 못 한다** (R-4 전면 재작성)

**§8 R-4 의 처방 「인라인 `<script>` 로 `document.title` · `meta[description]` · OG 태그를 설정한다」 중 OG 부분은 무효다. 삭제한다.**

### 왜 무효인가
**카카오톡·페이스북·인스타그램·네이버(Yeti) 크롤러는 JavaScript 를 실행하지 않는다.** 이들은 서버가 준 원본 HTML 의 `<meta property="og:*">` 만 읽는다. JS 로 바꿔도 **공유 카드에는 100% 반영되지 않는다.**
→ **무효인 코드를 남기면 다음 사람이 「돼 있다」고 오해한다.** 그래서 아예 쓰지 않는다.

### 페이지 타입별 실측 (개발 재측정 · iPhone UA · 2026-09-07)

| 페이지 | `<title>` | `og:title` | `og:image` |
|---|---|---|---|
| 상품 상세(11) | **고유** — `젠제네틱스 포타슘 칼륨 (20ea) \| 붓기 제거 · 전해질 밸런스…` | **고유** — `젠제네틱스 포타슘 칼륨 (20ea) - Zengenetics` | **고유** — 상품 대표이미지 |
| 게시판(복용법 8) | **고유** — `젠제네틱스 복용법 총정리 \| 붓기부스터·퍼포먼스부스터…` | 게시판명 — `복용법 - Zengenetics` | **몰 공용** `share-image-1-….jpg` |
| 이벤트(93) | `이벤트 - 진행중인 이벤트 - Zengenetics` | 동일 | 상품 이미지 |
| **`/about.html` (커스텀)** | **`젠제네틱스 공식몰`** | **`젠제네틱스 공식몰`** | **몰 공용** |
| 홈 | `젠제네틱스 공식몰` | `젠제네틱스 공식몰` | 몰 공용 |
| `/shopinfo/company.html` · `/member/agreement.html` | `젠제네틱스 공식몰` | — | — |

**⇒ 카페24는 관리자에 등록된 타입(상품·분류·게시판·이벤트)에만 고유 메타를 준다. 스킨 커스텀 페이지는 몰 기본값으로 고정된다.**
`og:url` 만은 페이지별로 맞게 나온다(`/about.html` → `https://zengenetics.co.kr/about.html` 실측).

### 우회로 3개 — 전부 막혔다 (QA 검토, 개발 동의)

| 후보 | 판정 |
|---|---|
| 관리자 › SEO › **주요 페이지 SEO 태그** | ❌ **고정 목록.** `/shopinfo/company.html`·`/member/agreement.html` 같은 **표준 화면조차** 기본값으로 떨어진다(실측) |
| 관리자 › SEO › **코드 직접입력** | ❌ **전 페이지 공통(PC/모바일 각 1개).** 여기에 브랜드스토리 `<title>` 을 넣으면 **모든 페이지가 그 제목이 된다.** **2026-09-06 에 실제로 난 사고**(전 페이지 `<title>` 2개)이고 이미 복구됐다(오늘 실측: 전 페이지 `<title>` **1개**). **다시 여는 길이므로 절대 쓰지 않는다** |
| `@layout` 없이 자체 `<head>` 를 갖는 독립 페이지 | ❌ 스마트 주문서가 그 구조인데 `<title>` 이 `젠제네틱스 공식몰` 로 덮인다(칼륨 4차 실측). 게다가 헤더·푸터·GA4 를 직접 만들어야 하고 **R-8(메뉴 2벌)** 과 정면 충돌 |

### 그래서 개정된 R-4

> **R-4 (개정) — `<title>` 과 `og:*` 는 이 방식으로는 해결할 수 없다.**
> - **`document.title` · `meta[name=description]` 은 JS 로 설정한다** — Google 렌더 크롤러에만 유효하다. **그 한계를 코드 주석에 적는다.**
> - **`og:title` · `og:description` · `og:image` 는 JS 로 설정하지 않는다.** 무효이므로 코드를 아예 두지 않는다.
> - **결과: 이 페이지를 카카오톡·페이스북·인스타로 공유하면 카드가**
>   제목 `젠제네틱스 공식몰` / 설명 `단일 성분, 빠른 흡수 Zengenetics` / 이미지 `share-image-1-9398931b….jpg` (몰 공용) **로 뜬다.** (실측값)
> - **이 페이지 용도가 「인스타 프로필 · 광고 랜딩」(§7 C-3)이므로 이것은 사소한 문제가 아니다.**

### ★ 대표님 결정 항목 (신규 A-3)

> **A-3. 이 페이지를 인스타 프로필·광고 랜딩으로 쓸 것인가?**
> - **(가) 쓴다** → 공유 카드가 몰 공용으로 뜨는 것을 **감수**한다. (링크를 눌러 들어온 뒤의 화면은 정상이다. 카드 미리보기만 몰 기본값이다.)
> - **(나) 공유 카드가 중요하다** → 이 콘텐츠를 **게시판(`board_no`)에도 한 벌 얹는** 방안을 별도 검토한다. 게시판은 고유 `<title>` 을 갖는다(단 `og:image` 는 여전히 몰 공용, `og:title` 은 게시판명 — **완전한 해결은 아니다**).
> - **(다) 광고에는 상품 페이지를 쓰고**, 브랜드 스토리는 사이트 내부 회유 동선으로만 쓴다.

**소관 이관:** 이 항목의 뿌리는 장부 **E-2(홈 `<title>` P0)** 와 같다. **SEO 담당(문가온)에게 이관**하고, 설계서는 「해결 못 함」을 명시만 한다.
**덤(문가온 이관):** 전 페이지에 **`<meta name="description">` 2개 · `<meta name="keywords">` 2개**가 남아 있다(홈·상품·게시판·이벤트·about **5종 전부 실측 확인**). `<title>` 2개는 복구됐으나 이 둘은 그대로다.

## 11-2. ★ C-2 — 안2(게시판) 기각 근거 교체 (§1-3 정정)

### 내가 틀린 것

§1-3 에 *"게시판 본문은 카페24가 `<img>` 를 `ec-data-src` 로 바꾼다(**이벤트 페이지 실측 6장**)"* 라고 썼다.
**그 실측은 「이벤트」에서 얻은 것이고 「게시판」에 적용되지 않는다. 이벤트 결과를 게시판 근거로 전용(轉用)한 것이 오류다.**

**개발 재측정 (iPhone UA · 2026-09-07):**

| 페이지 | `ec-data-src` |
|---|--:|
| 이벤트 `/event/detail.html?product_no=93` | 6 |
| 상품 상세 `?product_no=11` | 14 |
| **게시판 `/board/gallery/list.html?board_no=8`** | **0** |
| `/about.html` · 홈 | 0 |

**⇒ 게시판에는 지연로딩 함정이 없다. 그리고 게시판만 고유 `<title>` 을 갖는다(§11-1).
즉 내가 가장 무겁게 든 기각 사유가 안2 에는 성립하지 않았고, 오히려 안2 가 §11-1 문제를 부분적으로 푼다.**

### 그래도 안1 이 옳다 — 남는 기각 사유 4가지 (이것이 교체된 근거다)

| # | 사유 | 내용 |
|:--:|---|---|
| **1. URL** | 게시판 글 주소는 `/board/gallery/read.html?no=NN&board_no=8` 다. **브랜드 페이지·광고 랜딩 주소로 쓸 수 없다.** `/brand-story.html` 과 비교 불가 |
| **2. 껍데기 통제 불가** | 제목·작성자·작성일·조회수·목록/이전글/다음글 버튼·댓글창을 **지울 수 없다.** 게시판 스킨을 고치면 **다른 게시판 5개(리뷰 4·상품후기 6·고객센터 1·자유 3·공지 1)가 같이 바뀐다** |
| **3. 코드 소유권** | 본문의 `<style>`/`<script>` 가 **관리자 에디터의 필터링 정책에 달려 있다.** 우리가 그 정책을 볼 수 없고, 카페24가 언제든 바꿀 수 있다. **16 KB CSS + 2 KB JS 를 남의 필터에 맡기는 설계는 성립하지 않는다** |
| **4. 버전관리·되돌리기** | 관리자 콘텐츠는 **git ↔ 전달본 `.txt` ↔ md5 체계 밖**이다. 칼륨 라운드가 세운 「해시로 관리한다」 규칙이 적용되지 않고, **잘못되면 되돌릴 수 없다** |

### ★ 트레이드오프 명시 (1차 문서에 없던 대가)

> **안1 을 고르면 `<title>`·`og:*` 를 포기한다.** 안2(게시판)를 골랐다면 고유 `<title>` 은 얻었을 것이다.
> **그 대가를 알고 고른다.** 위 4가지(특히 3·4번)가 **되돌릴 수 없는 성질**이라 더 무겁다고 판단했다.
> `<title>` 문제는 **A-3 결정**과 **문가온 이관**으로 따로 다룬다(§11-1).

*(안3 상품상세 · 안4 이벤트의 기각 사유는 §1-3 그대로 유효하다 — 둘 다 `ec-data-src` 14 / 6 으로 **직접 실측**했고 전용이 아니다.)*

## 11-3. ★ C-3 · C-4 — CSS `url()` 은 **전부 루트 절대경로**

### 함정
`ds/css/brand-story.css` 는 `<!--@css()-->` 로 선언되면 **`/ind-script/optimizer_user.php?filename=…` 번들 안으로 들어간다.**
번들의 실제 URL 이 `/ind-script/…` 이므로, CSS 안의 **상대 `url()` 은 `/ind-script/` 기준으로 해석되어 404 가 난다.**

```
잘못:  src: url(bs-serif-400.woff2)        → /ind-script/bs-serif-400.woff2   ❌ 404
잘못:  src: url(../image/bs-map.webp)      → /ind-script/image/bs-map.webp    ❌ 404
옳음:  src: url(/ds/css/bs-serif-400.woff2)                                    ✅
```

### 스킨이 이미 이 규칙을 지키고 있다 (개발 재측정)

| 번들 | 바이트 | `url()` | **상대경로** | `@font-face` | `!important` |
|---|--:|--:|--:|--:|--:|
| 시스템 CSS 번들 | 24,495 | 2 | **0** | 0 | 5 |
| **사용자 CSS 번들** | **156,896** | **27** | **0** | **0** | **99** |

- **번들 안에 `@font-face` 가 0개**다. Pretendard 의 `@font-face` 는 번들이 아니라 **`moa/layout/fonts.html` 의 인라인 `<style>`** 에 있고 `url(/moa/fonts/…)` **루트절대**다.
- *(QA 는 상품 페이지에서 207,864 B / `!important` 164 를 쟀다. 페이지마다 `@css` 집합이 달라 크기가 다르다 — **상대경로 0 · `@font-face` 0 이라는 결론은 두 측정에서 동일**하다.)*

### 적용 범위 — **예외 없이 전부**

| 대상 | 규칙 |
|---|---|
| `@font-face { src: url(…) }` | `/ds/css/bs-serif-400.woff2` · `/ds/css/bs-serif-600.woff2` |
| `background-image: url(…)` | 쓰지 않는다. **이미지 15장은 전부 `<img src>`** (지연로딩·`width`/`height`·`alt` 때문) |
| CSS 안 그 밖의 모든 `url()` | **루트절대.** `data:` URI 도 쓰지 않는다(용량) |
| `brand-story.html` 안의 `src`/`href` | 전부 루트절대 `/ds/image/…` |
| `brand-story.js` 안의 경로 | 하드코딩 경로 **0개** (동적 로드 없음) |

**기계 검수 항목:** `brand-story.css` 에 대해 `url(` 뒤 첫 글자가 `/` 가 **아닌** 것 **0건**을 확인한다.

### C-4 — 폰트는 **`ds/css/`** 에 둔다 (1차의 `ds/image/` 에서 변경)
새 폴더 0개인 것은 같다. **업로더가 폴더 성격으로 확장자를 거를 경우 이미지 폴더가 `.woff2` 를 거절할 확률이 더 높다**는 QA 지적을 수용한다.
`url()` 이 어차피 루트절대이므로 **코드 차이는 경로 문자열 하나뿐**이다.

**woff2 서빙은 증명됐다:** `/moa/fonts/pretendard/PretendardVariable.subset.0.woff2` → **200 · 36,424 B**(개발 실측). MIME 이 `application/octet-stream` 이지만 **`nosniff` 는 font 목적지에 적용되지 않고, 지금 라이브에서 Pretendard 가 그 MIME 으로 정상 렌더 중**이다 — 존재 증명.
**미증명인 것은 「편집기 [파일 업로드]가 `.woff2` 를 받는가」 하나뿐**이고, `/moa/fonts/` 는 구매 스킨 동봉본이라 업로더의 증거가 아니다. → **①②에서 이미지 15장과 폰트 2개를 같이 올려 한 번에 판정**한다(왕복 0회). 막히면 **Google Fonts `<link>` 1줄 폴백**(코드 한 줄 차이).

## 11-4. ★ C-5 · C-6 · C-7 — 번들 순서 · 지시자 · 주석 규칙

### C-5. 우리 CSS 는 사용자 번들 **1번**이다

카페24 번들 규칙(칼륨·홈에서 확정): **① 콘텐츠 페이지의 직접 선언(줄 순서) → ② 레이아웃 → ③ import.**
`brand-story.html` 은 **`@css` 를 자기가 처음 선언하는 페이지**다(다른 콘텐츠 `@css` 가 없다).
→ `ds/css/brand-story.css` 가 **번들 맨 앞**에 놓인다 = `layout/basic/css/*` 17개, `moa/css/*` 전부보다 **앞**.
→ **구체도가 같으면 전부 진다.**

| 대결 | 구체도 | 승자 |
|---|---|---|
| `.zgbs h2` vs 스킨 `h2` | (0,1,1) vs (0,0,1) | **우리** ✅ |
| `.zgbs .zg-spec` vs 스킨 `.spec` | 개명해서 **대결 자체가 없음** | — |
| `.zgbs .fig` vs 스킨 `.foo .fig` | (0,2,0) vs (0,2,0) **동률** | **스킨** (뒤에 있으므로) ❌ |
| 아무거나 vs 스킨 `!important` (99~164개) | — | **스킨** ❌ |

**규칙 (검수 항목으로 승격):**
1. **`.zgbs` 접두를 예외 없이 전 셀렉터에 적용한다.** `@font-face` · `@keyframes` · `:root` 대체(`.zgbs{--zg-…}`) 를 제외하고 **접두 없는 셀렉터 0개**를 기계적으로 센다.
2. **동률이 나올 수 있는 클래스는 이기려 하지 말고 회피(개명)한다.** `.spec`→`.zg-spec` 이 그 사례다. 1차 §4-2-4 의 단문자 클래스 `.zg-` 개명도 같은 이유로 유지.
3. **새 `!important` 0개** (칼륨 정정 5 승계). 스킨 `!important` 는 이길 수 없으므로 **부딪히지 않게 설계**한다.

### C-6. `<!--@css()-->` / `<!--@js()-->` **만** 쓴다
- 생 `<link rel="stylesheet" href="/ds/css/…">` · `<script src="/ds/js/…">` **금지.** 칼륨 F-6 이 이 사고였다(절대경로 생 태그 → 404).
- `brand-story.html` 1~3줄:
  `<!--@layout(/layout/basic/layout.html)-->` → `<!--@css(/ds/css/brand-story.css)-->` → `<!--@js(/ds/js/brand-story.js)-->`
- **`moa/layout/head.html` 은 고치지 않는다** — 폰트·GA4 재삽입 금지(1차 §9-3 유지).

### C-7. HTML 주석 규칙 (칼륨 R-6 승계)
- **주석 안에 `{$` 를 쓰지 않는다** — 카페24는 **HTML 주석 안의 `{$변수}`도 치환한다.**
  (이 페이지는 `{$변수}` 를 쓰지 않아 사고 확률은 낮지만 규칙은 승계한다.)
- **HTML 주석은 공개 소스에 그대로 나간다.** 18 KB 파일의 설계 주석에 **내부 인명·판정 용어·문서 경로·해시**를 쓰지 않는다.
  (허용: `<!-- 커버 1 / LCP 대상 -->` · 금지: `<!-- 오세진 REJECT R-3 반영 -->`)

### 왜 H2 만 남기지 않았는가

### 흡수 지점 — 08 「회사」 두 번째 문단

| | 문장 |
|---|---|
| **전** | 안 팔리면 다음 제품이 없으니 안 팔릴 제품을 만들 수가 없습니다. 과장해서 팔면 두 번째 주문이 없으니 과장할 수도 없습니다. **재구매율을 제일 자주 들여다보는 이유가 그겁니다.** |
| **후** | 안 팔리면 다음 제품이 없으니 안 팔릴 제품을 만들 수가 없습니다. 과장해서 팔면 두 번째 주문이 없으니 과장할 수도 없습니다. **숫자도 같은 기준으로 다룹니다. 어느 기간, 어느 채널에서 나온 값인지 함께 적을 수 없으면 그 숫자는 쓰지 않습니다.** |

- **길이 증가 0에 가깝다** — 삭제한 마지막 문장(「재구매율을…」)과 맞바꿨다.

## 12-5. ★ 유지하되 대표님 확인이 필요한 것 — **제품 규격 수치 (신규 A-5)**

대표님 표에 없던 항목이라 **개발이 임의로 지우지 않았다.** 성격이 다르기 때문이다.

| 구분 | 성격 | 처리 |
|---|---|---|
| **마케팅 성과 수치** (리뷰·평점·재구매율·수출국·랭킹·채널) | 우리가 주장하는 성과 | **전량 삭제** (§12-0~3) |
| **제품 규격 수치** (함량·중량·원료사·인증) | **제품 라벨(표시사항)에서 나오는 값** | **A-5 확인 대기 — 기본값 유지** |

### 확인이 필요한 이유 — **개발은 이 값들을 검증할 수 없다**

라이브 상품 11·13·16 을 받아 **HTML 텍스트에서 전수 검색**했다:

| 찾은 문자열 | 상품 11 | 상품 13 | 상품 16 |
|---|--:|--:|--:|
| `262.5` · `525mg` · `400mg` · `2.5g` · `2g 스틱` | **0** | **0** | **0** |
| `HACCP` · `GMP` · `콜마비앤에이치` · `Jungbunzlauer` · `구연산칼륨` | **0** | **0** | **0** |

**0인 이유는 값이 틀려서가 아니라, 이 값들이 전부 상세설명 PNG 이미지 안에만 있어 텍스트로 존재하지 않기 때문이다.**
(상품정보 표에서 텍스트로 확인된 것은 상품명·가격·**배송비 `3,500원 (50,000원 이상 구매 시 무료)`** 뿐이다.)

**다만 이 수치들은 본문이 스스로 출처를 밝히고 있다** — 05 섹션 마지막 문장:
> 「자세한 원재료명과 영양정보는 **각 제품 페이지 하단 표시사항**에 전부 적혀 있습니다.」

즉 **「출처를 적지 않은 수치」가 아니라 「출처를 적은 수치」**다. 그래서 삭제 대상과 분리했다.
