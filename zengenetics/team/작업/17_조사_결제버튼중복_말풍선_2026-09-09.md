# R-4 말풍선 텍스트 잘림 — **원인 확정. 우리 CSS 다. 1줄이면 고쳐진다.**

캡처 `team/작업/11차_캡처/04_말풍선_현재_390.png` 에 그대로 나온다 — 노란 배경은 26px 인데

## 2. 원인 — 우리가 버튼에 준 `line-height` 가 말풍선으로 **상속**된다

```css
/* ds/css/detail.css — 우리 것 */
.zg-detail .productAction [class^='btn'].sizeL.gFull {
  height: var(--zg-bar-h);        /* 54px */
  line-height: var(--zg-bar-h);   /* 54px  ← 이 값이 자식으로 흘러간다 */
}
```
```css
/* 스킨 것 — height 만 있고 line-height 가 없다 */
.benefit-bubble > a { position:absolute; top:-28px; height:26px; display:flex; align-items:center; font-size:12px; }
```

말풍선 `<a>` 는 `div.btnSubmit.gFull.sizeL` 의 자식이다. 스킨은 `line-height` 를 지정하지 않으므로 **우리 값 54px 를 상속**한다.
26px 짜리 flex 상자 안에 54px 짜리 줄상자가 들어가 아래로 8px 밀려난다.

**대조 실험 (같은 페이지·같은 문구, `.zg-detail` 클래스만 제거 = 스킨 원본 상태)**

| 조건 | `line-height` | 글자가 pill 위로 넘침 | 아래로 넘침 | 판정 |
|---|:--:|:--:|:--:|:--:|
| **현재(우리 CSS 적용)** | **54px** | −20.0 | **+8.0** | ❌ 잘림 |
| 우리 CSS 없음(스킨 원본) | 12px | −6.0 | −6.0 | ✅ 정상 |
| **`line-height:1.2` 만 되돌림** | 14.4px | −5.8 | −6.2 | ✅ **정상** |

⇒ **8차 F-3 에서 넣은 `.productAction{margin-top:37px}` 와는 무관하다.** 그것은 말풍선의 *세로 위치*를 옮겼을 뿐이고,
이번 건은 말풍선 *안쪽* 줄상자 높이 문제다. 두 건은 별개다.

## 3. 고치는 방법 (승인 대기 — 이번 판은 조사만)

```css
/* ds/css/detail.css 에 1블록 추가 — !important 0 */
.zg-detail .benefit-bubble > a { line-height: 1.2; }
```
- 상속만 끊는다. 스킨 규칙·앱 산출물(`{#title}`·`style="{#html}"`)은 건드리지 않는다.
- 구체도 (0,2,1) → 우리 다른 규칙과 충돌 없음. `!important` 불필요.
- 캡처 `06_말풍선_lineheight교정_390.png`.

## 4. 같이 발견한 것 — **가로 여유가 없다 (이쪽은 관리자 조치 후보)**

말풍선은 「구매하기」 버튼 기준 `left:50%` 중앙 정렬이고 **폭을 지정하지 않아 글자 길이만큼 늘어난다.**

| 조건 | pill 폭 | pill 오른쪽 끝 | 뷰포트/컨테이너 오른쪽 |
|---|:--:|:--:|:--:|
| 현재(우리 CSS) | 198px | **375.8** | 374 (`.infoArea-footer`) → **1.8px 초과** |
| 우리 CSS 없음 | 198px | 384.8 | 374 → **10.8px 초과** |

**우리 CSS 가 오히려 9px 덜 넘친다**(`.buy-btn-wrap` 을 `gap:9px` 로 넓혀 버튼이 왼쪽으로 왔다).
즉 **가로 넘침은 우리 회귀가 아니라 스킨·문구 길이 문제**다. 문구가 더 길어지면 더 넘친다.

**분리 보고:**
- **우리 책임(고침):** 세로 잘림 = `line-height` 상속 (§2·§3).
- **관리자 조치 후보:** 배너매니저 문구 길이. 지금 문구(18자)에서 이미 컨테이너를 넘는다. **문구를 줄이거나**(예: 12자 이내) 그대로 두거나는 대표님 판단이다. 코드로 줄바꿈을 강제하면 26px 상자에서 두 줄이 되어 더 나빠진다 — **폭 문제는 문구로 푸는 편이 안전하다.**

# R-3 결제 버튼 중복 — **⚠ 그냥 숨기면 판매가 멈춘다. 실측으로 확인했다.**

## 5. 실물 구조 (라이브 런타임 조상 체인)

```
DIV.zg-detail

    └ DIV.mobile-layer.jsMobileLayer          ← 바텀시트 본체
       └ DIV.mobile-layer__inner

             │   └ .buy-btn-wrap
             │       ├ button.actionCart   onclick="product_submit(2,…)"
             │       └ div.btnSubmit       onclick="product_submit(1,…)"
             │           └ span.benefit-bubble       ← 말풍선이 여기 산다
             └ .app-pay-wrap (#NaverChk_Button · #appPaymentButtonBox)

```

**`#fixedActionButton` 은 바텀시트 안에 있다.** 이것이 이번 건의 전부다.

## 6. 지시하신 5가지에 대한 답

### ① 카페24 자체 스크립트가 `#fixedActionButton` 을 참조하는가 — **한다. 2곳.**

| 위치 | 내용 | 숨겼을 때 |
|---|---|---|
| 스킨 번들 `globalBuyBtnScrollFunc` | `sFixId = $('#orderFixItem').length ? … : 'fixedActionButton'` → 스크롤 시 `$item.offset().top` 으로 `#orderFixArea` 를 여닫는다 | **실측 무해.** 숨긴 상태로 2600px 까지 스크롤해도 `#orderFixArea` 는 `display:none` 유지(추가 바가 튀어나오지 않는다) |
| 카페24 옵션레이어 `SHOP_FRONT_PRODUCT_OPTIONLAYER.init` | 주석에만 등장(관심상품 분기 설명). 코드 참조 아님 | 무해 |

**그러나 진짜 문제는 스크립트 참조가 아니라 시트 구조다 — 아래 ③.**

### ② 말풍선이 구매하기 버튼 안에 있다 → **인라인을 숨기면 말풍선도 같이 사라진다. 실측 확인.**
숨긴 상태에서 말풍선 박스 = `0×0`. **그래서 R-3 과 R-4 는 한 몸이다.**

### ③ 하단 고정바는 인라인에 **위임한다. 독립이 아니다.** ← **가장 중요**

스킨 원문:
```js
function mobileLayerOn() {                       // 바의 「구매하기」(.jsLayerBtn) 가 부르는 함수
    if ($('.jsMobileLayer').hasClass('fixed')) {
        $('.jsMobileLayer, .jsMobileLayerBG').addClass('on');   // ← 시트를 연다
        …
    } else {
        $('.buy-btn-wrap').find('.btnSubmit.gFull.sizeL').trigger('click');  // ← 인라인 구매하기를 대신 누른다
        …
    }
}
```

- **`.fixed` 아닐 때:** 바의 구매하기가 **인라인 버튼을 프로그램으로 클릭**한다 → 인라인이 없어지면 그 경로가 죽는다.
- **`.fixed` 일 때(= 실제로 바가 보이는 상태):** 시트를 연다. **그리고 시트 안의 구매 버튼이 바로 `#fixedActionButton` 이다.**

**실측 (390px, 스크롤 2600 → `.mobile-layer` 가 `.fixed` → 바의 구매하기 클릭):**

| 조건 | 시트 열림 | 시트 안 `#fixedActionButton` | 화면에 보이는 `product_submit(1,…)` |
|---|:--:|---|:--:|
| 현재 그대로 | ✅ (`mobile-layer … fixed on`) | 보임 (top 774 ~ 828, 시트 758~844 안) | **1개** |
| **`#fixedActionButton{display:none}`** | ✅ | **안 보임 (0×0)** | **0개** ← **구매 불가** |

바에 남는 것은 `product_submit(2,…)` **장바구니뿐**이다. **「구매하기」로 주문을 시작할 방법이 사라진다.**
⇒ **단순 숨김은 판매 정지다. 절대 그렇게 하면 안 된다.**

### ④ 네이버페이·카카오페이 — **같이 안 사라진다. 확인 완료.**
`.app-pay-wrap` 은 `#fixedActionButton` 의 **형제**다(조상 체인 §5). 인라인을 숨겨도 박스가 남는다.
(계측 환경에선 두 결제 SDK 가 교차출처 차단으로 안 떠서 높이가 0 이지만, **DOM 상 부모가 다르다는 사실**이 근거다.)

### ⑤ 품절·예약주문·정기배송 — 전부 `#fixedActionButton` **안**이다
`.productAction .soldout`(SOLD OUT) · `#actionReserve`(예약주문) · 정기배송 span 모두 이 블록 안에 있고 현재 `display:none` 상태다.
**인라인을 통째로 숨기면 품절 표시와 예약주문 분기도 같이 사라진다.** 우리 하단바에는 `zg-bar__soldout` 대체 슬롯이 있으나 **예약주문·정기배송 대체는 없다.**

## 7. 선택지 — 3안 (전부 `onclick` 보존 · DOM 보존 · `!important` 0)

### A안. 인라인에서 **「장바구니」만** 감춘다 (가장 안전 · 중복 절반 해소)
```css
.zg-detail .infoArea-footer #fixedActionButton .actionCart { display: none; }
```
| | |
|---|---|
| 판매 경로 | **무손상** — 시트의 「구매하기」·`mobileLayerOn` 위임 둘 다 살아 있다 (실측 확인) |
| 말풍선 | **그대로 산다** (구매하기 안이므로). R-4 단독 처리로 끝난다 |
| 품절·예약 | 영향 없음 |
| 대표님 요청 충족도 | **절반.** 「구매하기」는 여전히 두 번 보인다 |
| 위험 | 낮음 |

### B안. 시트가 닫혀 있을 때만 인라인을 감춘다 (요청 100% · 검증 완료)
```css
.zg-detail .mobile-layer:not(.on) .infoArea-footer #fixedActionButton { display: none; }
```
`.on` 은 `mobileLayerOn()` 이 `.jsMobileLayer` 에 붙이는 클래스다(스킨 원문 §6-③).
| | |
|---|---|
| 평상시 | 인라인 「장바구니·구매하기」가 **안 보인다** — 대표님 요청 그대로 |
| 시트 열면 | 인라인이 시트 안에 **다시 나타난다** → **실측: top 774~828, 시트 758~844 안. 구매 경로 정상** |
| 말풍선 | 평상시 안 보이고 **시트 안에서만** 보인다 → R-4 와 맞물린다(아래 ⚠) |
| 품절·예약 | 시트 안에서 정상 표시. 다만 **평상시 품절 표시는 하단바 `zg-bar__soldout` 이 담당**(이미 있음) |
| 위험 | **중간** — `.fixed` 가 아닌 상태에서 바의 구매하기는 `.trigger('click')` 위임 경로를 타는데, 이때 인라인이 `display:none` 이라 **jQuery 는 클릭을 정상 발화**하지만 뒤따르는 `scrollTop: $('.buy-btn-wrap').position().top` 이 0 을 가리켜 **화면이 맨 위로 튈 수 있다.** 구현 판에서 이 경로를 실기 재현해 확인해야 한다 |

### C안. 인라인은 남기고 **높이만 줄여 보조 버튼으로 격하** (중복은 남되 위험 0)
`--zg-bar-h` 54px → 인라인만 40px + 톤 다운. 말풍선·품절·예약·위임 전부 무손상.
대표님 요청(「없애도 될 듯」)과는 거리가 있다.

### ⚠ 말풍선을 어디로 — B안을 고르면 반드시 같이 정해야 한다
말풍선은 **앱이 `df-banner-code="detail-bubble"` 로 그 자리에만 꽂는다.** 우리가 다른 곳으로 옮기려면
DOM 이동(`appendChild`)이 필요한데, **앱이 나중에 다시 그리면 원위치로 돌아간다**(관측 미확인 — 앱 스크립트가 재실행되는 조건을 아직 못 봤다).
| 안 | 내용 | 평가 |
|---|---|---|
| 가 | **시트 안에서만 보이게 둔다**(추가 작업 0) | 가장 안전. 다만 평상시 카카오 혜택 노출이 사라진다 — **매출 영향 판단은 대표님 몫** |
| 나 | 말풍선만 하단 고정바의 「구매하기」 위로 **이동** | 노출 유지. **앱 재렌더 위험**을 먼저 관측해야 한다 |
| 다 | `.app-pay-wrap`(카카오페이 버튼) 위로 이동 | 문맥이 가장 자연스럽다(카카오 혜택 ↔ 카카오페이). 위험은 「나」와 같다 |

## 8. 권고 (판단 요청)

1. **R-4 는 지금 바로 고칠 수 있다** — `line-height:1.2` 1블록, `detail.css` 1파일. **R-3 과 분리해서 먼저 내보내길 권한다.**
2. **R-3 은 A안(장바구니만 숨김)을 권한다.** 위험이 사실상 0 이고 중복의 절반이 사라지며 말풍선·품절·예약·위임 경로를 하나도 건드리지 않는다.
   요청을 100% 맞추려면 **B안 + 말풍선 「가」안**이고, 이 경우 **`.fixed` 아닌 상태의 위임 경로 실기 확인**이 선행 조건이다.
3. **어떤 안이든 「그냥 `#fixedActionButton` 숨기기」는 채택하면 안 된다** — §6-③ 실측대로 구매 경로가 0 개가 된다.
