### F-1 — 상세 지연로딩 차단 (문가온 R-1)
문가온 §1 의 `unlazyDetailImages()` 를 **그대로** 넣었다(IIFE 최상단, 파싱 시점 동기 실행).
`ec-data-src` → `src` 승격 + 속성 제거(로더 대상 제외) + `loading="lazy"`/`decoding="async"` + `h1.prd-name` 에서 읽은 `alt`.
무효 완화책(`scroll`/`resize` 재발사)은 **삭제**했다. `init()` 에서 한 번 더 돌려 **로더가 먼저 돌아 1×1 을 씌운 경우도 회수**한다
(`CAFE24.lazyload()` 는 교차 전까지 `ec-data-src` 를 남기므로 사후 회수가 성립한다).
NNEditor 원본 미변경 — 런타임 속성 승격일 뿐이다.

### F-2 — z-index
`--zg-z-bar: 12 → 10`. 스킨 원값을 그대로 쓴다. 시트 열림 시 버튼 줄을 접는 처리는 유지했다(중복 방지).

### F-3 — 푸터 예약 ⚠ **판정서 근거를 실측으로 정정한 항목**
- 판정서 근거: `css/module/product/detail.css:1` `html .footer{padding-bottom:60px}`.
- **실측 추가 확인:** 같은 파일 **4248행**(`@media (max-width:1023px)` 블록 안, 3606~4330)에
  `.footer { padding-bottom: 100px !important; }` 가 있다. **모바일 예약은 이미 100px** 이다.
- 우리 바 높이는 82px + safe-area(K-12 AC2) → 부족분은 `safe-area − 18px` 뿐이다.
- `padding` 은 important 로 잠겨 있어 이길 수 없고, 이기려 하면 새 important 부채가 생긴다.
  → **잠기지 않은 `margin-bottom` 으로 부족분만** 더한다. 새 important **0개**.
```css
@media (max-width: 1023px) {
  html body .footer { margin-bottom: max(0px, calc(env(safe-area-inset-bottom) - 18px)); }
}
```
- `.zg-detail` 의 `padding-bottom` 은 제거 → 상품문의~푸터 사이 104px 빈 공간 소멸.

### F-4 — 추가상품 은닉
- `.zg-detail.zg-picked-0 #totalProducts{display:none}` **규칙 자체를 삭제**했다(행 은닉 금지).
- 빈 상태 판정을 `pickedRows()`(옵션 행) → **`anyRows()`(`tr.option_product, tr.add_product`)** 로 바꿨다.
- 카드 선택 표시는 여전히 `tr.option_product` 만 본다(기획 §6 진실원장 규칙 유지).
- 재현: 추가상품만 선택 → 안내문 사라지고 행이 보이며 `.delete` 로 지울 수 있다.

### F-5 — 주석 내 변수 치환
`moa/import/product_detail/detail.html` 주석에서 `{$` **전부 제거**(0개). 설명은 변수명 없이 서술로 바꿨다.
파일 전체 `{$` = **1개**(래퍼 안 실제 `{$product_detail}`) — 1차의 2개에서 되돌아왔다.

### F-6 — 리소스 로딩
- 꼬리의 생 `<link>/<script>` **삭제** → `<!--@css(/ds/css/detail.css)-->` / `<!--@js(/ds/js/detail-ui.js)-->` 로 교체, 위치는 **파일 상단**.
- `preconnect` 2줄 + Google Fonts `<link>` 도 상단으로 이동(문가온 P1 A안). 폰트 구성은 그대로(Archivo + IBM Plex Mono 1요청, IBM Plex Sans KR 미로드).
- **`@js(/ds/js/detail-ui.js)` 를 `@js(/moa/js/product/detail.js)` 앞에 두었다.** 같은 JS 번들 안에서 우리 파일이 먼저 실행돼야
  ① `data-delivery`/`.delivery_price_css` 가 지워지기 전에 캡처하고 ② `CAFE24.lazyload()`(jQuery ready) 보다 먼저 이미지를 승격한다.
  판정서가 지적한 대로 1차 주석의 "번들보다 뒤에 파싱" 근거는 틀렸으므로 **주석을 사실로 다시 썼다.**
- `CAPTURED` 는 한 번 읽히면 기억하고, 못 읽으면 매 갱신마다 재시도하며, 끝내 못 읽으면 **숫자를 지어내지 않고** 안내 문구로 대체한다.

### F-7 — 스테퍼 두 구조 대응 (§3 표 참조)
판정서 §0-1 원문대로 `optimizer.php` 의 `bIsMobile = (EC_MOBILE || EC_MOBILE_DEVICE)` 분기를 전제로 구현했다.
**데스크톱 UA 라이브 HTML 을 새로 받아** `CAFE24.MOBILE_DEVICE = true / false` 를 직접 확인했다.

수정 과정에서 추가로 발견해 반영한 것 3가지:
- 스킨 3750행(≤1023px) `#totalProducts table p:not(.product){margin:0 !important}` → 우리 `margin` 선언은 **죽은 코드라 제거**.
- 스킨 1592행 `body:not(#userStyle) #totalProducts .eProductQuantityUpClass{position:absolute}`(ID 2개)가
  `#totalProducts table p:not(.product) a`(ID 1개)를 **이긴다.** → 우리 모바일 스테퍼 규칙 전부에 `body:not(#userStyle)` 접두를 붙여 ID 개수를 맞췄다.
  (이게 없으면 `a` 가 `position:absolute` 로 남아 flex 배치가 깨진다 — 1차 설계의 숨은 결함이었다.)
- 모바일 행은 `padding:16px` + 가격 칸 `position:absolute; bottom/right:16px` 이다. → **행 `padding` 은 `.is-pc` 에서만** 바꾸고,
  `tr.add_product` 구분도 `padding-left` 대신 **좌측 레일(`box-shadow: inset 3px`) + 배경 톤 + 「추가」 칩**으로 바꿨다(K-05 AC6 의도 충족, 절대배치 보호).

## 8. 이번 라운드에서 내가 가장 불안한 것

**F-3 의 `margin-bottom` 방식.** 스킨의 `.footer{padding-bottom:100px !important}` 를 이기지 않고 부족분(`safe-area − 18px`)만
margin 으로 얹었는데, jsdom 은 레이아웃을 계산하지 않으므로 **"푸터 마지막 줄이 실제로 안 가려지는가"는 코드로 증명하지 못했다.**
`max()` + `env()` 조합은 iOS 11.3 이상에서 동작하지만, safe-area 값이 0 인 기기(비노치)에서는 margin 0 이 되어
기존과 완전히 동일해진다는 것까지만 보장된다. **대표님 폰(노치)에서 페이지 최하단 스크롤 시 푸터 마지막 줄 가림 여부**를
신아린 실기 검수의 최우선 항목으로 올려 주시길 요청한다. 가려지면 `18px` 상수를 낮추는 한 줄 조정으로 끝난다.
