# 1. 고친 것 — 지시 항목별 (파일 · 줄 · 증명)

## 1-1. F-1 — 접근자 스텁 3변수 (`index.html` 이미지 목록 `<script>` 안, 53행 부근)

**2차의 무엇이 틀렸나.** `window.runMainBannerSlidePC = {…}` 식 **대입형** 스텁은 로드 시점만 막는다. `main_js.html` 의 리사이즈 분기(오세진 §A-② `@209,720`)가 폭이 768 을 넘으면 `destroy()` 뒤 **변수를 `undefined` 로 되돌려** 가드(`== undefined`)를 다시 열고, 폭이 돌아오면 el 없는 Swiper 를 만들다 `reading 'pause'` 를 던진다. 세 번째 변수 `runSubBannerSlide` 는 스텁조차 없어 `reading 'removeEventListener'` 를 냈다.

**3차.** 대입 대신 **접근자**로 둔다 — getter 는 항상 같은 스텁을 돌려주고, setter 는 비어 있어 `= undefined` 대입이 **무시**된다. `writable:false` 는 쓰지 않았다(그건 strict 모드에서 대입 자체가 던진다).

```js
['runMainBannerSlidePC', 'runMainBannerSlideMobile', 'runSubBannerSlide'].forEach(function (k) {
  var stub = { autoplay: { pause: function () {} }, destroy: function () {} };
  Object.defineProperty(window, k, { get: function () { return stub; }, set: function () {}, configurable: true });
});
```

- 멤버는 여전히 **실제로 불리는 둘**(`autoplay.pause` · `destroy`)뿐. Swiper 흉내 0.
- `main_js.html` 의 `var runMainBannerSlidePC;` 재선언은 기존 전역 접근자를 지우지 않는다(스크립트 최상위 `var` 는 이미 있는 non-configurable/configurable 프로퍼티를 재정의하지 않고 그대로 둔다). H8 의 `stubTypes` 가 전환 뒤에도 `['object','object','object']` 인 것이 그 증거다.
- `configurable: true` — 나중에 누군가 진짜 배너를 되살릴 때 `delete window.runMainBannerSlidePC` 한 줄로 걷어낼 수 있게.

**증명 — 회전 3경로 오류 0 (하네스 H8, §3-3 캡처).**

## 1-2. F-2 — 뒤늦은 승격 임계 `pageYOffset <= 8` (`home-hero.js` `promoteIfNearTop`)

2차 `> innerHeight*0.5` 는 신아린 실측에서 **CLS 0.812**(414, 0.49 지점 승격). 3차는 **스크롤 0(iOS 바운스 여유 8px)** 에서만 3D 로 올리고, 조금이라도 내려갔으면 폴백 100vh 를 유지한다. 실측 CLS 는 0 에서만 0.006, 그 아래는 0.4~0.8 — 주석에 그대로 적었다.

```js
if ((window.pageYOffset || 0) > 8) return;
```

하네스 `H7.promote`/`late`(three.js 3초 지연 후 스크롤 0 → 승격) 는 그대로 PASS.

# 6. 개발이 가장 불안한 것 (3차)

1. **`var` 재선언과 접근자의 관계** — `main_js.html` 최상위 `var runMainBannerSlidePC;` 가 접근자를 데이터 프로퍼티로 되돌리지 않는다는 것은 ECMAScript 규칙(이미 있는 프로퍼티는 재정의하지 않음)이고 H8 `stubTypes` 가 실증했다. 다만 cafe24 가 향후 `main_js.html` 을 `let` 으로 바꾸면 **SyntaxError** 가 난다(전역 렉시컬 vs 전역 객체 프로퍼티 충돌은 없지만 같은 스크립트 내 `var`→`let` 은 그쪽 문제). 확률 낮음.
2. **CLS 임계 8px 가 너무 엄격해 승격 빈도가 낮을 수 있다** — 신아린 실측이 그 아래에선 0.4~0.8 이라 의도한 것이다. 3D 를 못 본 사용자는 폴백(첫 배경 + 그라데이션)을 본다. 승격 비율은 GA4 `hero_mode`(no3d/reduced/3d) 로 며칠 뒤 볼 수 있다.
