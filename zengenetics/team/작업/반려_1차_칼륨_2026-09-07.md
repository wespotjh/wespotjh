## 반드시 고칠 것 (P0 — 전부 수정해야 재검수)

### F-1. 상세 접기가 카페24 지연로딩을 영구 차단한다  ← 문가온 R-1
`ds/css/detail.css:772` `.zg-fold{max-height:1700px;overflow:hidden}` (데스크톱 `:997` 2200px)
카페24 `CAFE24.lazyload` 는 `img[ec-data-src]` 를 1×1 PNG 로 덮고 **IntersectionObserver 교차 시에만** 진짜 src 를 넣는다.
IO 교차사각형은 조상의 클립사각형과 교집합을 취하므로 `overflow:hidden` 으로 잘린 12장은 **영영 로드되지 않는다.**
`detail-ui.js:428-432` 의 `dispatchEvent(new Event('scroll'))` 완화책은 **무효** — IO 는 scroll 을 구독하지 않는다.
칼륨 상세는 텍스트 0자·전부 이미지라 크롤러 입장에서 상품설명 전량이 사라진다. 개편 전엔 되던 것 → 회귀.
**수정**: 문가온 판정서 §1 의 `unlazyDetailImages()` 를 적용 — `ec-data-src`→`src` 승격 + 속성 제거(로더 제외)
+ 네이티브 `loading="lazy"` + `{$name}` 기반 `alt` 자동 채움. 완화책 코드는 삭제한다.

### F-2. 하단바 z-index 역전 — 시트를 덮는다  ← 신아린 R1
`ds/css/detail.css:52,857` `--zg-z-bar:12`.
스킨 실측 `.mobile-layer.fixed` **11** / `.mobile-layer-bg` **11** / `.mobile-fix-footer` **10**.
개발이 52행 주석에 정확한 값을 적어놓고 12를 썼다. 재현: 390×844 → 「구매하기」 → 시트가 올라와도
불투명 흰 띠(≈45px)가 시트·딤 위에 남아 시트 하단 구매 버튼을 덮는다.
**수정**: `--zg-z-bar: 10`.

### F-3. 하단바가 푸터를 가린다  ← 신아린 R2
`ds/css/detail.css:76` 하단 여백을 `.zg-detail`(푸터 미포함 범위)에만 줬다.
스킨의 유일한 예약은 `css/module/product/detail.css:1` `html .footer{padding-bottom:60px}` (54px 바 기준).
바가 ≈96px + safe-area 로 커졌는데 예약은 60px 그대로 → 상품문의~푸터 사이 104px 빈 공간 + 최하단 푸터 가림.
**수정**: 예약값을 실제 바 높이에 맞춘다. `.zg-detail` 이 아니라 **푸터를 포함하는 범위**에 걸어라.

### F-4. 추가상품만 고르면 그 행이 통째로 사라진다  ← 신아린 R3
`detail.css:451` + `detail-ui.js:519` — `zg-picked-0` 판정이 `tr.option_product` 만 세는데
`#totalProducts{display:none}` 을 걸어 `tr.add_product` 까지 은닉된다.
재현(jsdom 확인됨): 추가상품만 선택 → 하단바 `37,900원` 인데 안내문 `"구성을 선택해 주세요."` 동시 표시,
선택 삭제 불가(새로고침만). K-05 AC6 · K-06 AC5 위반.
**수정**: 빈 상태 판정에 `tr.add_product` 를 포함한다. 행 은닉이 아니라 안내문 토글로 바꿔라.

### F-5. 주석 안 `{$product_detail}` 이 서버에서 치환된다  ← 신아린 R4
`moa/import/product_detail/detail.html:9`
카페24는 **HTML 주석 안 변수도 치환한다.** 증거: `detail_tab.html:4` 의 주석 `{$review_count}` 가 라이브에 `413` 으로 박혀 나온다.
상세설명 전체가 주석 안에 한 벌 더 들어가고, NNEditor 에 `-->` 가 들어오면 주석이 조기 종료되어
중복 이미지가 래퍼 밖으로 렌더된다. (현재 11/13/16/63번은 `-->` 0회라 아직 안 터졌을 뿐이다.)
**수정**: 주석에서 `{$` 를 제거한다. 설명이 필요하면 변수명을 쓰지 말고 서술하라.

### F-6. `@css()/@js()` 대신 생 태그 + 절대경로 → 404  ← 신아린 R5
`product/detail.html:645~647`. `/ds/css/detail.css` 404 실측.
개발 주석의 근거("번들보다 뒤에 파싱")도 **사실과 다르다** — `optimizer_user.php` 는 `<head>` 안이다
(119,937 byte, `</head>` 121,031). 게다가 `<body>` 중간 스타일시트라 상세가 무스타일로 한 번 그려진다.
**수정**: `<!--@css(/ds/css/detail.css)-->` / `<!--@js(/ds/js/detail-ui.js)-->` 로 바꾸고 **위치를 파일 상단으로** 올린다.
(문가온 P1 도 같은 지적: preconnect·폰트 link 4줄이 `</body>` 직전이라 이득 소멸 + CLS)
`CAPTURED` 가 jQuery ready 보다 먼저 실행되어야 하는 요구는 그대로 유효하니 그 부분만 확인하라.

### F-7. K-05 스테퍼 CSS 7블록이 보이지 않는 행에만 매칭된다  ← 신아린 R6
`detail.css:488~528`. **네가 "가장 불안하다"고 한 그 지점의 실제 마크업을 신아린이 원문에서 찾아냈다** —
`optimizer.php` 의 `bIsMobile = (EC_MOBILE || EC_MOBILE_DEVICE)` 로 행이 두 종류로 갈린다:
- iPhone UA → `buildMobileSoldInCells` : **`.quantity` 래퍼가 없다.** `<p>` 안에 `input.quantity_opt` + `a.up/.down`
- 데스크톱 UA → `buildPcSoldInCells` : `.quantity` 있다
`#totalProducts` 의 `.quantity` 는 `<tbody class="displaynone">` 정적 행 1개뿐이고 11번은 필수옵션이라 영구 숨김이다.
즉 지금 CSS 7블록은 **모바일에서 아무 데도 안 걸린다.**
같은 원인으로 `tr.add_product{padding-left:12px}`(470행)도 455행(구체도 2,1,3)에 패배한다.
**수정**: 신아린 판정서 §0-1 의 실제 마크업 전문을 근거로 모바일/PC 두 구조를 각각 대응하라.
