## 3. 실렌더 픽스처를 어떻게 만들었나 (검수받아야 할 부분)

카페24에 로그인할 수 없고 새 파일은 아직 배포 전이다. 그래서 **라이브 HTML(= 옛 템플릿이 카페24에서
렌더된 실제 DOM)에 새 템플릿의 델타만 얹는다.** 델타는 git 으로 확인한 것이 전부다:

```
git diff b2912fb^ b2912fb -- cafe24-skin/product/detail.html                 → 11줄
git diff b2912fb^ b2912fb -- cafe24-skin/moa/import/product_detail/detail.html → 22줄
```

DOM 에 영향을 주는 것은 4가지뿐이고, 문자열 수술이 아니라 **DOM API** 로 적용한다:
`.detail-container` → `.zg-detail` 래핑 / `.zg-brand` / `.zg-badges` /
`#prdDetail` 상세설명 div → `.zg-fold`(+`.zg-veil`/`.zg-more`) 래핑 + `.zg-dh`·`.zg-guide`·`.zg-note`.

**④의 마크업 조각은 하드코딩하지 않고 실제 템플릿 파일에서 잘라 온다** — 템플릿이 바뀌면 하네스도 따라 바뀐다.
잘라내기에 실패하면 예외를 던져 C 스위트가 통째로 FAIL 한다.

그리고 렌더 전에 **랜드마크 선검사**(`C0.*`)로 `.zg-detail` 1 · `.zg-fold` 1 · `.zg-chip` 3 ·
`#prdDetail`·바·옵션 select 탐지 > 0 을 확인한다. **하나라도 0이면 그 뷰포트 결과 전체를 신뢰하지 않는다.**

조건은 오세진 3차 §2-3 과 같게 맞췄다 — **교차출처 전면 차단**(= 웹폰트 0벌), 동일출처 자산은 실물 캐시,
우리 CSS/JS 는 **사용자 번들 바로 앞**, `env(safe-area-inset-bottom)` 은 **0px/34px 토큰 치환**.
이미지는 지정 크기 **스텁 PNG** 로 채워 원본 폭 가정을 바꿔 가며 확대 배율을 재현한다.

## 4. 거짓 통과(false pass) 방지

테스트가 조용히 통과하는 것이 최악이라는 지시에 따라 네 겹으로 막았다.

1. **`[탐지]` 검사** — 셀렉터·패턴이 0개 매칭이면 그 자체가 FAIL.
2. **랜드마크 선검사** — §3.
3. **음성 대조군** — `C3N`: 원본 폭 400px 스텁을 넣으면 확대가 **일어나야** 통과.
   신아린 4차 §4 가 손으로 만든 반례(768/1023px 에서 1.60x)를 매 실행 자동 재현한다.
   안 일어나면 확대 측정 자체가 죽은 것이므로 FAIL.
4. **클릭 스텝 검증** — 계측 시나리오의 셀렉터가 하나라도 안 잡히면 FAIL.
   아무것도 안 누른 채 "중복 없음"으로 통과하는 것을 막는다.

## 5. PASS / FAIL / **KNOWN**

`KNOWN` 은 **규칙상 틀렸지만 baseline 에 이미 알려진 결함으로 등재된 것**이다.
종료코드를 막지 않되 요약표에 항상 노출된다. **"괜찮다"가 아니라 "알고 있고 아직 안 고쳤다"는 뜻이다.**
고쳐서 0 이 되면 baseline 에서 빼야 다시 생겼을 때 FAIL 이 된다.

지시에 「기존 7개 파일을 고치지 마라」가 있어, 아래 §6 의 발견들은 **고치지 않고 KNOWN 으로 등재**했다.

### 6-1. 🔴 `detail-ui.js` 의 md5 가 신아린 4차 판정서와 다르다 — **PASS 도장이 이전 판에 찍혀 있다**

신아린 4차는 **5차본**에 도장을 찍었고, 최종본은 6차본이다.
6차 변경은 주석 1줄(+3 B)이라 실질 영향은 없다고 판단되지만,
**"통과 도장이 최종본이 아닌 이전 판에 찍혀 있다"는 바로 그 사고가 이번에도 한 번 더 일어났다.**

### 6-2. 🟡 `product/detail.html` 주석 안에 `{$review_count}` 2건

```
product/detail.html:122  <!-- <div class="info-review-summary__count jsGoReview">리뷰 <span class="jsReviewCount">{$review_count}</span>건</div> -->
product/detail.html:529  <!-- <span module="product_additional" class="review-count jsReviewCount">{$review_count}</span> -->
```

- **우리가 만든 주석이다** (`git blame` → `814f13d4`, 2026-09-06. 알파리뷰로 교체하며 원본을 주석 처리).
- 카페24 템플릿 엔진은 **HTML 주석 안 변수도 치환**한다. 이 사실은
  `moa/import/product_detail/detail.html` 안에 *"주석에 치환변수 표기 금지"* 라고 우리가 직접 적어 뒀다.
  그 규칙이 `product/detail.html` 에는 적용되지 않은 채 남았다.
- **현재 위험은 낮다** — 치환 결과가 숫자라 주석이 깨지지 않는다.
  다만 위젯 미설치·비로그인 등에서 빈 값이나 예상 밖 문자열이 들어오면 주석이 열린 채 남을 수 있다.
- **권고: 주석 자체를 삭제.** 원본은 git 에 있다. 8종 전개 라운드에서 처리.

### 6-3. 🟡 내부 판정 용어 `[검수 근거]` · `검수 항목` 이 공개 소스에 17건 남아 있다

두 판정이 본 것은 인명·호칭·반려 이력·이슈ID 였고, **QA 프로세스 용어 자체는 스캔 목록에 없었다.**
`[K-xx ACn]` 사양 참조는 두 QA 가 **존치**로 결론냈고 나도 그 판단에 동의한다 — 이건 그것과 다른 항목이다.

### 6-4. 🟡 `moa/layout/head.html` 의 `@css` 개수가 판정서와 다르다

오세진 3차 §2-1 은 head.html `@css` **16**, 나의 실측은 **17** 이다(`<!--@css(...)-->` 리터럴 카운트).
증감이 아니라 **세는 방법의 차이**로 보이지만, 두 사람이 같은 파일에서 다른 수를 얻었다는 사실 자체가
"보존 개수"를 사람이 손으로 세는 방식의 한계다. → baseline 에 **측정 코드째로** 고정했다.

### 6-5. 🔴 최종본 7개 파일이 **git 에 커밋되지 않은 상태**다

`git status` → `M cafe24-skin/ds/js/detail-ui.js` (6·7차 변경분 미커밋).
**판정 대상이 워킹트리에만 있다.** 실수로 덮어쓰면 복구 경로가 없다.
오세진 3차 §4-8 「되돌리기」는 *"원문은 저장소 git 에 있습니다"* 를 전제로 하는데 **지금은 사실이 아니다.**
→ 배포 전에 커밋 권고.

### 6-6. 🟢 라이브 상세 이미지 원본 폭 = **639px** (640 아님)

9종 전수 IHDR 실측: 최소 **639** / 최대 **640**.
신아린 4차 §4 가 *"639px 은 640으로 +0.16% 늘지만 육안 식별 불가"* 로 이미 수용한 값이다.
