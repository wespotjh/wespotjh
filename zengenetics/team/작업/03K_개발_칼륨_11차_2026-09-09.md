### 2-1. 왜 안 바뀌는가 — 두 분기의 착지점이 둘 다 합계 위다

```js
  function place() {
    if (ZG_MOVE_TOTALPRODUCTS && mobile && po) {      /* ① .productOption 바로 뒤 */
      po.parentNode.insertBefore(pickedHead, po.nextSibling);
      po.parentNode.insertBefore(tpNode, pickedHead.nextSibling);
    } else if (tpAnchor.parentNode) {                  /* ② 원래 앵커 자리 */
      tpAnchor.parentNode.insertBefore(pickedHead, tpAnchor);
      tpAnchor.parentNode.insertBefore(tpNode, tpAnchor);
    }
  }
```

실측한 부모:

| 분기 | `pickedHead`·`#totalProducts` 의 부모 | 합계 블록(`.zg-sum`) 의 부모 |
|---|---|---|
| ① true | `DIV.fix-pc-r` (= `.productOption` 의 형제) | `DIV.infoArea-footer` |
| ② false | **`DIV.fix-pc-r`** (앵커도 같은 상자 안이다) | `DIV.infoArea-footer` |

`.fix-pc-r` 는 문서 순서상 `.infoArea-footer` **앞**이다. 그래서 ①·② 어느 쪽이든 목록은 합계보다 위에 온다.
**합계 블록은 `buildSum()` 이 `#totalPrice` 바로 뒤에 만든다** — 즉 `.infoArea-footer` 안이고, `place()` 는 그 안으로 갈 길이 없다.

또한 이 결과는 부수적으로 하나를 더 말해 준다 — **「모바일과 데스크톱이 다르다」는 전제도 사실이 아니다.**
1280 과 390 의 순서가 이미 같다.

## 3. 그러면 무엇이 답인가 — **합계 블록 「안」으로 넣어야 한다** (승인 요청)

`pickedHead` + `#totalProducts` 를 **`.zg-sum` 안, 「상품 금액」 행 바로 뒤**로 옮기면 요청 순서가 정확히 나온다.
저장소에는 반영하지 않고 **런타임 시안으로만** 만들어 재보니 이렇게 된다:

| 뷰포트 | 시안 순서 |
|:--:|---|
| 360 · 390 · 414 · 1280 | 구성 카드 → 무료배송바 → 합계 블록 → **상품 금액 → 선택한 구성 안내문 → 선택한 구성 목록 → 배송비 → 총 구매 금액** ✅ |

**요청하신 4단(`상품 금액 → 선택한 구성 → 배송비 → 총 구매 금액`) 그대로다.** 안내문(`pickedHead`)도 목록과 같이 내려간다(요구 5).

### 3-2. 구현 시 손댈 곳 (승인 나면)

`place()` 의 착지점을 **`.zg-sum` 의 첫 행 뒤**로 바꾸고, `buildSum()` 이 합계를 만든 **뒤에** `place()` 가 돌도록 순서를 보장한다(현재도 `init()` 에서 `buildSum()` → `place()` 순서라 그대로 성립).
`ZG_MOVE_TOTALPRODUCTS` 플래그는 **살려 둔다** — 「합계 안으로 넣는다 / 원래 앵커로 되돌린다」의 스위치로 의미를 바꿔 유지한다(설계 규칙: 되돌리기 한 줄).
리사이즈 왕복(요구 2)은 `place()` 가 매번 같은 착지점을 계산하므로 분기 자체가 하나로 줄어 오히려 단순해진다 — 구현 판에서 왕복 실측을 붙이겠다.

## 5. 무엇을 지웠나 (`detail.css` 1블록 · diff 전부)

```diff
-/* [검수 근거] 이전 판의 `tr.add_product{padding-left:12px}`(1,2,3)은
-   455행 `…tr:not(#totalProductsOption)`(2,1,3) 에 져서 무효였다.
-   구체도를 (2,2,3) 으로 올리되 **padding 을 바꾸지 않는다** — 모바일에서 가격 칸이
-   행 padding 기준으로 절대배치되기 때문이다. 대신 좌측 레일 + 배경 톤으로 구분한다. */
-.zg-detail #totalProducts > table tbody tr.add_product:not(#totalProductsOption) {
-  background: var(--zg-bg-2);
-  box-shadow: inset 3px 0 0 0 var(--zg-hair-2);
-}
+/* 추가구성상품 행은 **본품 행과 같은 흰 배경**이다. 구분은 「추가」 칩 하나로만 한다.
+   ⚠ 여기서 `padding` 을 바꾸지 않는다 — 모바일에서 가격 칸이 행 padding 기준으로
+   절대배치되기 때문이다(8차에 실측으로 확인). 배경·테두리 계열만 다룬다.
+   이전 판의 배경 톤(`--zg-bg-2`)과 좌측 레일(`inset 3px`)은 뺐다 — 다른 구성처럼 보였다. */
```

`diff` 출력이 이 8줄→4줄 교체 하나뿐이다. **「추가」 칩 규칙(`tr.add_product td .product::before`)은 한 글자도 안 건드렸다.**
규칙을 지우면 위쪽 `tr:not(#totalProductsOption) { background: var(--zg-bg) }` 가 그대로 적용돼 **본품과 같은 흰 배경**이 된다 — 새 선언을 추가하지 않았다.

| 항목 | 값 | 판정 |
