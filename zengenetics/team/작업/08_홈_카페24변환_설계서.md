## 5-3. 업로드 위치 — 🔴 **v2 에서 뒤집혔다: `/web/upload/` 로 간다**

### v1 원안 (반려됨) — 기록으로 남긴다

> v1 은 스킨 `ds/image/home/{bg,tex,stick,diss}/` 를 제안했다. 근거는 실측이었다:

> GET /ds/css/detail.css          → 404   (미적용 디자인의 파일은 안 나온다)

### 반려 사유 — **새 폴더 5개는 `ga4.js` 사고의 조건 그 자체다**

실측: 저장소·라이브 모두 **`ds/image/` 에 하위 폴더가 0개**다(`ico_price1.png`·`ico_price2.webp` 2개뿐).

> **`ga4.js` 사고는 폴더 1개에서 났다.** 「화면 추가」 대신 「폴더 추가」를 눌러 **지울 수 없는 폴더**가 생겼고,
> 그래서 파일명을 `zg-ga4.js` 로 우회해야 했다. v1 은 그 조작을 **5회**, 그중 4회는 한 단계 더 깊은 곳에서 하라고 했다.

### 왜 상세보다 홈에서 치명적인가

`body{position:fixed}` 가 붙는 순간 문서가 흐름에서 떨어져 **화면이 문서 최상단으로 튀고 모든 `sticky` 가 죽는다.**
상세(짧은 페이지)에서는 눈에 잘 안 띈다. **386vh 히어로에서는 60 % 지점에서 검색창을 탭하면 히어로가 처음으로 되감긴다.**

### 조건 ④ 설계 (개발 책임 — 스킨 코드는 수정 금지)

```
1) 감시   MutationObserver(document.body,  {attributes:true, attributeFilter:['class']})
          MutationObserver(document.documentElement, 동일)
2) 부착 시 (eMobilePopup | scroll-disabled 감지)
     - 현재 window.scrollY 를 zgFrozenY 에 저장
     - rAF 렌더 루프 중단 (frozen=true) — 잘못된 rect 로 진행률을 덮어쓰지 않는다
3) 이탈 시
     - frozen=false, lastP=-1 (전 블록 강제 재계산)
     - window.scrollTo(0, zgFrozenY)  ← body 가 fixed 였다 풀리며 0 으로 튀는 것을 되돌린다
     - 다음 rAF 에서 1회 렌더
4) 안전장치: frozen 상태가 3초를 넘기면 (= 떼는 코드가 없어 영영 안 풀리는 경우)
```

## 7-6. 🆕 `CAFE24.lazyload()` 와 `.zg-home` 의 `overflow` (QA F-6)

시스템 JS 번들에서 원문을 복원했다:

```js
EC$(function () {
  sAttribute = 'ec-data-src';
  if (EC$('img[' + sAttribute + ']').length > 0) { CAFE24.lazyload(); }   // ← 게이트
});
CAFE24.lazyload = function () {
  var oConfig = { rootMargin: '0px 0px 50px 0px', threshold: 0 };          // ← root 미지정 = 뷰포트
  var placeholder = 'data:image/png;base64,iVBORw0…';                      // 1×1 투명
  EC$('img[ec-data-src]').attr('src', placeholder);                        // ← 먼저 전부 투명으로 바꾼다
  var oIntersection = new IntersectionObserver(…, oConfig);
  … MutationObserver 로 뒤에 추가되는 노드도 등록 …
};
```

| 사실 | 함의 |
|---|---|
| 게이트가 **`img[ec-data-src]` 존재 여부**다 | **현재 라이브 홈은 `ec-data-src` 0건 → `CAFE24.lazyload()` 가 아예 호출되지 않는다**(iPhone/Android/데스크톱 3벌 동일 실측) |
| `IntersectionObserver` 에 **`root` 를 안 준다** | root = 뷰포트. **조상의 `overflow:hidden` 이 root 를 바꾸지는 않는다** — 그것만으로 즉시 깨지지는 않는다 |
| **먼저 전부 1×1 투명으로 치환**한다 | 그 뒤 **뷰포트와 한 번도 교차하지 못하면 영원히 투명**이다. 이것이 칼륨 R-1(문가온)의 실제 메커니즘 |
| `MutationObserver` 는 **`lazyload()` 가 한 번 호출된 뒤에만** 걸린다 | 초기 0건이면 나중에 `ec-data-src` 를 넣어도 안 잡힌다 |

### 설계 규칙 3개 (확정)

1. **우리가 넣는 이미지에 `ec-data-src` 를 절대 쓰지 않는다.** 히어로 배경·`diss` 프레임·스틱·썸네일 전부
   평범한 `src` 또는 네이티브 `loading="lazy"` 다. → 홈의 `ec-data-src` 는 **계속 0건**이고 지연로더는 **잠든 채로 남는다.**
2. **상품진열(Q6)을 존치한다면 `.zg-home` 밖에 둔다.** 진열 썸네일은 `ec-data-src` 를 쓸 수 있고,
   그 순간 `lazyload()` 가 깨어난다. **`#hero-stage{overflow:hidden;height:100vh}` 나 `.zg-stage{overflow:hidden}` 안으로
   들어가면 클립되어 뷰포트와 교차하지 못하고 영원히 1×1 투명이 된다.**
3. **`.zg-home` 에 `overflow` 를 걸지 않는다.** §6-4 자기정정(sticky 파괴)과 **완전히 같은 결론**이다.
   두 개의 독립된 이유가 같은 규칙을 가리킨다.

## 개발이 가장 불안한 것 (v3)

**v2 에서 R14(WebP MIME)를 1순위로 꼽았다. 그대로다** — Q7 시험 업로드 1장이 81장의 운명을 정하고,
`nosniff` 때문에 틀리면 **⑤ 저장 후에야 화면으로 드러난다.**

**v3 에서 새로 불안해진 것은 R16 이다.**
`$('body').removeAttr('class')` 가 홈에 **5회** 있다는 것을 v1·v2 는 몰랐다.
프로토타입이 `body.no3d`(CSS 12규칙)·`body.reduced`(5규칙)에 기대고 있으므로 **그대로 이식했으면
히어로 폴백이 조용히 죽는 결함을 심을 뻔했다.** 조용히 죽는 결함은 QA 도 못 잡는다 — 3D 가 뜨는 기기에서는
증상이 아예 안 나오기 때문이다. **M-1(`.zg-home.zg-no3d` 이관)이 이 판의 가장 값나가는 산출물이다.**

**R17(모바일 무한 `setInterval`)은 고칠 수 없다.** 삭제 금지 파일 안에 있고, 지금 라이브 홈에서도 이미 돌고 있다.
회귀는 아니지만 **386vh 히어로는 정적 홈보다 훨씬 민감하다.** 미리보기에서 눈으로 보는 것 외에 방법이 없다.

**§6-2 40px 점프 · §6-5 `eMobilePopup` 은 여전히 실기로만 닫힌다.**
칼륨 때는 상세가 깨져도 판매가 계속됐다. **홈이 깨지면 유입이 즉시 멈춘다.**
그래서 §10-4 의 **중단점 4개**와 **`9_index_원복.txt`** 가 이 라운드의 실질 안전판이다.
