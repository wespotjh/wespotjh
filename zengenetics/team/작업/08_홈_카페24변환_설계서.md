## 2-1. 홈이 이미 오버레이 헤더다 — 히어로에 유리한 사실

스킨 CSS 번들(`optimizer_user.php`, 207,864 B) 1행에서 확인:

```
main#contents{max-width:100%;padding:0;}
#main .header{height:0;}
#main .header__wrap:not(.m-fixed){background:transparent;border-color:transparent;}
#main .header__wrap:not(.m-fixed) .category__link,… {color:#fff;}
```

- 홈은 `<body id="main">` 이다(실측).
- **홈에서만 헤더가 높이 0 · 배경 투명 · 글자 흰색**으로 히어로 위에 떠 있다.
- `main#contents` 는 **max-width 100% · padding 0** → 특이도 (0,1,1) 로 `#contents{max-width:1280px;padding:0 50px}`(0,1,0)를 이긴다.
  **→ 풀블리드 히어로를 위한 `margin-left:calc(50% - 50vw)` 같은 탈출 해킹이 필요 없다.**
- **→ 프로토타입의 `<header class="gnb">` 는 이식하지 않는다.** 스킨 헤더가 그 자리를 이미 채운다.

## 6-2. 조건 ①  `#wrap.m-fixed` 40px 점프를 흡수해야 한다

`moa/js/common.js:74` `scrollHeaderFixed()`:

```js
$(window).on(' scroll', scrollHeaderFixed);     // ← 비패시브
…
if (getScroll > mCutLine) { $('#wrap').addClass('m-fixed'); }
```
스킨 CSS: `#wrap.m-fixed{padding-top:40px;}`

**스크롤 시작 직후(상단띠 높이 통과 시) `#wrap` 에 padding-top 40px 이 붙어 문서 전체가 40px 내려간다.**
히어로 진행률은 `getBoundingClientRect().top / (offsetHeight - vh)` 로 계산하므로 **여기서 진행률이 튄다.**

→ **대응(개발 책임):** 진행률을 rect 기준으로 매 프레임 재계산하고 캐시하지 않는다.
`m-fixed` 토글 시 `lastP=-1` 로 강제 재계산. **`common.js` 는 수정 금지 파일이므로 우리 쪽에서만 흡수한다.**

## 6-3. 조건 ②  스크롤 리스너가 3벌이 된다

| 리스너 | 성격 |
|---|---|
| `moa/js/common.js` `scrollHeaderFixed` | **비패시브 jQuery.** 매 이벤트마다 `position()`·`outerHeight()`·`outerWidth()` → **강제 동기 레이아웃 3회** |
| `moa/css` `.scroll-effect` 리빌 (`transform`+`transition`) | 스킨 자체 |
| **우리 히어로 + 제품블록** | passive + `requestAnimationFrame` 1틱 |

→ 우리 쪽은 이미 최선(passive+rAF)이다. **`common.js` 의 레이아웃 강제 읽기는 우리가 못 고친다.**
→ **대응:** 히어로/블록 렌더 함수 안에서 **레이아웃 읽기를 rect 1회로 제한**하고, 쓰기(스타일 변경)를
그 뒤에 몰아 넣어 read→write 순서를 지킨다. 이미 프로토타입이 그 구조다(`lastP` 문턱 0.0015).

## 6-4. 조건 ③  CSS 전역 오염 69건을 전부 스코프한다

프로토타입 `<style>` 셀렉터 **277개 중 69개가 `#heroSkin`·`.zg*` 밖**이다. 그중 치명적인 것:

```css
:root{ --bg:#FFFFFF; --ink:#15161A; --navy:#1A2B6B; … }   /* 스킨 변수와 충돌 가능 */
*{ box-sizing:border-box }                                 /* 쇼핑몰 전 요소 */
body{ background:var(--bg); font-size:16px; overflow-x:hidden }
a{ color:inherit }                                         /* 헤더·푸터 링크 색 파괴 */
section{ padding-block:72px }                              /* xans-product-listmain 등 */
h2{ font-size:clamp(24px,6.4vw,32px) }
header nav a{ … }                                          /* 스킨 헤더 직격 */
```

→ **전부 `.zg-home` 래퍼 하위로 재작성한다.** `*`·`body`·`a`·`section`·`h2`·`header nav a` 는
`.zg-home *`, `.zg-home`(body 속성은 래퍼로 이관), `.zg-home a` … 로 옮긴다.
`:root` 변수는 **`.zg-home{ --zg-…: }`** 로 접두사까지 붙여 이중 격리한다.
**새 `!important` 0개** (브리프 정정 5).

# 7. CSS / JS 격리 방침

## 7-1. 네임스페이스
- 래퍼 `<div class="zg-home">` 1개로 본문 전체를 감싼다 → 특이도 +1 로 moa CSS 를 이긴다(정정 5 재사용).
- 새 클래스는 전부 **`zg-` 접두사**. 프로토타입의 `.w .hero .cta .track` 등은 **`.zg-w .zg-hero .zg-cta .zg-track`** 로 개명한다.
  (현재 충돌 0건이지만, 카페24 코어 CSS 는 전량 확보되지 않았고 앱이 나중에 붙을 수 있다.)
- `#heroSkin` → `.zg-home .zg-hero-skin` 로 id→class 전환 (id 는 카페24 모듈과 충돌 위험).

## 7-2. 파일 경로
- CSS/JS 는 반드시 **`<!--@css(/ds/css/home.css)-->` / `<!--@js(/ds/js/home-*.js)-->`**.
  **생 `<link>`/`<script src="/ds/…">` 절대경로는 404 난다** (칼륨 라운드 확정 사실).
- **예외**: three.js 는 외부 절대 URL 이므로 생 `<script src="https://cdnjs…">` 가 맞다.
- **HTML 주석 안에 `{$` 를 쓰지 않는다** — 카페24는 주석 안 변수도 치환한다.

## 7-3. 제품 3블록은 정적 마크업으로 전개한다 (JS 생성 금지)

- 이유 ①: 크롤러·JS 실패 시 홈 본문이 통째로 사라진다(§3-3).
- 이유 ②: 장부 F-2 「홈 `<h1>` 0개」와 E-2 「홈 title 키워드 0개」가 열려 있다. 정적 전개가 F-2 를 닫는다.
- 이유 ③: 대표님 확정 문구를 **파일에서 직접 문자열 대조**할 수 있다(검증 5).
- 비용: 마크업 7,734 B → 약 12 KB (+4 KB). **싸다.**
- 제목 위계: `<h1>` 은 `.zg-hero` 「물 없이도, OK」 **1개만**. 제품 블록·스토어는 `<h2>`, 히어로 캡션은 `<p>`/`<h2>`.

## 7-4. JS 는 2개로 나눈다
- `ds/js/home-hero.js` — three.js 히어로 전용. `THREE` 없으면 즉시 폴백 후 return.
- `ds/js/home-blocks.js` — 제품 블록 스크럽 + 프레임 프리로드. **three.js 와 무관하게 단독 동작**해야 한다.
  (프로토타입은 한 파일에 섞여 있지 않지만, 데이터/빌더가 얽혀 있어 분리가 필요하다.)

## 개발이 가장 불안한 것

**§6-2 의 40px 점프와 §5-3 의 "적용 전 검증 불가"가 겹친다.**
히어로가 실제로 매끄러운지는 **적용 후에만** 알 수 있고, 홈은 되돌릴 때 결제 계측까지 같이 꺼진다(R11).
그래서 이 라운드는 **미리보기에서 히어로를 끝까지 스크롤해 보는 단계를 반드시 배포 절차에 넣어야 한다** —
칼륨 때는 상세가 깨져도 판매가 계속됐지만, **홈이 깨지면 유입이 즉시 멈춘다.**
