# 프로토타입 모바일 햄버거 메뉴 적용 — 2026-09-07

담당: 개발 (웹/모바일 개발팀)
지시: 대표님 — "홈화면 왜 네비게이션바가 없어? 모바일은 삼발이(햄버거) 아이콘으로 메뉴가 나와야 하는데
이것 때문에 어색해 보인다." + 추가 지시 "리뷰 빼버리고 그 위치에 웰니스라는 메뉴 만들어서 브랜드 스토리 넣자"

## 1. 문제 원인

| 파일 | 증상 | 원인 |
|---|---|---|
| `site/home.html` | 모바일에서 헤더 가운데가 텅 빔 | `@media (max-width:760px){ #heroSkin .gnb nav{display:none} }` — 메뉴를 숨기기만 하고 대체 진입점 없음 |
| `site/brand-story.html` | 동일 | `@media(max-width:680px){ .top nav{display:none} }` — 동일 |
| 프로토타입 12개 전체 | `hamburger`/`burger`/`drawer`/`menu` 문자열 0회 | 햄버거 자체가 없었음 |

참고: 라이브 카페24 스킨에는 이미 `<div class="header__hamburger display-m jsHamburger">Menu</div>` 가 있다.
프로토타입만 빠져 있어 대표님 눈에 어색하게 보인 것.

### 조사 중 정정한 사항
오케스트레이터 사전조사에서 "`home.html` 에 `.gnb` 헤더가 2개"라고 전달받았으나,
실제로는 **헤더 마크업은 1개(`<header class="gnb">`, 히어로 안)** 이고
두 번째 `.gnb{...}` CSS 블록(두 번째 `<style>` 안)은 **같은 헤더에 겹쳐 적용되는 잔여 스타일**이다
(`.gnb .in` 을 요구하지만 `.in` 자식이 없어 대부분 미적용). 별도 섹션 헤더는 존재하지 않는다.
따라서 햄버거는 home.html 에 1세트만 넣었다.

### 「웰니스」 처리 방식 — 선택과 이유

| 화면 | 방식 |
|---|---|
| 햄버거 패널 (모바일) | **섹션 제목 + 들여쓴 자식** (펼치기 없이 처음부터 노출) |
| 데스크톱 가로 nav | **hover / focus 드롭다운** (`.zgs:hover .zgsm`, `.zgs:focus-within .zgsm`) |

- **드롭다운을 택한 이유**: 「웰니스」 자체를 브랜드 스토리 링크로 만들면 나중에 자식이 늘었을 때
  부모 링크와 자식 목록이 충돌한다(부모를 눌러야 할지 하위를 봐야 할지 모호). CSS 5줄로 끝나는
  드롭다운이라 비용이 거의 없어서 확장 가능한 쪽을 골랐다.
- **패널을 아코디언으로 안 만든 이유**: 자식이 「브랜드 스토리」 1개뿐이라 아코디언이면 탭이 2번 필요하다.
  대신 마크업을 `<li><span class="zgm-g">웰니스</span><ul class="zgm-k">…</ul></li>` 로 짜서
  **나중에 항목이 늘면 `<span>` 을 `<button aria-expanded>` 로 바꾸고 `.zgm-k` 를 토글하기만 하면**
  아코디언으로 전환된다.
- 키보드 접근: 「웰니스」 `<span>` 에 `tabindex="0"` 을 줘서 포커스만으로도 드롭다운이 열린다.

## 4. 구현 요약

| 요구사항 | 구현 |
|---|---|
| ≤760px 전용 노출 | `@media(max-width:760px){.zgb{display:flex}}` / `@media(min-width:761px){.zgm{display:none}}` |
| 데스크톱 가로 nav 유지 | 그대로. 햄버거는 `display:none` 이라 데스크톱 레이아웃 무변화 |
| 아이콘 3줄 막대 24×24 | `.zgb i{width:24px;height:2px}` × 3 |
| 터치 타겟 44px+ | `.zgb, .zgm-x{width:44px;height:44px}` / `.zgm-n a{min-height:44px}` |
| 슬라이드 패널 | 우→좌 (`transform:translateX(100%)` → `none`, `.28s ease`), `width:min(86vw,336px)` |
| 딤 | `.zgm-b{background:rgba(8,14,30,.5)}` 페이드 |
| 닫기 4종 | × 버튼 / `Esc` / 딤 클릭 / 메뉴 링크 클릭 |
| `aria-label` `aria-expanded` `aria-controls` | `aria-label="메뉴 열기"`, `aria-expanded` false↔true 토글, `aria-controls="zgp"` |
| 첫 항목 포커스 | 열릴 때 `panel.querySelector('a[href]').focus()`, 닫힐 때 햄버거로 포커스 복귀 |
| 배경 스크롤 잠금 | `body.zgm-open{overflow:hidden}` 클래스 토글 |
| 히어로=흰색 / 아래=어두운 색 | `.zgb.lt{color:#fff}` (home 히어로) · `.zgb.dk{color:var(--ink)}` (brand-story). 막대는 `currentColor` |
| 자체 완결 단일 HTML | 외부 파일 0개. 기존 `<style>`/`<script>` 안에만 삽입 |
| 기존 스크립트·데이터 URI 불가침 | `window.__STK__` / `__MAP__` / three.js 애니메이션 전부 무수정 |
| `prefers-reduced-motion` | home: 전용 규칙 추가 / brand-story: 기존 전역 `*{transition:none!important}` 이 이미 커버 |

접근성 메모: 포커스 트랩은 요구사항 밖이라 넣지 않았고, 그래서 `aria-modal="true"` 도 **일부러 붙이지 않았다**
(트랩 없이 `aria-modal` 을 선언하면 스크린리더에 거짓 신호가 된다). `<nav aria-label="사이트 메뉴">` 로 처리.

다크모드: 드로어는 `var(--paper)`/`var(--ink)`/`var(--rule)` 토큰 + 폴백을 쓴다.
brand-story.html 은 다크 팔레트가 있어 자동으로 따라가고, home.html 은 폴백(흰 패널)으로 동작한다.

## 6. 경로 확인 필요 (지어내지 않고 `#` 로 둔 항목)

| 메뉴 | 현재 href | 코드 내 표시 |
|---|---|---|
| 멤버십 혜택 | `#` | `<!-- 경로 확인 필요 -->` |
| 고객센터 | `#` | `<!-- 경로 확인 필요 -->` |

대표님이 보내신 화면에는 있으나 `curl` 로 라이브 메뉴 HTML을 확인했을 때 URL이 잡히지 않은 두 건이다.
경로를 받으면 두 파일 각 2곳(드로어 `<li><a href="#">`)만 치환하면 된다.
※ 데스크톱 가로 nav 의 「멤버십 혜택 / 고객센터」는 원래부터 링크 없는 `<span>` 이라 그대로 두었다.

## 7. 남은 제안 (이번 범위 밖)

- 라이브 카페24 스킨(`cafe24-skin/`)에는 햄버거가 이미 있으므로 이번 변경은 **프로토타입 한정**이다.
  프로토타입 메뉴 구성(리뷰 제거 · 웰니스 신설)을 라이브에도 반영할지는 대표님 결정이 필요하다.
- 「웰니스」 하위가 2개 이상이 되면 패널을 아코디언으로 전환할 것 (전환 방법은 3절에 기재).
