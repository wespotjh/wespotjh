## 1. 브리프 §2 매핑표 검증 결과 — 확정 8건, 정정 6건

라이브 `https://zengenetics.co.kr/product/detail.html?product_no=11` (iPhone UA, 2026-09-07 취득)과
`cafe24-skin/` 안의 템플릿·CSS·JS 원문을 대조했다. 브리프 매핑표는 대체로 맞지만 **6곳이 사실과 다르다.**

### 1-1. 정정 ① — K-05 수량: **이 상품에는 독립 수량 입력칸이 아예 렌더되지 않는다**

스킨 `product/detail.html` 에는 수량 마크업이 3군데 있다:
`tr module="product_quantity"`(옵션표 안) · `dl module="product_quantity"`(하단) · 추가상품 안.
**11번 라이브 HTML에는 이 셋 중 어느 것도 없다.** (`ec-base-desc quantity` 0회, `input#quantity` 는 `#totalProducts` 안 숨김행 1개뿐)

이유: 11번은 **필수 옵션 상품**이라 카페24가 수량을 옵션행으로 넘긴다.
실제 수량 UI는 옵션을 고른 뒤 `#totalProducts` 안에 생기는
`tr.option_product` → `input.quantity_opt` + `a.up` / `a.down` 이 유일하다.

→ **K-05 는 "기존 마크업에 CSS만"이 아니라 "선택 후 생성되는 행을 스타일링"이다.** 작업 성격이 바뀐다.

### 1-2. 정정 ② — K-04 옵션: **카페24는 선택 직후 select 를 `*` 로 되돌린다**

`ds/js/ga4.js` 157~183행에 실측 주석이 남아 있다(2026-09-06 배시우/오케스트레이터 검증분).

```
select 상태(선택 전) : value="*"  text="- [필수] 옵션을 선택해 주세요 -"
── 옵션 선택 ──
select 상태(선택 후) : value="*"   ← 카페24가 select 를 미선택으로 되돌린다
선택 결과는 #totalProducts 안의 tr.option_product 로 옮겨진다:
  <tr class="option_product " data-option-index="1" target-key="11">
    <td><p class="product">젠제네틱스 포타슘 칼륨 (20ea)<br>-<span>🔥BEST🔥…2 box…</span></p></td>
    <td><span class="quantity"><input name="quantity_opt[]" class="quantity_opt" value="1" product-no="11">…
```

→ **"카드의 선택 상태 = `select.value`" 라는 브리프의 전제는 성립하지 않는다.**
   카드가 봐야 할 진실원장은 `select` 가 아니라 **`tr.option_product` 행 목록**이다. (결론은 §6)

### 1-3. 정정 ③ — K-07 무료배송 진행바: **신규 JS 아님. 이미 스킨에 있다**

`#freeShipGuide` (`.text1` 부족액 / `.text2` 달성 / `.levelMeter > #levelLineActive` 진행바)가
`product/detail.html` 466~474행에 이미 있고, `moa/js/product/detail.js` 397행의 난독화 블록이
- `#freeShipGuide[data-delivery]` = `{$delivery_price}` = **"3,500원 (50,000원 이상 구매 시 무료)"** 를 파싱해 기준액·배송비를 뽑고
- `#totalPrice .total` 에 **MutationObserver** 를 걸어 총액이 바뀔 때마다 진행바·부족액·달성문구를 갱신한다.

또한 이 상품의 옵션가가 2box=68,000 / 3box=97,000 / 5box=149,000 으로 **전부 5만원을 넘는다.**
1box×1=34,900(유료) / 1box×2=69,800(무료) — **프로토타입의 "2박스 이상 무료" 규칙과 결과가 모든 경우에 동일하다.**

→ **K-07 은 "JS 신규"가 아니라 "CSS만 + 기존 모듈 재사용"이다.** 별도 5만원 계산 JS를 새로 짜지 않는다.

### 1-4. 정정 ④ — K-08 합계 4줄: **"상품 금액 / 할인 금액" 2줄은 만들 수 없다**

카페24가 주는 값은 `#totalPrice .total em`(옵션·추가상품·수량이 반영된 **판매가 합계**) 하나뿐이다.
프로토타입의 `상품 금액`(정가 합)·`할인 금액`은 `소비자가 45,000 × 박스수 × 수량` 을 **우리가 계산**해야 나오는데,
브리프 §3 이 "가격을 JS로 계산해서 표시하지 말 것"으로 명시 금지했다.

→ **K-08 은 4줄 → 3줄로 축소한다.** (상품 금액 / 배송비 / 총 구매 금액 — §5 K-08 참조)
   할인율은 이미 `moa/js/product/detail.js` `calcDiscountPer()` 가 헤드 가격 영역에 `.discount-per` 로 그린다(중복 금지).

### 1-5. 정정 ⑤ — K-03 뱃지: **`detail-spec` 은 뱃지 자리가 아니다**

`detail-spec` 와 `price-spec` 은 **같은 모듈**(`product_detaildesign`)이고, 11번 라이브에서 둘 다
`상품명 / 소비자가 / 판매가 / 배송비 / 상품간략설명 / 추가항목1(오늘출발 사용) / 추가항목2(마감시각 14)` **7행 동일**하게 렌더된다.
`custom_option1·2` 는 오늘출발 기능이, `custom_option3·4` 는 `ds/js/price-config.js` 의 회원가·플친가 카드가 이미 점유했다.

→ 프로토타입의 뱃지 5종(독일 Jungbunzlauer / FDA 기준 함량 / HACCP / Kolmar BNH / 당류가공품)은
   **현재 카페24 데이터로 만들 수 없다.** 스킨에 직접 타이핑하면 나머지 8종 복제 시 전부 틀린 문구가 된다.
→ **뱃지는 개발 범위 밖 → §8 대표님 결정 필요로 올린다.** 스킨은 빈 컨테이너 + CSS만 준비하고, 데이터가 없으면 통째로 숨긴다.

### 1-6. 정정 ⑥ — K-10 아코디언: **배송·교환/반품은 이미 법정 탭에 있다**

`#purchase-info` 탭(관리자 자동생성)에 결제/배송(택배·전국·3,500원·3~7일)/교환·반품(7일, 불가 사유, 반송지 주소)이 전부 들어 있다.
프로토타입 아코디언의 「배송」·「교환·반품」은 이것과 **중복이고, 손으로 옮겨 적으면 두 곳이 어긋날 위험**이 생긴다.
「먹는 방법」·「제품 정보」는 상품별 텍스트라 스킨(한 벌)에 하드코딩하면 8종 복제가 깨진다.

→ **K-10 은 신규 아코디언 4개 → "안내 바로가기 칩 3개"(§5 K-10)로 대체한다.**
   아코디언 본문을 살리려면 관리자 추가항목 신설이 필요 → §8 결정 항목.

## 2. 스크롤 내러티브 — 최종 섹션 순서

### 2-1. 판단

프로토타입 순서와 카페24 DOM 순서를 겹쳐 보면 **거의 그대로 간다.** 어긋나는 곳은 두 군데뿐이다.

| 프로토타입 | 카페24 DOM | 판단 |
|---|---|---|
| 옵션 → **수량** → 추가상품 | 옵션 → 추가상품 → (`fix-pc-r`) 오늘출발 → **선택목록/수량** → 무료배송바 | ⚠ 수량이 추가상품 **뒤로** 밀린다 |
| (없음) | 헤드와 옵션 사이에 `detail-spec` 표·정기배송 | 표는 유지(K-16), 정기배송은 숨김(K-19) → 순서 문제 아님 |

**DOM 순서 자체는 바꾸지 않는다.** 이유:
- `.opt-content__payment > .fix-pc-l / .fix-pc-r` 는 데스크톱에서 좌우 2단이 되는 구조다. 템플릿에서 블록을 옮기면 데스크톱이 깨진다.
- `moa/js/product/detail.js` 가 `.eventArea` `.app-pay-wrap` 을 폭에 따라 `appendTo()` 로 옮기고 있어, 우리가 또 순서를 흔들면 충돌 지점이 늘어난다.
- 브리프 §3: `module` `{$변수}` `onclick` 은 한 글자도 건드리지 않는다.

**예외 1건만 허용한다 — `#totalProducts` 의 모바일 위치 이동(K-05).**
이 상품에서 수량 조절 UI는 `#totalProducts` 안에만 존재하는데(§1-1), 추가상품 뒤에 있으면
"구성을 고르고 → 수량을 정한다"는 승인된 흐름이 끊긴다.
→ **≤767px 에서만** JS `insertAfter('.productOption')`, ≥768px 에서는 원위치(`.fix-pc-r` 안 `#freeShipGuide` 앞)로 되돌린다.
   마크업·id·module·`{$변수}` 는 그대로, **노드를 옮기기만** 한다. (moa 스킨이 이미 쓰는 패턴)
   ↳ QA에서 부작용(무료배송바 갱신 실패·PC 2단 붕괴)이 확인되면 **이동을 철회하고 원위치**한다. 그래도 §9 성공 기준은 유지된다.

### 2-2. 확정 순서 (390×844, 위 → 아래)

### 상태별 필수 규칙

- **A에서 버튼을 `disabled` 로 만들지 않는다.** 카페24가 "옵션을 선택해 주세요" 검증 메시지를 띄우는 경로를 막게 된다.
  대신 금액 슬롯의 안내문으로 알린다.
- **A→B 전환은 우리가 만들지 않는다.** 카드 탭 → `select.value` 세팅 → `change` 디스패치 → **카페24가 행을 추가** → 그 결과를 읽어 화면을 그린다. 순서가 뒤집히면 안 된다.
- **초기 자동 선택 없음.** 프로토타입은 2box 가 초기 선택 상태지만, 카페24에서 그것을 재현하려면 **로드 시점에 장바구니 후보 행을 자동 생성**하게 된다(총액이 0→68,000으로 바뀌고, 사용자가 고르지 않은 구성이 담긴다). 1.9MB 옵션 스크립트가 늦게 바인딩되는 레이스 위험도 있다.
  → **미선택으로 시작하고, 2box 카드에는 뱃지·강조 테두리만 준다.** (자동 선택을 원하시면 §8-4)
- 상태 갱신 트리거는 **`#totalPrice .total` 의 MutationObserver 1개**로 통일한다. 카페24 스킨이 이미 같은 노드를 관찰하므로 타이밍이 어긋나지 않는다.

## 6. 엣지케이스 결론 — 단일 라디오 vs `tr.option_product` 다중 행

### 6-1. 충돌의 실체
- 프로토타입: 라디오 1개만 선택. 다른 카드를 누르면 이전 선택이 **대체**된다.
- 카페24: 옵션을 고를 때마다 `#totalProducts` 에 `tr.option_product` 가 **누적**된다. 각 행은 자기 수량(`quantity_opt`)과 삭제 버튼(`.option_box_del`)을 갖는다.
  `ga4.js` 실측 기록: *"2 box ×3 + 1 box ×1 → 총액 238,900원 / 수량 4"* — **실제로 쓰이는 경로다.**

### 6-2. 검토한 3안

| 안 | 내용 | 판정 |
|---|---|---|
| A | 카드 탭 시 기존 행의 `.option_box_del` 을 프로그램으로 클릭해 지우고 새로 추가 → 진짜 라디오 | ❌ **기각.** 카페24 옵션 스크립트(`optimizer.php`, 1.9MB)의 내부 상태를 우리가 뒤에서 조작하게 된다. 삭제→추가 사이에 총액이 0으로 튀고, 실패하면 사용자가 고르지도 않은 구성이 남는다. 무엇보다 **여러 구성을 한 번에 담는 실제 구매 경로를 막는다.** |
| B | 카드는 장식, 행 목록만 진짜 | △ 안전하지만 프로토타입의 승인된 시각 위계를 잃는다 |
| C | **카드 = "담기" 트리거 + 행 목록 = 진실원장** | ✅ **채택** |

### 6-3. 채택안(C) 규칙

1. **카드의 의미를 라디오에서 "구성 담기"로 재정의한다.** `role="radio"`/`aria-checked` → `role="button"`/`aria-pressed`.
2. 카드 탭 → `select.value` 세팅 + `change` 디스패치. **삭제는 절대 하지 않는다.**
3. 카드의 선택 표시는 `tr.option_product` 목록을 조회해 결정한다. 같은 구성 행이 있으면 `aria-pressed=true` + "선택됨 · N개"(N = 그 행의 `quantity_opt`).
4. **이미 담긴 카드를 다시 탭하면 아무 일도 하지 않고** 토스트로 알린다: `이미 담겨 있어요. 수량은 아래에서 조절하세요.`
5. **다른 카드를 탭하면 행이 추가된다.** 카드 2장이 동시에 선택 상태가 되며, 이는 오류가 아니다. 상단에 안내 1줄이 뜬다: `구성 2개가 담겼어요. 필요 없는 구성은 아래에서 지워 주세요.`
6. 취소·수량 조절은 **오직 K-05 목록에서** 한다(카드에 삭제 버튼을 두지 않는다 — 카드와 행 두 곳에 조작점이 생기면 상태가 어긋난다).
7. 총액·배송비·진행바는 전부 카페24 값 미러. 우리 JS가 산술을 하지 않는다.

### 6-4. 이 결정이 프로토타입에서 벗어나는 지점 (팀장 컨펌 필요)
- 초기 2box 자동 선택 없음 → 뱃지·강조 테두리로 대체 (§4)
- 카드 복수 선택 가능 → 프로토타입은 단일 선택
- 카드에 "한 포당 N원 / 박스당 N원" 단가 문구 없음 → 계산 금지 규칙 때문 (K-04 AC3)

## 8. 대표님 결정 필요 (개발 범위 밖 — 관리자 설정 사항)

### 8-1. 상품 뱃지 · 브랜드 라벨 (K-03 AC10, K-11 AC3)

  브랜드 라벨 `Potassium 525mg Direct` 를 넣을 **데이터 자리가 카페24에 없다.**
  (추가항목1·2 = 오늘출발, 추가항목3·4 = 회원가·플친가가 이미 점유)
- **여쭐 것:** 상품 상세정보에 **추가항목을 2개 더 신설**해 주시겠습니까?

### 8-2. 추가 구성 상품 구성 (K-06 AC6 · 브리프 §1-3)

- 프로토타입에는 있으나, 상품별 텍스트라 스킨(한 벌)에 넣으면 8종 복제가 깨진다.

- 프로토타입은 2box 가 처음부터 선택돼 있다. 카페24에서 그대로 하면 **페이지를 열자마자 2box 가 담긴 상태**가 된다.
- **여쭐 것:** 자동 선택을 켤까요, 미선택으로 둘까요?
- **기획 권고: 미선택.** 사용자가 고르지 않은 구성이 담기고, 총액이 로드 직후 0 → 68,000 으로 튀며, 옵션 스크립트 로딩 레이스 위험이 있다. 대신 2box 에 「가장 많이 담아요」 뱃지를 준다.

## 9. 성공 기준 (대표님 폰에서 무엇이 보이면 통과인가)

1. 옵션을 안 골랐을 때 화면 어디에도 **가짜 금액이 없다.** 하단바에 `구성을 선택해 주세요` 만 보인다.
2. 2box 카드를 한 번 탭하면 **1초 안에** 하단바 금액이 `68,000원`, 무료배송바가 100% 초록, 선택 목록에 행 1개가 생긴다.
3. 수량 `+` 를 누르면 세 곳(선택 목록·합계·하단바)이 **동시에** 같은 숫자로 바뀐다. 한 곳이라도 늦거나 다르면 실패.
4. 상세 이미지가 처음엔 잘려 있고 「상세 정보 모두 보기」를 누르면 14장이 끝까지 나온다.
5. 리뷰 수·평점 자리에 **우리가 쓴 숫자가 하나도 없다**(알파리뷰가 채우기 전에는 `-`).
6. 장바구니에 담고 주문서까지 갔을 때 금액이 상세페이지 총액과 **1원도 다르지 않다.**
7. GA4 에서 `view_item` / `add_to_cart` 가 **정상 발사**되고 `item_variant` 에 옵션명이 들어간다(배시우 검수).
8. `<title>` `canonical` 이 각 1개, 보존 태그 목록(§5 전역 보존)이 전부 살아 있다(문가온 검수).
