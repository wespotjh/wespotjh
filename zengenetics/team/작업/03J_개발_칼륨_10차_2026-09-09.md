## 1. 확인한 원문 — 힌트가 맞다 (그리고 왜 안전한가)

미리보기 `optimizer.php` JS 번들에서 삭제 경로를 그대로 뽑았다.

```js
// 옵션박스 선택상품 삭제  (본품 tr.option_product)
EC$(document).on('click', '#totalProducts a.delete', function () {
    EC$(this).find('.option_box_del').click();

EC$(document).on('click', '.option_box_del', function (event) {
    var oSelf = EC$(this);
    var eSelectedItem = EC$('#' + oSelf.attr('id').replace('_del', '_id'));
    EC$('option[value="' + eSelectedItem.val() + '"]').parent().removeAttr('is_selected');
    …  // 행 제거 + 옵션 데이터 정리 + 총액 재계산까지 카페24가 한다

// 추가구성상품 삭제 — **경로가 다르다**
```

- 우리가 누르는 것은 **행에 이미 그려져 있는, 고객이 직접 누르는 그 버튼**이다.
  1.9MB 옵션 스크립트의 내부 상태를 우리가 고치는 것이 아니다 (기획 1차 경고와 성격이 다르다 — 코디네이터 판단이 맞다).
- 행 제거·`is_selected` 해제·총액 재계산·마일리지까지 **전부 카페24 자기 핸들러가** 한다. 우리는 DOM 을 뜯지 않는다.
- **추가상품은 `.option_add_box_del` 로 경로가 갈린다** → 본품 셀렉터에 걸리지 않는다. 요구 4는 구조적으로 지켜진다.

`'single'` 모드의 `pruneRows()` 가 쓰던 탐색기를 `delControl(row)` 로 뽑아 **한 곳에서** 쓰게 했다(중복 제거).

## 2. 구현 — `detail-ui.js` 4곳

```js
  function delControl(row) {                    /* pruneRows 와 공용 */
    return $('a.delete, .option_box_del, a[class*="delete"], a[class*="Del"]', row);
  }

  function unpick(key) {
    var hits = pickedRows().filter(function (r) { return rowMatches(r.key, key); });
    if (!hits.length) return false;
    var done = 0;
    hits.forEach(function (r) {
      var del = delControl(r.el);
      if (!del) return;
      try { del.click(); done++; } catch (e) {}
    });
    if (!done) return false;                    /* 하나도 못 눌렀으면 호출부가 폴백 */
    schedule();                                 /* 총액·무료배송·하단바·빈 상태를 즉시 재동기 */
    return true;
  }
```

```js
    if (already) {                                /* 이미 담긴 카드를 다시 눌렀다 */
      if (unpick(key)) { toast('구성을 뺐어요.'); return; }
      if (modeEffective === 'multi') toast('이미 담겨 있어요. 빼시려면 아래 목록에서 지워 주세요.');
      return;
    }
```

`pickedRows()` 는 **`tr.option_product` 만** 읽는다 — 추가상품 행은 애초에 후보에 없다.

### 2-1. 요구 3 — 수량 2 이상이면? **전량 삭제**로 정한다

| 안 | 근거 |
|---|---|
| **전량 삭제 (채택)** | ① 카드는 **담기/빼기 스위치**다. 「담기」가 1회 탭으로 구성 하나를 넣었으니 「빼기」도 1회 탭으로 그 구성을 뺀다 — 대칭이다. ② 수량 조절 조작점은 아래 「선택한 구성」의 스테퍼로 이미 정해져 있다(**조작점 이원화 금지** 규칙). 카드가 1개씩 깎으면 같은 일을 두 곳에서 하게 된다. ③ 카페24 삭제 핸들러 자체가 **행 단위**다 — 1개 감소는 스테퍼를 프로그램으로 눌러야 해서, 우리가 안 하기로 한 「내부 상태 조작」에 한 발 더 가까워진다. ④ 코디네이터 의견과 같다. |
| 1개 감소 | 수량 3을 빼려면 3번 탭해야 한다. 카드 시각 상태(`선택됨`)가 언제 꺼지는지 예측이 안 된다. |

### 2-2. 요구 6 — `aria-label` 이 **실제로 일어나는 일**을 말하게 했다

| 카드 상태 | 라벨 접미 |
|---|---|
| 미선택 | `, 장바구니에 담기` |
| 담김 + 해제 가능 | **`, 선택 해제`** |
| 담김 + 삭제 컨트롤 없음(폴백 상품) | **`, 이미 담김`** — 되지 않는 일을 안내하지 않는다 |

`data-zg-on` 은 기존 `refresh()` 경로가 그대로 해제한다. 2장 이상 담겼을 때의 힌트도
**해제가 실제로 가능한 경우에만** `구성 N개가 담겼어요. 카드를 다시 누르면 빠집니다.` 로 바뀐다
(불가능하면 기존 문구 유지).

### 2-3. 요구 7 — 토스트 문구

| 상황 | 문구 |
|---|---|
| 해제 성공 | `구성을 뺐어요.` |
| 삭제 컨트롤 없음(폴백) | `이미 담겨 있어요. 빼시려면 아래 목록에서 지워 주세요.` (기존 `…수량은 아래에서 조절하세요.` 에서 정정 — 재탭의 의도는 빼기이므로) |

둘 다 사실 서술이고 **배송 조건·수치를 말하지 않는다.**

3. 커밋은 지시가 없어 하지 않았다. baseline 갱신 사유는 `B._note_10` · `C._note_rows` 에 남겼다.

## 8. 이번 판에서 내가 틀렸던 것 (자진 기록)

1. **새 주석에 `대표님` 을 넣었다.** 5차에 내가 직접 만든 규칙(공개 소스에 내부 호칭·판정용어 0)을 내가 어겼다. 하네스 B3 가 잡았다 — 하네스를 만들어 둔 값을 이번에 처음 돌려받았다.
2. 재탭 해제를 넣으면서 **`aria-label` 이 「장바구니에 담기」로 남는 것**을 처음 판에 놓칠 뻔했다. 요구 6 이 명시돼 있어 살았다. 버튼의 동작이 바뀌면 **라벨의 동사도 같이 바꾼다** — 다음 판 규칙으로 장부에 넣는다.
