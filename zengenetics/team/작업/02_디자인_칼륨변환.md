**충돌 여부:** 없음에 가깝다. 기존 선언이 `body,code` **구체도 (0,0,1)** 이므로 우리 `.zg-detail`(0,1,0) 한 겹으로 무조건 이긴다. `!important` 불필요.

**대응 (확정안):**

1. **IBM Plex Sans KR 은 로드하지 않는다.**
   - 근거 ①: 한글 가변 웹폰트를 2벌 받으면 모바일 LCP가 무너진다. Pretendard subset 43분할이 이미 깔려 있다.
   - 근거 ②: `design-system.md` — *"전체 **볼드 고딕(프리텐다드 계열)** 단일 체계"* 가 **상세페이지 실물 기준**으로 확정돼 있다. IBM Plex Sans KR 700 확정은 **홈 히어로 자이언트 타이포 한정** 결정이다. 상세에 Pretendard 를 쓰는 것이 오히려 확정사항과 정합한다.
   - 조치: `--f-b: 'Pretendard Variable','IBM Plex Sans KR',-apple-system,BlinkMacSystemFont,'Apple SD Gothic Neo',sans-serif;`
     (IBM Plex Sans KR 을 2순위로 남겨 둔다 — 나중에 대표님이 홈과 완전 통일을 원하시면 `<link>` 한 줄 추가만으로 전환된다.)
   - **웨이트 매핑:** Pretendard 는 가변폰트라 300/400/500/600/700 전부 나온다. 다만 스킨 `body` 가 `font-weight:500` `letter-spacing:-0.4px` 를 걸어 두었으므로 `.zg-detail` 에서 `font-weight:400; letter-spacing:-0.01em` 로 **재설정**해야 프로토타입 톤이 산다.

2. **Archivo + IBM Plex Mono 는 Google Fonts 1 요청으로 로드한다.**
   ```html
   <!-- moa/layout/head.html — @css() 가 아니라 생 <link> (외부 URL 은 @css 로 못 넣는다) -->
   <link rel="preconnect" href="https://fonts.googleapis.com">
   <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
   <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Archivo:wght@500;600;700&family=IBM+Plex+Mono:wght@400;500&display=swap">
   ```
   - 둘 다 **라틴 전용**이라 총 ~40KB. 한글 폰트 대비 무시 가능.
   - `display=swap` 필수 — 숫자가 FOIT 로 사라지면 가격이 안 보인다.
   - **head.html 은 전 페이지 공통이다.** 상세 페이지에만 필요하면 `product/detail.html` 상단에 같은 `<link>` 를 넣어도 동작한다 (cafe24 는 `@css` 가 아닌 생 태그를 그대로 출력한다). **1순위 = product/detail.html 에만**, 다른 8종 상품 이식 완료 후 head.html 로 승격.

3. **폴백 안전장치 (QA 체크 항목):** 회사망·해외망에서 Google Fonts 가 느릴 때를 대비해 숫자 폰트 폴백을 명시한다.
   `--f-d: "Archivo","Pretendard Variable",system-ui,sans-serif;` + 금액 표기에는 항상 `font-variant-numeric: tabular-nums` (프로토타입에 이미 6곳 적용돼 있음 — 유지).

4. **하지 말 것:** 폰트를 `/ds/font/` 에 직접 올려 self-host 하는 안은 **보류.** 카페24 편집기의 파일 업로드 허용 확장자에 `.woff2` 가 포함되는지 미확인이며, 확인 부담 대비 이득(라틴 40KB)이 작다.

### K-02 갤러리 — **CSS만**

**[후크]** `.imgArea` / `.prdImg` / `.jsPrdThumbSlide` / `.thumbnail__list` / `.thumbnail__item` / `.thumb-slide-pager`(=`.jsThumbSlidePager`) / `.thumb-slide__nav` / `.listImg`

**라이브 실측 (product_no=11):**
- 슬라이드 **4장** (대표 1 + 추가 3). 프로토타입은 2컷이었다 → **도트는 4개가 나온다.** 개발은 2개로 강제하지 말 것.
- 추가 이미지 `<li>` 에 cafe24가 **인라인 `style="display:none"`** 을 박는다. 스킨은 `.xans-product-detail .imgArea .prdImg .thumbnail__list > li{display:block!important}` (0,4,1 + `!important`) 로 그걸 이긴다. **이 규칙을 무력화하면 갤러리가 1장만 보인다 — 절대 건드리지 말 것.**
- `moa/js/product/detail.js` `thumbSlide()` 가 `li` 개수 > 1 일 때만 Swiper 를 붙이고 `.thumb-slide-pager` 에 clickable pagination 을 그린다.

| 속성 | 값 |

| 무대 배경 | `var(--bg-2)` `#FBFAF8` |
| 하단 구분선 | `1px solid var(--hair)` |
| 슬라이드 높이 | `min(64vh, 440px)` → 390×844 에서 **440px** (64vh=540 > 440) |

| 도트 활성 | `6×6px` 원 `var(--ink)` · 전환 `background var(--t-mid)` |

**충돌 3건과 처리:**
1. `.thumb-slide-pager{ top:auto!important; bottom:22px!important; left:16px!important; width:calc(100% - 32px)!important; }` — 위치 4속성이 전부 `!important`.

**⚠ 가장 중요한 발견:** product_no=11 은 **`module="product_quantity"` 가 아무것도 렌더하지 않는다.**

→ **K-05 는 정적 마크업이 아니다.** CSS는 동적 삽입되는 행을 겨냥해야 하고, JS는 없는 노드를 잡으려 하면 안 된다.

| 속성 (프로토타입 `.qty` 재현) | 값 |

| 순위 | 셀렉터 | 구체도 | `!important` |

| 1 | `#totalProducts:not(.is-pc) > table > tbody > tr:not(#totalProductsOption) > td > table > tbody > tr:first-child` | **(2,4,7)** | – |

**이기는 법 (`!important` 없이):**
- `.zg-detail` 래퍼가 **모든 셀렉터에 +1 클래스**를 준다 → 위 1번은 `(2,4,7)` → 우리 `.zg-detail #totalProducts:not(.is-pc) > table > tbody > tr:not(#totalProductsOption)…` = **(2,5,7) 승** ✅

### 3-4. 가장 위험한 3개 (`!important` 없이 이길 수 없거나, 이기면 기능이 깨지는 것)

#### 🥇 1위 — `body:not(#userStyle) #totalProducts .quantity { width: 103px !important }`
- 구체도 **(2,2,1)** + `!important`. `css/module/product/detail.css`.
- **왜 위험한가:** K-05 수량 스테퍼의 **폭 자체를 못 바꾼다.** 우리 설계는 134px(44+46+44)인데 103px 로 강제된다. `!important` 로 맞불을 놓으면 이길 수 있으나, 이 셀렉터는 **카페24가 자기 옵션 스크립트와 짝지어 쓰는 것**이라 폭을 바꾸면 `.up`/`.down` 의 `position:absolute; left:0/right:0` 앵커가 어긋난다.
- **처리:** **폭을 건드리지 않는다.** `span.quantity` 에는 `display:inline-flex` + `min-width:134px` 만 주고(둘 다 `!important` 없음 → 승), 내부 `input#quantity` 를 `flex:1`, `a.up/.down` 을 `position:static; flex:0 0 44px` 로 되돌린다. `position` 에도 `!important` 가 없다. ✅

#### 🥈 2위 — `#totalProducts:not(.is-pc) > table > tbody > tr:not(#totalProductsOption) > td > table > tbody > tr:first-child`
- 구체도 **(2,4,7)** — 이 페이지 최고치. 짝 규칙 `#totalProducts.is-pc > …`(2,3,7)에는 `padding-top !important` 까지 붙는다.
- **왜 위험한가:** ① 셀렉터가 7단 자손이라 **DOM 구조를 한 칸이라도 바꾸면 스킨 스타일이 통째로 증발**한다. ② `.is-pc` 는 **뷰포트가 아니라 UA** 로 붙는다(`isMobile()` 정규식) — 데스크톱 크롬을 390px 로 줄여도 `.is-pc` 가 유지돼, 반응형 테스트와 실기기 결과가 갈린다.
- **처리:** ① `#totalProducts` 내부에 **어떤 래퍼도 추가하지 않는다**(감싸는 순간 자손 체인이 끊긴다). ② 우리 규칙은 `.zg-detail` 접두 1겹으로 (2,5,7)/(2,4,7) 을 만들어 이긴다. ③ **`.is-pc` 유무 양쪽 CSS를 다 쓴다.** QA는 반드시 **실기기**로 판정 (SwiftShader·데스크톱 축소는 이 분기를 못 잡는다).

#### 🥉 3위 — `.xans-product-detail .imgArea .prdImg .thumbnail__list > li { display: block !important }`
- 구체도 (0,4,1) + `!important`.
- **왜 위험한가:** 이건 **우리가 이겨서는 안 되는 규칙**이다. cafe24 가 추가이미지 `<li>` 에 **인라인 `style="display:none"`** 을 박아 넣는데, 이 `!important` 만이 그걸 이긴다. 우리가 `.zg-detail` 로 구체도를 올려 `display` 를 건드리면 **갤러리가 4장 → 1장으로 줄어든다.** (product_no=11 실측: 대표 1 + 추가 3)
- **처리:** `.thumbnail__list > li` 의 `display` 를 **절대 선언하지 않는다.** 우리가 손댈 것은 `.thumbnail__item`(li)의 `height/padding/background` 와 `img` 의 `max-height/max-width` 뿐. **QA 회귀 항목으로 "갤러리 슬라이드 4장·도트 4개" 를 못 박는다.**

#### 준위험 (참고)
- `.info-review-summary__star svg{fill:var(--review-star-color)!important}` — 별 색. **이기지 않고 양보**(1-2, K-03 참조).
- `.productDetail img{width:auto!important}` — 상세 이미지 폭. **이길 필요 없음**(K-09).
- `#orderFixArea{display:none!important}` — 되살리지 말 것.
- `.thumb-slide-pager{bottom:22px!important …}` — 도트 위치. **수용**(K-02).

## 5. 모바일 우선 · 반응형

### 5-1. 기준: 390 × 844

- 콘텐츠 폭 `390 - 20×2 = 350px`.
- 갤러리 높이 `min(64vh, 440px)` → `64vh = 540px` 이므로 **440px 확정**.
- 하단바 점유 `92px + safe-area`. 본문 `padding-bottom: calc(92px + env(safe-area-inset-bottom) + 12px)`.
- **최소 탭 타깃 44px** — 옵션 카드 74px / 아코디언 summary 56px / 수량 버튼 44px / 하단 버튼 54px / `.zg-more` 48px. **전부 통과.**
- `word-break: keep-all` 을 한글 문장 전부에 적용 (h1, `.sub`, `.hint`, `.zg-acc__a`, `.zg-note`, 뱃지, 옵션명).
- `-webkit-text-size-adjust:100%` — 스킨 `body` 에 없다. `.zg-detail` 에 추가.
- ⚠ 스킨 head 의 `<meta name="viewport" content="width=device-width, user-scalable=no">` — **확대 금지**가 걸려 있다. 접근성상 아쉽지만 **전 페이지 공통이라 이번 작업 범위 밖.** 대신 본문 최소 폰트를 **11.5px 이상**으로 유지한다(프로토타입 최소값과 동일).

### 5-2. 브레이크포인트 — 스킨이 이미 쓰는 값에 맞춘다

스킨은 **767 / 768 / 769 / 1023 / 1024 / 1025** 를 뒤섞어 쓴다(실측: `max-width:1023px` 3회, `max-width:1024px` 5회, `min-width:769px` 1회, `max-width:767px` 2회…). **새 브레이크포인트를 만들면 1px 틈이 생긴다.**

**우리는 딱 하나만 쓴다: `1023px / 1024px`.**
- `@media (max-width:1023px)` — 모바일·태블릿. `.mobile-fix-footer` 가 보이고 `.mobile-layer` 가 바텀시트가 되는 스킨의 실제 경계와 **정확히 일치**한다.
- `@media (min-width:1024px)` — 데스크톱.
- **390–1023 구간은 단일 레이아웃**(유동 폭). 프로토타입 `.w{max-width:520px}` 를 그대로 써서 큰 폰·태블릿에서도 읽기 폭이 벌어지지 않게 한다.

### 5-3. 데스크톱 (≥1024px) 대응 방침

**원칙: 데스크톱은 새로 디자인하지 않는다. 스킨의 2단 레이아웃을 존중하고, 우리 토큰·타이포·컴포넌트 껍데기만 얹는다.**

## 7. 팀장(나윤설) → 대표님 문의 후보 (개발 범위 밖)

1. **갤러리 컷** — 현재 관리자 추가이미지 3장으로 총 4컷. 프로토타입은 2컷 구성. 어떤 컷을 몇 장 쓸지.
2. **무료배송 규칙** — 프로토타입 "2박스 이상 금액 무관 무료" vs 카페24 위젯의 "금액 기준(5만원)". 관리자 배송조건 설정 사항.
3. **추가상품 구성** — 라이브 3종(붓기부스터 세트/비타민B/마그네슘) vs 프로토타입 4종. 브리프 §1-3 그대로 유지 예정.
4. **평점 별 색상** — 스킨 기본 노랑(`rgb(255,184,0)`) 수용 결정. 오렌지로 바꾸려면 `!important` 부채를 져야 함.
5. **합계 4줄 → 2줄** — 상품금액/할인금액을 표시하려면 카페24 값이 없어 계산이 필요하고, 이는 금지사항. 2줄로 축소함.
