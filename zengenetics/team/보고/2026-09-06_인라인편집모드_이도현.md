## 1. 무엇을 만들었나

페이지 우측 하단의 **연필 버튼**을 누르면 그 페이지가 편집 모드로 바뀐다.
글자를 누르면 하단 시트가 올라오고, 거기서

- **문구** 직접 수정 (여러 줄 입력 시 자동으로 줄바꿈 처리)
- **자간** −0.100em ~ +0.300em
- **크기** ×0.70 ~ ×1.60 (원래 크기 대비 배율)
- **굵기** 300 ~ 800
- **줄간격** 1.00 ~ 2.20

를 조절한다. 모든 값은 **손대는 즉시 화면에 반영**된다.
**저장**을 누르면 그 페이지의 새 버전으로 발행되어, 같은 주소를 여는 모두가 바뀐 화면을 본다.
폰·랩탑 어디서든 동작한다 (390px 하단 시트, 최대 높이 45vh, 세로 스크롤).

**되돌리기** = 선택한 요소만 원래대로. **전체 취소** = 저장 안 한 편집을 전부 버리고 마지막 저장 상태로 복귀.
연필 버튼을 다시 누르면 아웃라인·패널이 전부 사라지고 평소 화면으로 돌아간다.

편집 권한이 없는 일반 열람자에게는 **연필 버튼이 아예 보이지 않는다.**
그래도 저장된 편집 내용은 그대로 보인다 (데이터 → 렌더로 재현되므로).

## 2. 설계 요약

### 2.1 편집 결과는 DOM 이 아니라 "데이터"다

라이브 DOM 을 직렬화해서 발행하지 않는다. 대신 페이지 안에 데이터 블록을 심었다.

```html
<script type="application/json" id="zg-edits">[]</script>
```

편집 결과는 이 배열에만 쌓인다.

```json
[{"s":"e005","t":"젠제네틱스 칼륨 다이렉트","ls":0.16,"fs":1.35,"w":800,"lh":2}]
```

| 키 | 뜻 | 단위 |
|---|---|---|
| `s` | 대상 요소의 `data-zg` 표식 | — |
| `t` | 문구 | 문자열(`\n` = `<br>`) |
| `ls` | 자간 | **em** (해상도 무관) |
| `fs` | 크기 **배율** | 배수 (px 를 박지 않는다) |
| `w` | 굵기 | 300–800 |
| `lh` | 줄간격 | 배수 |

페이지가 로드되면 이 JSON 을 읽어 DOM 에 바른다. 즉 **편집 결과는 언제나 데이터에서 다시 그려진다.**
크기는 px 로 굳히지 않고 `배율 × (그 순간의 CSS 계산 크기)` 로 매번 다시 계산하므로,
**미디어쿼리·반응형이 그대로 살아 있다** (창 크기가 바뀌면 260ms 디바운스로 재계산).

### 2.2 selector 안정성

`nth-child` 같은 깨지기 쉬운 경로를 쓰지 않는다.
주입 스크립트가 **파일에 미리 `data-zg="e001"` 표식을 박아** 두고, 런타임은 `[data-zg="e001"]` 하나만 쓴다.

### 2.3 저장 흐름

```
① 페이지 로드
     └ 우리 스크립트가 DOM 을 건드리기 전, 맨 처음에
       document.documentElement.cloneNode(true) → 문자열 = 원본 스냅샷
         · data-zg-o 없는 <script> 제거      (아티팩트 런타임이 주입한 스크립트 배제)
         · [data-zg-e] 의 innerHTML 비움     (페이지 스크립트가 채운 자리 원상복구)
         · [data-zg-s] 의 src/srcset 제거    (스크립트가 넣은 base64 배제)
② 편집        → EDITS 배열만 갱신 + 화면 즉시 반영
③ [저장] 클릭 → 스냅샷 문자열에서 #zg-edits 블록의 "내용만" 새 JSON 으로 치환
④              artifact.publish(html)
```

②의 세 가지 정리 덕분에 **저장해도 페이지 용량이 늘지 않는다** (아래 4-c 참조).
이 정리가 없을 때는 스크립트가 만든 base64 이미지가 스냅샷에 박혀 **한 번 저장에 +909KB** 가 붙었다.

권한/실패 처리:

| 상황 | 처리 |
|---|---|
| `claude.use('artifact')` 가 `null` | 편집 UI 자체를 만들지 않는다 |
| `conflict` | **재시도하지 않고** "다른 화면에서 먼저 저장되었습니다. 새로고침 후 다시 시도해 주세요" 만 띄운다 |
| `not_granted` / `not_writer` / `not_declared` / `consent_required` / `capability_disabled` / `capability_removed` | 편집 UI 를 즉시 감춘다 |
| `too_large` / `rate_limited` / 기타 | 안내 문구만 표시 |

### 2.4 기존 화면 오염 방지

- 모든 클래스·id 에 `zg-edit-` / `zg-` 접두. CSS 는 스니펫 안에 인라인 (외부 리소스 0, three.js/WebGL 0).
- 편집 UI 는 **런타임에만** 생성 → 스냅샷·발행본에 UI 흔적이 남지 않는다.
- 하단 고정 CTA 바는 클래스명(`.bar`/`#ctabar`)에 의존하지 않고 **런타임에 `position:fixed` + 화면 하단 점유**를 계산해 찾아낸다
  (상품페이지의 `.bar` 는 CTA 바와 배송 진행바 두 종류라 클래스 지정이 위험했다).
  패널이 열릴 때만 아래로 내려가고, 닫으면 즉시 복귀 → **CTA 바의 문구도 편집 대상으로 남는다.**

## 7. ⚠️ 메인 세션이 반드시 확인할 것

1. **발행 시 `artifact` 능력을 선언해야 한다.** 이 능력이 선언되지 않으면
   `claude.use('artifact')` 가 `null` 을 돌려주고 **대표님 화면에도 연필 버튼이 안 나온다.**
   publish 할 때 `capabilities` 에 `artifact` 를 넣어야 하며, 정확한 config 형태는
   `artifact-capabilities` 스킬을 로드해 확인할 것. (아티팩트는 `capabilities` 를 생략하면 기존 선언을 유지하므로,
   **최초 1회 반드시 선언**해야 한다.)
2. **README 규칙대로 같은 아티팩트 URL 로 republish** 한다 (`url` 파라미터 필수). 새 URL 이 생기면 대표님 북마크가 끊긴다.
3. 대표님이 화면에서 저장하시면 **저장소 파일이 아니라 아티팩트만 갱신된다.**
   유실 사고를 막으려면 주기적으로 `action:"read"` 로 라이브 HTML 을 읽어 `site/` 파일에 반영하고 커밋·푸시해야 한다.
   (아티팩트 watch 를 걸어두면 대표님 저장 시 세션이 깨어난다.)

## 8. 한계와 주의사항

1. **스크립트가 만들어내는 텍스트는 편집 대상이 아니다.**
   상품페이지의 **옵션 카드(1/2/3박스 가격)·추가상품 목록·상세 이미지**는 페이지 자체 JS 배열(`OPTS`/`ADDS`)에서 생성되므로
   `data-zg` 표식이 붙지 않는다. 이 문구·가격을 바꾸려면 개발팀이 코드를 고쳐야 한다.
   → **cafe24 이식 후에는 이 값들이 cafe24 상품 변수로 대체되므로 오히려 정상적인 경계다.**
2. **애니메이션이 덮어쓰는 텍스트.** 홈의 카운트업 숫자, 브랜드스토리의 `262.5mg` 등은
   스크롤 시 스크립트가 값을 다시 써 넣으므로, 그 요소의 문구를 편집해도 애니메이션이 다시 덮는다.
3. **표식 id 는 문서 순서다.** `_inject-edit-mode.py` 를 다시 돌릴 때 **마크업 구조가 바뀌면 `eNNN` 번호가 밀려**
   저장돼 있던 편집이 엉뚱한 요소에 붙을 수 있다. 페이지 구조를 고친 뒤에는
   재주입 → 대표님께 "편집분 확인" 요청 순으로 가야 한다. (구조를 안 바꾸는 재주입은 안전 — 검증 8·9번)
4. **스냅샷은 페이지 자체 스크립트가 한 번 돈 뒤의 DOM 이다.** 계산된 합계 금액, 선택된 옵션의 `class="on"` 같은
   런타임 상태가 발행본에 함께 박힌다. 모두 로드 시 다시 계산되는 값이라 화면에는 영향이 없고,
   반복 저장해도 용량이 늘지 않음을 확인했다 (검증 4-c).
5. **동시 편집 불가.** 두 화면에서 동시에 편집하면 나중에 저장하는 쪽이 `conflict` 로 거절된다.
   설계 지시대로 재시도하지 않고 새로고침을 안내한다.
6. **편집 모드 중에는 페이지 클릭이 잠긴다** (링크 이동·장바구니 담기 등). 연필 버튼을 다시 눌러 끄면 정상 동작한다. 의도된 동작이다.
7. **`<br>` 만 품은 요소**는 편집 가능하지만, 그 밖의 하위 태그(`<b>` 강조 등)를 품은 요소 63개는 스타일만 조절된다.
8. **로컬 파일(file://) 에서는 저장 기능이 동작하지 않는다.** `claude.use` 가 없기 때문이며, 이때는 연필 버튼도 뜨지 않는다.
   저장은 아티팩트로 발행된 화면에서만 된다.
