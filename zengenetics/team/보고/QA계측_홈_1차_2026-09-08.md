## 4. ★ `zg_scroll_depth` 분모 계산 (팀장 항목 2)

`ga4.js:759-761`: `h = scrollHeight − innerHeight` · `pct = pageYOffset / h`.
**sticky 는 분모를 줄이지 않는다** — `position:sticky` 는 자식(`.zg-hero-stage` 100vh)을 고정할 뿐, 부모 트랙(`.zg-hero-track` 386vh / `.zg-track` 300vh)은 **정상 흐름의 높이 그대로 `scrollHeight` 에 들어간다.** (`home.css:42,47,207,208` 실사 — `overflow` 없음, 스크롤 컨테이너 아님)

### 4-1. sticky 트랙이 분모에서 차지하는 비중

| 뷰포트 | 히어로(386vh) | 제품 트랙 3개(900vh) | **sticky 합(1,286vh)** | no3d 히어로(100vh) | **3D→no3d 분모 Δ** |
|---|---|---|---|---|---|
| 360×740 | 2,856 | 6,660 | **9,516** | 740 | **−2,116** |
| **390×844** | **3,258** | **7,596** | **10,854** | 844 | **−2,414** |
| 414×896 | 3,459 | 8,064 | 11,523 | 896 | −2,563 |
| 768×1024 | 3,953 | 9,216 | 13,169 | 1,024 | −2,929 |
| 1280×900 | 3,474 | 8,100 | 11,574 | 900 | −2,574 |

`home.css` 고정 px 분(hero2·phead·store·cta-wrap·legalnote·tail-pad 76 등)과 셸(헤더·푸터)을 더한 **모델값 @390×844: 3D ≈ 14,294px / no3d ≈ 11,880px**. sticky 트랙만으로 **약 78 %**.
(px 고정분·푸터는 추정 — 정확값은 L-H1 실기. **vh 항은 정확하다.**)

### 4-2. 그래서 퍼센트가 무엇을 뜻하게 되는가 (@390, 3D)

| 마크 | `pageYOffset` ≈ | 화면 위치 |
|---|---|---|
| 10 % | 1,345 | 히어로 트랙 41 % (아직 첫 화면) |
| 25 % | 3,363 | **히어로 트랙 끝 직후** |
| 50 % | 6,725 | 마그네슘 블록 트랙 중간 |
| 75 % | 10,088 | 비타민B 블록 트랙 중간 |
| 90 % | 12,105 | 스토어 섹션 |
| 100 % | 13,450 | 푸터 |

**no3d 에서는 25 % 가 이미 칼륨 블록 안**(히어로가 844px 로 줄어 히어로는 0→7.6 %). **같은 `percent:25` 가 3D/no3d 에서 다른 장소**를 뜻한다. `zg_ver` 도 `page_kind` 도 이를 못 가른다 → **파라미터 필요(§7 N-H3)**.

### 4-3. 조건 ④ 동결이 분모를 흔드는가 — **흔들지만 오발사는 없다**
`body{position:fixed}` → 문서 높이 붕괴 → 브라우저가 `scrollY` 를 0 으로 클램프(개발 §3-1 실증). `ga4.js:760` `if (h <= 0) return` 또는 `pct = 0/h = 0` → **마크 없음.** 해제 시 `scrollTo(frozenY)` → 이미 찍힌 마크는 `fired[]` 로 차단. 픽스처 실측 **+0 / +0**. ✅

### W-H1 ★ three.js `defer` 가 `zg-ga4.js` 부팅을 붙잡는다 (신규 · REJECT 아님)
- `zg-ga4.js:30-34`: 번들이 `<body>` 끝에서 돌 때 `readyState==='loading'` → **DOMContentLoaded 대기**.
- HTML 규격: **DOMContentLoaded 는 모든 `defer` 스크립트 실행 후** 발화. → **cdnjs 에서 615 KB 가 다 오고 실행될 때까지 홈의 `zg_scroll_depth` 는 시작조차 못 한다.**

- `page_view` 는 head 의 gtag 라 무관. 3D 폴백(`zg-no3d`) 시에도 **차단은 똑같이 걸린다**(cdnjs 응답 실패가 확정될 때까지 기다린다).
- **권고(개발, `ga4.js` 무관):** `defer` → **`async`** 로 바꾸고 `home-hero.js` 가 `THREE` 도착을 `script.onload` 로 받아 3D 를 **뒤늦게 켜도록** 한다(부팅 시점에 없으면 일단 폴백, 도착하면 승격). 또는 `<link rel="preload" as="script">` 로 다운로드를 앞당긴다. 실측은 L-H2.

1. 추적계획 §0: *"개편 단계(2.001 → 2.002 → …)마다 이 값만 올린다."* 홈은 상세와 **별도 개편 단계**다.
2. `page_kind` 는 홈/상세를 가르지만 **홈 개편 전/후는 못 가른다.** 상세(2.002)가 먼저 배포되고 홈이 나중에 붙는 순차 복붙에서 `page_kind:home` 데이터에 **두 홈**이 섞인다.
3. §4 — 홈 분모의 **성격**이 바뀌었다(sticky 1,286vh). 이전 홈의 `zg_scroll_depth` 와 숫자를 나란히 놓으면 안 된다.

**고칠 곳 — `ds/js/zg-ga4.js`**
```js
/* :22 */  var ZG_VER = '2.003';   /* 2.002 = 상세 개편판 / 2.003 = 홈 개편판(히어로·제품 3블록) */
/* :767-770  zg_scroll_depth 페이로드 */
            page_kind: isProduct ? 'product' : 'home',
            item_id: isProduct ? currentPrdNo() : '',
            hero_mode: isHome ? (document.querySelector('.zg-home.zg-no3d') ? 'no3d'
                      : document.querySelector('.zg-home.zg-reduced') ? 'reduced' : '3d') : undefined,   /* N-H3 */
            detail_expanded: isProduct ? (document.querySelector('.zg-fold.zg-open') ? 1 : 0) : undefined   /* N-H6 */
```
(+ N-H1 `select_item` 위임 블록 ~10줄, N-H2 `zg:hero-stage` 수신 블록 ~5줄 — 승인 시 전문을 낸다)
**주문서 2페이지 스니펫:** 4차 안건대로 아직 라이브에 없으므로, 처음 붙일 때 **`?v=2003`** 으로 붙인다(재작업 없음).

**대표님이 읽으실 문장 (2줄):**
> 홈이 새로 바뀌면 GA4 에 "새 홈"이라고 표시를 달아야 옛 홈 숫자와 섞이지 않습니다. 계측 파일의 버전 한 줄을 **2.003** 으로 올리고,
> 새 홈에서 **손님이 제품을 눌렀는지·히어로를 어디까지 봤는지**를 기록하는 두 줄을 같이 넣겠습니다. 이게 없으면 새 홈이 잘 됐는지 GA4 로 판단할 수 없습니다.
