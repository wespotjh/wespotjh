## 1. N1 — `item_variant` 가 실제 흐름에서 항상 비었다

**파일·줄** `ds/js/ga4.js:157-217`(신규 판독부) · `287-290`(수량) · `301-309`(payload) · `336-339`(`zg_option_select`)

### 근거 재확인 — 먼저 반려 상태를 재현했다

배시우가 미러링해 둔 카페24 동일출처 스크립트 8종(`root/mirror/*.js`, `optimizer.php` 1.9MB 포함)을 그대로
구동해 `rt_variant.mjs` 를 돌렸다. **수정 전 코드로 반려 현상이 그대로 재현됐다.**

```
select 상태(선택 전) : {"name":"option1","value":"*","text":"- [필수] 옵션을 선택해 주세요 -"}
zg_option_select      {"item_variant":"BEST 젠제네틱스 붓기파우더 2 box (무료배송)"}   ← 정상
select 상태(선택 후) : {"value":"*"}                                   ← 카페24가 되돌린다
add_to_cart           {"items":[{"item_variant":"", ...}]}              ← 빈 값 (재현 확인)
```

### 선택 결과가 실제로 머무는 자리 — 실측 DOM

```html
<tr class="option_product " data-option-index="1" target-key="11">
  <td><input type="hidden" class="option_box_id" id="option_box1_id" value="P000000L000I" …>
      <p class="product">젠제네틱스 포타슘 칼륨 (20ea)<br> -
         <span>🔥BEST🔥[지금 24%▼] 젠제네틱스 붓기파우더 2 box (무료배송) (+33,100원)</span></p></td>
  <td><span class="quantity">
        <input type="text" id="option_box1_quantity" name="quantity_opt[]"
               class="quantity_opt eProductQuantityClass" value="1" product-no="11">…
</tr>
```
옵션 2종을 고르면 `tr.option_product` 가 2행이 되고, 수량을 3으로 바꾸면 그 행의 `quantity_opt.value` 가 `3` 이 되며
`#totalPrice .total strong` 가 `238,900원`(68,000×3 + 34,900)으로 따라온다 — 직접 눌러 확인했다.

### 수정

```js
function selectedOptionRows() {
  var rows = document.querySelectorAll('tr.option_product');   /* tr.add_product(추가상품)는 제외 */
  …  p.product span → cleanVariant()  ·  input.quantity_opt → 수량
}
function currentVariant() {
  select 가 유효하면 select,  아니면 selectedOptionRows().map(변형).join(' + ')
}
function selectedOptionQty() { 옵션 행의 수량 합계, 행이 없으면 null → currentQty() 폴백 }
function withVariant(obj, variant) { if (variant) obj.item_variant = variant; return obj; }
```
- **팀장 지시대로 빈 값이면 키 자체를 뺀다.** GA4에서 "옵션이 없는 상품"과 "옵션을 못 읽은 상품"이 구분돼야 한다.
  `add_to_cart`·`zg_buy_click`·`zg_option_select`·`purchase.items` 전부 같은 규칙을 쓴다.
- **수량도 실제값으로 바꿨다.** 예전에는 항상 `1` 이었다. `screenTotal()` 이 이미 수량이 반영된 금액이라
  단가 역산(R8)의 분모가 맞아떨어진다.

## 2. N2 — `begin_checkout` 유실

**파일·줄** `ds/js/ga4.js:437-476`

도달과 금액을 분리했다.

```js
var v0 = checkoutTotal();
if (v0) send('begin_checkout', { currency:'KRW', value:v0, checkout_route:'orderform' });
else {
  send('begin_checkout', { checkout_route:'orderform' });        // ① 도달 즉시
  (function tick(){                                              // ② 금액은 따로
    var v = checkoutTotal();
    if (v) { sendAlways('zg_checkout_value', {currency:'KRW', value:v, checkout_route:'orderform'}); return; }
    if (ckTries++ >= 25) { sendAlways('zg_checkout_value_unreadable', {…}); return; }  // ③ 5초
    setTimeout(tick, 200);
  })();
}
```
`send()` 가 이름으로 중복을 막으므로 `begin_checkout` 은 어떤 경로로도 **1건**이다.

## 3. N3 — `purchase` 폴링 여부: 판단 근거

**파일·줄** `ds/js/ga4.js:535-548`(판단 주석) · `565-689`(`readPurchase()` 로 분리) · `691-706`(안전망)

### 판단: **주문완료는 서버 렌더다.** 그래서 판정을 늦추지 않는다.

라이브 원문(`LIVE_order_result.html`, curl 110KB)을 열어 두 페이지를 나란히 비교했다.

| | 주문서 `/order/orderform.html` | 주문완료 `/order/order_result.html` |
|---|---|---|
| 성격 | 카페24 **원터치(스마트) 주문서** — "읽기 전용 파일" 주석 명시 | 일반 스마트디자인 페이지 |
| id | `<button class="btnSubmit" id="">` `<span id=""></span>` — **id 자리를 비워 두고 JS 가 채운다** | 주문번호 자리가 `<span class="txtEm"></span>` — **id·JS 훅이 아예 없다** |
| module 속성 | 남아 있지 않음 | `module=` **0건**, `xans-order-*` 로 **치환됨** → 서버가 렌더했다는 증거 |
| 결론 | JS 렌더 → **폴링 필요** | **서버 렌더** → 즉시 판독이 맞다 |

→ 폴링으로 판정을 늦추면 배시우가 PASS로 확인한 **`zg_purchase_unreadable` +33~38ms 즉시 발사**가 깨진다.
그래서 **즉시 판정은 그대로 두었다.**

### 그 위에 안전망만 얹었다 (매출을 잃지 않기 위해)

"만약 JS 렌더라면 모든 주문이 `zg_purchase_unreadable` 로 빠진다"는 위험은 남는다. 그래서:

- t=0 에 판독 성공 → `purchase` (기존과 동일, 변화 없음)
- t=0 에 실패 → **`zg_purchase_unreadable` 즉시 발사**(기존 동작 유지) + 5초 동안 계속 지켜봄
  - 늦게 채워지면 → `purchase` 정상 발사 + `zg_purchase_late_render {ms}`
  - 끝내 안 채워지면 → **`purchase` 미발사** (틀린 값을 쏘느니 미발사)

**실측** (`t7.mjs`)

| 케이스 | 결과 |
|---|---|
| 정상(서버 렌더) | `purchase` 1건. 안전망 미작동 — **기존과 완전히 동일** |
| 1.2초 뒤 렌더 | `zg_purchase_unreadable` +7ms → **`purchase` +1812ms** + `zg_purchase_late_render {ms:1806}` |
| 끝내 미렌더(6.5초) | `zg_purchase_unreadable` 만. **`purchase` 미발사** ✅ |
| 빈 DOM (하네스 `RESULT_blank_timing`) | `zg_purchase_unreadable` **+38ms** — 지연 없음 ✅ |

> **배시우께**: 이 설계 때문에 "렌더가 살짝 늦은" 경우 `zg_purchase_unreadable` 과 `purchase` 가 **같이** 뜬다.
> 실제로 당신 하네스 `rt_snip2` 두 케이스(값을 ~200ms 뒤에 채우는 구조)에서 그렇게 나왔고,
> **수정 전이었다면 그 두 케이스는 purchase 가 통째로 유실됐다.**
> GA4에서 두 이벤트가 짝지어 뜨면 `zg_purchase_late_render` 가 사유이고, 그때는 즉시 판독 시점을 늦추면 된다.
> 매출을 잃는 쪽보다 진단이 하나 더 뜨는 쪽을 택했다. 다르게 보시면 그 판단에 따르겠다.

L4(실주문 1건 DebugView 확인)는 여전히 필수다 — §5 에 최우선으로 남겼다.

## 4. N4 / N5 / L-신규1

### N4 — 스니펫 `try/catch` (§6 확정본 참조)
결제 페이지 `<head>` 에서 예외가 밖으로 나가지 않도록 인라인 스크립트 전체를 감쌌다.
같은 취지로 **`ga4.js` 의 `boot()` 호출도 `try/catch` 로 감쌌다**(`ga4.js:41-48`) —
이 파일은 결제 페이지에서도 돌기 때문에, 예상 못 한 DOM으로 부팅이 실패해도 페이지에 영향이 없어야 한다.
(기존 "gtag 없으면 조용히 종료" 동작은 그대로다.)

### N5 — 옵션세트 `item_variant` (`ga4.js:623-648`)
```js
if (!variant) {                       /* p.option 이 비었을 때만 */
  var optSet = box.querySelector('[module="Order_optionSet"], ul.xans-order-optionset');
  /* 구성상품 <li> 별로: <strong>(구성상품명)은 item_name 과 겹칠 때만 제거,
     끝의 "(N개)"는 quantity 가 이미 갖고 있으므로 제거 → cleanVariant → ' + ' 로 잇는다 */
}
```
`<strong>` 을 무조건 지우면 세트 주문에서 **무엇을 샀는지가 사라진다**(구성상품명이 거기 있다).
그래서 `item_name` 과 겹칠 때만 지운다.

**실측** (배시우 `rt_purchase.mjs → D_optionset`, `p.option` 을 비우고 ul 에만 값을 남긴 상태)
```
ulText  : "젠제네틱스 마그네슘 1 box (1개)비타민B컴플렉스 1 box (1개)"
수정 전 : item_variant ""
수정 후 : item_variant "젠제네틱스 마그네슘 1 box + 비타민B컴플렉스 1 box"      ✅
```
(`p.option` 이 정상인 일반 주문은 기존 경로 그대로 — 회귀 없음.)

### L-신규1 — 수량이 `strong` 안에 들어오는 경로 (`ga4.js:230-240`)
배시우가 §2 경계값 표에서 "⚠경계 / 실제로는 일어나지 않는다"로 남긴 마지막 줄을 코드로 막았다.
카페24 원본의 모바일 전용몰 경로는
`EC$(getTotalPriceSelector()).html('<strong class="price">'+금액+' '+수량문자열+'</strong>')`
로 수량을 `strong` 안에 넣는다. 이 몰은 반응형 단일 스킨이라 그 경로를 안 타지만,
설정이 바뀌어도 안전하도록 `strong` 텍스트 끝의 `(N개)` 를 떼고 파싱한다.

### 이 코드가 안전한 이유 (전부 실측)

1. **`try{...}catch(e){}` 로 감쌌습니다.** 어떤 이유로든 예외가 나도 결제 화면에 영향이 없습니다.
   (배시우가 `window.gtag` 를 읽기전용으로 만들어 재현한 `TypeError` 도 밖으로 안 나갑니다.)
2. **기존 것을 지우지 않습니다.** `dataLayer` 는 `|| []` 로 이어받고, `gtag` 는 **이미 있으면 덮지 않습니다.**

   실측: 삽입 후 `dataLayer` 에 `["config","G-84HNK1MRBG"]` 와 `["config","G-GZHFY596SS"]` 가 **둘 다** 들어갑니다.
3. **`gtag/js` 로더를 새로 넣지 않았습니다.** 두 페이지에 이미 `gtag/js?id=G-84HNK1MRBG` 로더가
   `<head>` 13,257 / 13,291 바이트 지점(`</head>` 는 51,070 / 50,786)에 있습니다.
   로더를 두 번 넣으면 page_view 가 중복될 수 있어 일부러 뺐습니다.
4. `GTM-5W5PV3CD`, `facebook-domain-verification`, `incentoSEOScriptV1.js` 는 **손대지 않습니다.**
5. 순서가 바뀌어 우리 스니펫이 먼저 실행돼도 안전합니다(양방향 실측 확인).

### 붙여넣은 뒤 확인 2가지

**(1) 소스에 실제로 나오는지** — 저장됐다는 사실만으로는 확인하지 않습니다.
주문 진행 중 `/order/orderform.html` 에서 Ctrl+U → `G-GZHFY596SS` 검색.

**(2) `/ds/js/ga4.js` 가 200 인지** — 이게 유일한 미검증 지점입니다.
지금 라이브는 `moa` 계열 스킨이라 `/ds/js/ga4.js` 는 **404** 입니다(오늘 실측, 규칙 9상 정상).
