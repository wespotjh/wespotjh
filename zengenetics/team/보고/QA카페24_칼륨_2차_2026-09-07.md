## 2-C. R-4 — 메커니즘 해소 ✅ / **전 페이지 비용은 트레이드로 기록한다**

### 메커니즘: 정확히 `<head>` 로 간다
`head.html` 은 스킨에서 `<head>` 를 소유하는 유일한 파일이다. 라이브 실측으로 확정:
head.html:24 의 `preconnect` → 문서 오프셋 **13,610**, head.html:54 의 raw `<script>` → **77,004**,
`</head>` → **121,031**. 새 3줄(27~29행)은 그 사이에 들어간다.
사용자 CSS 번들(**119,880**)보다 **10만 바이트 앞**이므로 preconnect 예열 이득이 실제로 발생한다. ✅

### 전 페이지 영향 — 판정
개발이 든 근거 4가지 중 ①(head 는 이미 배포 경로) ②(preconnect 는 바이트 0) ④(원래 방침)는 타당하다.
**③ "전 페이지 캐시 공유가 오히려 이득" 은 과장이다.**

실측: `fonts.googleapis.com/css2?family=Archivo…&family=IBM+Plex+Mono…` = **HTTP 200 / 8,027 B / 19 `@font-face`**.
그리고 `Archivo`·`IBM Plex Mono`(`--zg-f-d`, `--zg-f-m`)를 참조하는 규칙은 **`.zg-detail` 스코프와
`price.css` 의 `.zg-detail .ds_benefit…` 뿐** — 즉 **상품 상세에서만 쓰인다.**
홈·목록·장바구니·게시판·회원 페이지에는 **렌더블로킹 교차출처 스타일시트 1건(8KB + 1 RTT)이 순수 비용**으로 추가된다.

**그래도 수용한다.** 이유:
1. 되돌리기가 `head.html` 의 `<link>` 3줄 삭제로 끝난다. 다른 어떤 파일도 이 3줄에 의존하지 않는다.
2. 바로 위 두 줄의 `preconnect` 가 DNS+TLS 를 임계경로에서 빼주므로 실비용은 **1 RTT + 8KB** 다.
3. `display=swap` 이라 텍스트가 가려지지 않는다. 한글은 기존 Pretendard 자체 호스팅 그대로 —
   **웹폰트 2벌 로드 금지 원칙(브리프 정정 6)은 유지**된다(IBM Plex Sans KR 미로드 확인).
4. 목표가 9종 상세 전개라 상세 진입 비중이 높다.

**기록할 조건:** 8종 전개 완료 후 **홈 LCP 를 실측해 재검토**한다. 회귀가 보이면
`<link>` 3줄을 `head.html` 에서 빼고 상세 전용 경로로 되돌린다(3줄 삭제).

**차이는 정확히 37줄 / 2,550 B 다.** 개행 방식이나 후행 개행으로는 이런 차이가 나지 않는다.

**원인은 내 1차 검수 중 파일이 편집됐다는 것이다.** 내 세션 로그가 자기모순을 일으킨다:

- 검수 초반 `grep -n` 결과: `1132: .zg-detail .zg-guide{max-width:760px}` / `1133: .zg-note` / `1134: .zg-fold{max-height:2200px}` — **들여쓰기 2칸 = 데스크톱 미디어 블록 안**

같은 파일의 **같은 1133행이 두 번 서로 다른 내용**이었다. 파일이 검수 도중 커진 것 외에는 설명이 없다.
`detail-ui.js` 는 634줄 / 27,912 B 로 개발·나 **바이트까지 일치**했다 — 그 파일은 그 사이 안 건드려졌다는 뜻이다.

## 검수 기준 제안 — **바이트 통일에 동의한다. 다만 그것만으로는 부족하다**

1. **바이트를 1차 기준으로 한다.** 줄 수는 편집기 개행 처리에 따라 갈리므로 보조 지표로만.
2. **제출 시 `md5sum` 을 함께 고정한다.** 이번 사고는 바이트 기준이었어도 똑같이 났다 — 대상이 움직였기 때문이다.
   제출 문서 머리에 5~6개 파일의 md5 표를 넣고, QA 는 **그 해시가 나오는 상태에서만** 판정한다.
   해시가 다르면 검수를 시작하지 않고 반려한다.
3. **검수 착수 후 개발은 대상 파일을 편집하지 않는다.** 고칠 것이 생기면 다음 라운드로 넘긴다.
4. 배포 체크리스트의 붙여넣기 검증도 **줄 수가 아니라 바이트 + 첫 줄/마지막 줄 문자열**로 한다
   (편집기가 붙여넣기 중 잘렸는지 대표님이 눈으로 확인할 수 있는 형태여야 한다).
