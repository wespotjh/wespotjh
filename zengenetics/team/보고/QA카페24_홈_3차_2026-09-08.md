# 1. F-1 — 접근자 스텁 3변수

## 1-1. `runSubBannerSlide` 스텁이 맞는 스텁인가 — **맞다. 「호출을 흉내내지 않고 경로를 끊는 것」이 정답이다**

- 2차에서 난 `reading 'removeEventListener'` 의 실체(라이브 번들 원문 `asset/h007.js` @89,104):
  `destroy: function(){ ee.removeEventListener("resize", this.resize.resizeHandler), ee.removeEventListener("orientationchange", …) }`
  — **Swiper 자신의** `destroy` 안에서 `this.resize` 가 `undefined` 라 터진 것이다(el 없는 Swiper 는 초기화가 끝나지 않는다).
- `main_js.html` 의 `subBannerSlide()` (@212,272): `else if (winWidth >= 768 && runSubBannerSlide != undefined) { runSubBannerSlide.destroy(); runSubBannerSlide = undefined; }`.
- 3차 스텁은 `destroy: function () {}` — **no-op**. 따라서 Swiper 의 destroy 에 **들어가지 않는다.** 스텁이 흉내내야 할 것은 `removeEventListener` 가 아니라 **"destroy 가 아무 일도 안 하고 끝나는 것"** 이다. 이 스텁이 정확하다.
- 이어지는 `runSubBannerSlide = undefined` 대입은 **setter 가 비어 있어 무시** → 가드 `== undefined` 가 다시 열리지 않는다 → `new Swiper('.jsSubBannerSlide')` 재생성 자체가 영구히 차단. 같은 논리가 `runMainBannerSlidePC`(`.autoplay.pause` @204,565) · `runMainBannerSlideMobile`(@209,644 / `= undefined` @209,720) 에도 적용된다.
- 멤버는 실제로 불리는 둘(`autoplay.pause`·`destroy`)뿐 — 픽스처에서 `Object.keys` = `autoplay,destroy` 확인. Swiper 흉내 0, 2차 §A-④(DOM 스텁 시 `on:init` 의 `$('body').removeAttr('class')`)를 피하는 구조도 그대로.
- `configurable: true` 유지 — 배너를 되살릴 때 `delete window.…` 한 줄로 걷어낼 수 있다. (2차 §H-2 전제: 유튜브 iframe 배너가 돌아오면 스텁의 `slideNext`/`autoplay.start` 부재로 던진다 — 그때는 스텁 제거가 먼저. 장부 H-2 유지.)

## 1-2. 회전 3경로 실측 — 3차 **0** vs 2차 대조군 **9**

픽스처: 라이브 홈 캡처의 본문만 3차 `index.html` 로 교체하고 **카페24 시스템·사용자 JS 번들과 `main_js.html` 인라인을 전부 실제 적재**. 폭 전환은 `documentElement.clientWidth` 게터 치환 + `resize`·`orientationchange` 디스패치. 대조군은 **같은 픽스처에서 접근자 블록만 2차의 대입 2줄로 되돌린 것**(그 외 100% 동일).

| 경로 | 3차 (`4cb10827`) | 2차 대조군 (`edbc4f4d`) |
|---|:--:|---|
| 390 → 844 → 390 | **0** | **2** (`removeEventListener` @844, `pause` @390) |
| 768 → 1024 → 768 | **0** | **3** (`removeEventListener` ×2, `pause` @768) |
| 768 → 1024 → 768 → 1000 | **0** | **4** (위 3 + `removeEventListener` @1000) |
| 전환 뒤 스텁 typeof | `object ×3` 전 구간 유지 | `runMainBannerSlideMobile` 이 `undefined` 로 되돌아감(@844·@1024) |

3차 스냅샷에 남은 오류 2건은 **픽스처 산물**이다 — 로그인 필요 페이지가 HTML 로 저장된 보조 스크립트 2개(`asset/h000.js`·`h001.js`)의 `SyntaxError`. 대조군에도 같은 2건이 있고, 변경 전 기준선에도 있었다. 위 표의 숫자는 그 2건을 뺀 값이다.
개발이 보고한 「2차본에 H8 을 돌리면 7 FAIL」은 검사 항목 단위 집계, 내 9는 콘솔 오류 건수 단위 — **둘 다 "2차는 재발, 3차는 0"** 으로 일치한다.

# 2. 실행 순서 · `var` 재선언 · strict

| 항목 | 값 |
|---|---|
| 접근자 정의 (`index.html` 인라인 `<script>`) | 44행 시작 / `forEach` 60행 / `Object.defineProperty` **62행 · byte 5,029** |
| `<!--@import(/moa/js/main_js.html)-->` | **263행 · byte 17,195** → 인라인으로 펼쳐져 그 자리에서 실행 |
| 사용자 JS 번들(`home-blocks.js`·`home-hero.js`) | `</body>` 직전 (2차 §B 오프셋 유지) |

문서 순서 = 실행 순서: **접근자 → main_js → 번들.** 2차 C-3 정정 그대로다.

- **`var` 재선언:** `main_js.html` 최상위 `var runMainBannerSlidePC, runMainBannerSlideMobile, runSubBannerSlide, bestPrdSwiper = undefined;` (@182,257) — 초기화자는 `bestPrdSwiper` 에만 붙고, 스크립트 최상위 `var` 는 **이미 존재하는 전역 프로퍼티를 재정의하지 않는다**(CanDeclareGlobalVar → HasOwnProperty true → 재정의 생략). 픽스처 전 구간 `typeof … === 'object'` 로 실증.
- **strict 모드:** 이번 스텁은 `set: function () {}` 을 **가지고 있다**. 접근자에 setter 가 있으면 strict 모드에서도 대입이 조용히 무시된다(예외 없음). setter 를 생략하거나 `writable:false` 데이터 프로퍼티였다면 strict 스크립트의 `runSubBannerSlide = undefined` 가 **TypeError 를 던졌을 것**이다 — 개발의 선택이 옳다. 참고로 실물 `main_js.html` 블록에는 `'use strict'` 가 없다(확인). 미래에 스킨이 strict 로 바뀌어도 안전하다는 뜻이다.

# 3. `data-zg-three` + `async`

- 3차 픽스처 전 스냅샷에서 `document.querySelector('script[data-zg-three]')` 존재 · `.async === true` · `typeof THREE === 'object'`.
- 카페24가 raw `<script>` 속성을 보존한다는 근거(2차 §C)는 그대로다: 라이브 캡처에 `<script async src="…gtag/js…">` · `<script defer src="/moa/js/lib/sub_category.js">` 가 원문 속성 그대로 있다. optimizer 는 `@js` 로 선언된 파일만 번들하고 **본문에 직접 쓴 `<script>` 태그는 건드리지 않는다** — 홈 3파일은 `@css`/`@js`(번들), three.js 태그는 raw(그대로) 로 갈린다.
- `home-hero.js` `boot()`: 태그를 못 찾으면 `if (!tag) return;` 으로 조용히 폴백 유지 — 속성이 사라져도 오류 0. **(실기 1건)** 편집기 저장 후 속성 잔존은 대표님 저장 뒤 내가 curl 로 확인한다.
- 3차 변경 2건 중 `promoteIfNearTop` 임계 `innerHeight*0.5` → `pageYOffset <= 8` 은 플랫폼 영향 없음(폴백 유지 쪽으로 더 보수적). `home.css` `.zg-no3d .zg-bg0{display:block}` 은 preload 한 첫 배경을 폴백에서도 쓰는 것 — `url()` 은 여전히 `index.html` 인라인 `<style>` 한 곳뿐이라 **CSS 파일에 이미지 경로 0** 원칙 유지.
