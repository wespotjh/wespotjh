## 0. 검수 방법 (개발 자기보고를 믿지 않고 재현한 것)

Playwright 는 이 사이트에서 차단된다. 대신 아래로 **실기에 준하는 재현**을 했다.

1. `curl` 로 라이브 11번 HTML 취득 (iPhone UA / 데스크톱 UA **양쪽**).
2. 라이브 HTML 에 이번 템플릿 변경(zg-detail 래퍼 · `#prdDetail` 재구성 · 슬롯 2개)을 그대로 적용해
   **변경 후 DOM 을 합성**했다.
3. `jsdom` 30.0.1 에서 `ds/js/detail-ui.js` 를 **실제로 실행**하고, 카페24 옵션 스크립트가 만드는
   행 마크업을 **`optimizer.php`(1.9MB) 원문에서 추출한 템플릿 그대로** 주입해
   상태 A/B/C/D/E/F 와 리사이즈 왕복을 돌렸다.
4. `ds/css/detail.css` 의 셀렉터 **168개 전수**를 그 DOM 에 대조해 0매칭을 색출했다.

### 0-1. 개발이 "가장 불안하다"고 지목한 부분 — 원문을 찾아냈다

카페24는 `#totalProducts` 행을 **UA 로 갈라 두 가지 마크업으로** 만든다.
`optimizer.php` 의 `CAFE24.SHOP_FRONT_NEW_OPTION_BOX` 파이프라인:

```
optionBoxState.bIsMobile = (EC_MOBILE === true || EC_MOBILE_DEVICE === true);
sTableRow = bIsMobile ? rowBuilders.mobile(state) : rowBuilders.pc(state);
```

라이브 실측:

| 접속 | `CAFE24.MOBILE_DEVICE` | 행 빌더 | 수량 UI |
|---|---|---|---|
| iPhone UA | **true** | `buildMobileSoldInCells` | `<p>` 안에 `input.quantity_opt` + `a.up` / `a.down` — **`.quantity` 래퍼 없음** |
| 데스크톱 UA | false | `buildPcSoldInCells` | `<td><span class="quantity" style="width:65px">…` — **`.quantity` 있음** |

**실제 모바일 행(재현본, 이것이 정답이다):**

```html
<tr class="option_product " data-option-index="1" target-key="11">
  <td>
    <input type="hidden" class="option_box_id" name="item_code[]">
    <p class="product"><strong>젠제네틱스 포타슘 칼륨 (20ea)</strong><br /> - <span>수량선택🔥BEST🔥[지금 24%▼] … 2 box (무료배송) (+33,100원)</span>  </p>
    <p><input type="number" name="quantity_opt[]" class="quantity_opt eProductQuantityClass" value="1" product-no="11">
       <a href="#none" class="up eProductQuantityUpClass"><img … class="option_box_up"></a>&nbsp;
       <a href="#none" class="down eProductQuantityDownClass"><img … class="option_box_down"></a></p>
  </td>
  <td class="right"><strong class="price">…<span class="ec-front-product-item-price">68,000원</span></strong></td>
  <td class="center"><a href="#none" class="delete"><img class="option_box_del"></a></td>
</tr>
```

추가로 확정한 카페24 실동작 3건:
- `setTotalPrice()` 는 모바일에서 `EC$('#totalPrice .total').html('<strong>68,000원</strong> (1개)')` —
  **`<em>` 이 사라진다.** 개발의 `#totalPrice .total strong, … em` 폴백은 **옳다.**
- 총액 문자열에는 **통화("원")가 포함**된다. 미러 표기가 "68,000" 이 아니라 "68,000원" 으로 나온다 — 정상.
- `#levelLineActive` 의 `full` 클래스는 스킨 `moa/js/product/detail.js` 가 실제로 붙인다.
  개발의 `isFreeShip()` 판정 근거는 **옳다.**

## 2. REJECT 사유

### R1. 하단 고정바가 **바텀시트 위로** 올라온다 — K-12 AC8 정반대
- `ds/css/detail.css:52,857` — `--zg-z-bar: 12` → `.zg-detail .mobile-fix-footer { z-index: 12 }`
- 스킨 실측(`css/module/product/detail.css`): `.mobile-layer.fixed` **11**(4053행) ·
  `.mobile-layer-bg` **11**(4025행) · `.mobile-fix-footer` **10**(3919행)
- 기획 K-12 AC8: *"바텀시트가 열리면 **시트가 바를 덮는다**(z-index 11 > 10)"*
- 개발은 자기 파일 52행 주석에 **정확한 스킨 값(11/11/10)을 적어 놓고도** 12를 썼다.
- 결과: 시트가 열려도 바가 시트와 딤(dim) 위에 그대로 떠 있다.
  `zg-sheet-open` 이 버튼 줄만 `height:0` 로 접지만, 바 컨테이너는
  `padding 6/4 + 18px 금액줄 + 10px + safe-area ≈ 45px` 의 **불투명 흰 띠**로 남아
  시트 하단(`{$action_basket}` / `{$action_buy}` 영역)을 덮는다.
- **재현**: 390×844 → `.infoArea` 아래까지 스크롤 → 「구매하기」 탭 → 시트 상승.
- **수정**: `--zg-z-bar: 10` (스킨 원값 유지). 시트 열림 시 바를 접는 처리는 그대로 두어도 무방.

### R2. 하단 고정바가 **푸터를 가린다** — K-12 AC3 미충족
- 스킨의 유일한 하단 예약은 `css/module/product/detail.css:1` — `html .footer { padding-bottom: 60px }`
  (54px 바 기준).
- 개발은 `ds/css/detail.css:76` 에서 **`.zg-detail` 에만** `padding-bottom: calc(92px + safe-area + 12px)` 를 줬다.
- `.zg-detail` 은 `product/detail.html:29~615` 로 **푸터를 포함하지 않는다**(푸터는 `layout/` 소관).
- 결과 2가지가 동시에 발생한다:
  1. 상품문의 탭과 푸터 사이에 **104px 빈 공간**이 생긴다(엉뚱한 위치의 여백).
  2. 페이지 최하단에서 바(≈96px+safe-area)가 60px 예약을 넘겨 **푸터 마지막 줄을 덮는다.**
- **재현**: 390×844 → 페이지 최하단까지 스크롤 → 푸터 하단이 바에 가림.
- **수정**: `.zg-detail` 의 padding-bottom 을 제거하고
  `html .footer { padding-bottom: calc(96px + env(safe-area-inset-bottom)) }` 상당으로 **푸터 예약을 키운다.**
  (스킨 기존 규칙과 같은 구체도로 `.zg-detail` 없이 선언해야 하므로, 파일 상단에 별도 섹션으로 둔다)

### R3. **추가상품만 고르면 그 행이 화면에서 사라진다** — K-05 AC6 / K-06 AC5 위반
- `ds/css/detail.css:451` — `.zg-detail.zg-picked-0 #totalProducts { display: none; }`
- `zg-picked-0` 판정은 `detail-ui.js:519` — `pickedRows()` = **`tr.option_product` 만** 센다.
  추가상품 행은 `tr.add_product` 이라 카운트되지 않는다.
- **재현(jsdom 실행 결과)**: 본품 옵션 미선택 상태에서 추가상품 select 만 고르면
  ```
  root class = zg-detail zg-picked-0     ← #totalProducts display:none
  bar        = "37,900원"
  sums       = ["37,900원", "3,500원 (…)", "37,900원"]
  안내문     = "구성을 선택해 주세요."   ← 금액과 정면 모순
  tr.add_product = 1  /  tr.option_product = 0
  ```
- 고객은 **자기가 담은 추가상품을 볼 수도, 지울 수도 없다.** 삭제하려면 새로고침뿐이다.
  하단바에는 금액이 찍혀 있어 "왜 37,900원이지?"가 된다.
- **수정**: `pickedRows()`(또는 `zg-picked-0` 판정)에 `tr.add_product` 를 포함하거나,
  `#totalProducts` 를 숨기지 말고 **행이 0개일 때만** 빈 안내를 겹쳐 놓는다.

### R4. HTML 주석 안의 `{$product_detail}` 이 **서버에서 치환된다**
- `moa/import/product_detail/detail.html:9`
  ```html
  <!-- K-09 접기 래퍼 · {$product_detail} 만 감싼다. #related 는 래퍼 밖에 남긴다 -->
  ```
- 카페24 템플릿 엔진은 **HTML 주석 안의 `{$변수}`도 치환한다.** 라이브 증거:
  `moa/import/product/detail_tab.html:4` 의 주석 `{$review_count|numberformat}` 이
  라이브 HTML 에 `<!-- … <span class="jsReviewCount">413</span> … -->` 로 **숫자가 박혀** 나온다.
- `{$product_detail}` 은 상세설명 전체(11번 기준 `<img>` 14장 ≈ 2.1KB)로 팽창한다. 즉시 화면이 깨지진 않지만:
  1. 페이지에 **상세설명 마크업이 두 벌** 실린다.
  2. NNEditor 상세설명에 `-->` 나 `<!--` 가 한 번이라도 들어가는 순간 **주석이 조기 종료되어
     중복 이미지가 접기 래퍼 밖에서 그대로 렌더된다.** 9종 복제 대상이고 관리자가 언제든 편집하는 영역이다.
  - 현재 상태 실측: 11 / 13 / 16 / 63번 상세설명에 `-->` `<!--` **0회** — 지금은 터지지 않는다.
- **수정**: 주석에서 `{$` 를 제거한다(예: `product_detail 변수만 감싼다`). 1글자 수정이며 위험도 0.

### R5. 신규 CSS/JS 를 `@css()/@js()` 가 아니라 **생 태그 + 절대경로**로 로드한다
- `product/detail.html:645~647`
  ```html
  <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Archivo…">
  <link rel="stylesheet" href="/ds/css/detail.css?v=1">
  <script src="/ds/js/detail-ui.js?v=1"></script>
  ```
- 문제 3가지:
  1. **경로 해석**: `/ds/...` 는 **현재 적용된 스킨**의 파일로 해석된다.
     실측 — `/ds/css/price.css` 200, `/ds/js/detail.js` 200(라이브 스킨), `/ds/css/detail.css` **404**, `/ds/js/detail-ui.js` **404**.
     작업본(skin_no=16)에만 올리면 미리보기에서 404 가 날 수 있다. `@css()/@js()` 는 스킨 스코프로 해석되므로 이 위험이 없다.
  2. **캐스케이드 근거가 틀렸다**: 개발 주석은 *"두 optimizer 번들보다 문서상 뒤에 파싱되어 캐스케이드 최후미를 확보"* 라 썼는데,
     실측상 `optimizer_user.php` 는 **`<head>` 안**(라이브 HTML 119,937 byte, `</head>` 는 121,031)이다.
     `@css(/ds/css/detail.css)` 를 `product/detail.html` 끝에 두면 번들 **맨 뒤**에 붙어 동일한 목적을 달성한다.
  3. **렌더 블로킹**: 스타일시트가 `<body>` 중간에 있어 상세 영역이 **무스타일로 한 번 그려졌다가 재배치**된다(FOUC/CLS).
- 부수: 개발 주석의 *"detail-ui.js 가 스킨 JS 번들보다 먼저 실행된다"* 도 사실이 아니다.
  다만 `CAPTURED` 는 **jQuery ready 보다 먼저** 실행되므로 `data-delivery` 확보는 결과적으로 성립한다
  (시뮬 결과 배송비 줄에 `"3,500원 (50,000원 이상 구매 시 무료)"` 정상 표시). **근거만 틀렸고 동작은 맞다.**

### R6. K-05 수량 스테퍼 CSS 7블록이 **보이지 않는 행에만** 걸린다 (사실상 죽은 코드)
- `ds/css/detail.css:488,499,517,525,526,527,528` 은 전부 `#totalProducts .quantity` 하위다.
- 라이브 실측: `#totalProducts` 안의 `.quantity` 는 **`<tbody class="displaynone">` 의 정적 행 1개뿐**이다
  (`<span class="quantity"><input id="quantity" name="quantity_name" value="0">…`).
  11번은 필수옵션 상품이라 이 tbody 는 영구히 `displaynone` 이다.
- 모바일에서 실제로 보이는 스테퍼는 `p:not(.product) > input.quantity_opt + a.up/a.down` 이며,
  개발이 여기에 준 것은 `font/color/border-color` **2줄뿐**이다.
- 다행히 **스킨이 이미** `#totalProducts table p:not(.product)` 에서
  `img{opacity:.00001}` + `a:before`(−) + `.up:after`(+) 로 글리프 대체를 하고 있어 **깨지지는 않는다.**
  그러나 디자인이 정한 값(높이 42px, 탭 타깃 `--zg-tap:44px`, min-width 134px, 알약 테두리)은
  **한 줄도 적용되지 않는다.** 실제 스테퍼는 스킨 기본값 **103px × 30px**, 탭 타깃 30px(44px 미달)이다.
- 같은 원인으로 `tr.add_product { padding-left:12px }`(470행)도 무효다.
  같은 파일 455행 `…tr:not(#totalProductsOption){padding:14px 0}` 이 구체도 (2,1,3) 로
  (1,2,3) 인 add_product 규칙을 **이긴다.** → 추가상품 행 들여쓰기 = 미적용.
- **수정**: 스테퍼 규칙 7블록을 `#totalProducts table p:not(.product)` 계열로 다시 쓰고,
  `.quantity` 블록은 데스크톱 전용임을 명시하거나 삭제한다.
  add_product 들여쓰기는 `padding-left` 를 `tr:not(#totalProductsOption)` 와 같은 구체도로 재선언한다.

## 6. 실기(대표님 폰) 확인이 반드시 필요한 잔여 항목

jsdom 은 레이아웃을 계산하지 않는다. 아래 6건은 **코드로는 판단 불가**다.

1. **K-09 AC6 지연로딩** — `#prdDetail` 이미지는 `src` 가 아니라 `ec-data-src` 이고 `width/height` 속성이 없다.
   로드 전 높이가 0 이라 `max-height:1700px` 클램프 박스가 **거의 비어 보이고 베일·버튼이 위로 올라붙는** 첫 페인트가 우려된다.
   「상세 정보 모두 보기」 후 14장이 전부 뜨는지, `dispatchEvent(scroll/resize)` 로 로더가 실제로 재훑는지 확인 필요.
2. **K-09 AC8** — 접힘/펼침 양쪽에서 `.detail-tab__item[data-link="prdDetail"]` 앵커가 `#prdDetail` 상단으로 정확히 가는지.
   `.zg-dh` 헤더가 새로 위에 붙어 스크롤 오프셋이 달라졌을 수 있다.
3. **K-17 AC4** — 스티키 탭바 `fixed` 상태에서 `.header__wrap.up` 과 겹치는지.
4. **K-12 AC2 실측 높이** — 82px 명세 대비 실제 몇 px 인지, R2 수정 후 재측정.
5. **K-06 AC2/AC3** — 추가상품 3종의 썸네일 54×54 정렬과, 63번 세트상품의 긴 이름
   `[설인아 PICK] 붓기 부스터 젠제네틱스 칼륨(2box) & 비타민B컴플렉스(1box) SET` 의 2줄 말줄임.
6. **iOS Safari 전용** — `backdrop-filter: blur(10px)`(바), `clip-path: inset(50%)`(select·`#totalPrice`),
   `env(safe-area-inset-bottom)`. 특히 `clip-path` 로 감춘 select 에 카페24 검증이 포커스를 줄 때
   iOS 가 화면을 튀게 하는지. **SwiftShader/jsdom 어느 쪽도 재현 불가.**

추가로 **9종 복제 전 반드시 확인할 구조 리스크 2건** (11번에서는 드러나지 않음):
- `buildOptionCards()` 는 DOMContentLoaded 시점의 `select.options` 를 한 번만 읽는다.
  11번은 `option_type="T"`(서버 렌더 select)라 정상이지만, `option_type="F"`(품목 조합, 런타임 생성)
  상품에서는 **카드가 0장**이 된다.
- `#totalProducts tbody td .product { font-size:0 }` 는 `<span>`(옵션 라벨)만 보이게 하는 설계다.
  옵션 없이 `add_option` 만 있는 상품은 `p.product` 에 `<span>` 이 없어 **행 텍스트가 통째로 안 보이고**,
  동시에 `pickedRows()` 의 key 가 빈 문자열이 되어 카드 선택 표시도 붙지 않는다.
