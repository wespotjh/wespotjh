## 판정할 수 없었던 것 — 정직하게 분리한다

**"`@js()` 가 없는 파일/폴더를 가리키면 카페24가 어떻게 하는가"는 증명하지 못했다.**

raw-deflate + base64url, 구분자 `\x15`, `_`→`\x0b` `.`→`\x0c` `-`→`\n` 치환.
내 인코더가 **실제 URL 과 바이트 동일**한 문자열을 만드는 것까지 확인했다(round-trip identical: True).
그런데 목록에 없는 파일을 한 개 끼워 넣거나 `skin10` 으로 바꾸면 **전부 404** 다 —

구조적으로는 이렇게 추정된다(**추정이다, 사실로 쓰지 마라**):
번들은 `optimizer_user.php` 가 서버에서 이어붙여 만드는 **하나의 응답**이다.
읽을 수 없는 항목이 응답 전체를 404 로 만든다면 오타 한 개로 몰 전체 CSS 가 날아가므로, 보통은 그 항목만 빈 채로 넘어간다.
그러면 **"GA4 가 v2 전 페이지에서 통째로 안 실린다"** 가 실제 결과다 — 몰이 죽지는 않지만 계측은 0 이다.

## R-2 (P0) — 옵션 없는 상품 61·62 에서 F-4 모순이 그대로 재현된다

`anyRows()` 는 `tr.option_product, tr.add_product` 만 센다(`detail-ui.js:153`).
**라이브 61·62 에는 그 두 클래스가 붙은 행이 영원히 생기지 않는다.**

라이브 원문 대조 (같은 자리, 같은 UA):

```
product 11 (필수옵션)          product 61 (옵션 없음)
<tbody class="displaynone">    <tbody class="">          ← 61 은 이 행이 "보이는" 행이다
  <tr>                           <tr>                    ← .option_product 도 .add_product 도 아니다
    <td>젠제네틱스 …칼륨</td>       <td>젠제네틱스 …데이팩</td>  ← p.product 도 <span> 도 없다
    <span class="quantity">        <span class="quantity">
      <input id="quantity"           <input id="quantity"
             name="quantity_name"           name="quantity_opt[]"
             value="0">                     value="1">   ← 이미 1개가 담겨 있다
      <a class="up QuantityUp">      <a class="up QuantityUp">
    <td class="right">             <td class="right">
      <span class="quantity_price">   <span class="quantity_price">15000</span>
                                                          ← strong.price 도 .ec-front-product-item-price 도 없다
```

결과: `refresh()` 에서 `anyRows().length === 0` → `.zg-picked-0` 이 **영구 유지** →
`.zg-picked-head__empty`("구성을 선택해 주세요.")가 계속 보인다.
그런데 카페24가 정적행(수량 1, 15,000원)으로 `#totalPrice` 를 채우면 `num > 0` 이 되어
하단바에는 **금액이 뜬다**. 반려 F-4 가 지적한 바로 그 모순이 **선택할 옵션조차 없는 상품**에서 재현된다.

개발 2차는 "9종 구조 리스크 2건 전부 FIXED" 로 보고했지만,
- 리스크1(`option_type="F"` 런타임 옵션 주입)은 **7상품 중 0건** — 존재하지 않는 위험을 막았다
  (11·13·16·63·64 는 `option_type="T"`, 61·62 는 옵션 자체가 없다)
- 실제로 존재하는 위험(**옵션 없는 상품, 9종 중 2종**)은 **막지 못했다**

같은 원인으로 개발 §3 표의 각주 **"PC 규칙이 모바일에서 1~2 로 잡히는 것은 `<tbody class="displaynone">` 의 영구 숨김 템플릿 행"** 도
**61·62 에서는 거짓**이다. 그 행은 숨겨져 있지 않고, 그 상품의 **유일한 실제 수량 컨트롤**이다.
(우연히 결과는 좋다 — `span.quantity` 규칙이 걸려 스테퍼가 스타일링된다. 그러나 근거가 틀렸다.)

**수정 방향(한 줄급):** 빈 상태 판정을 클래스가 아니라 **"보이는 행"** 기준으로 바꾼다 —
`#totalProducts > table > tbody:not(.displaynone) > tr` 중 `#totalProductsOption` 이 아닌 것.
`tr.option_product` 를 카드 선택 표시의 진실원장으로 쓰는 규칙(기획 §6)은 그대로 둔다.

## R-4 (P1) — `<link>` 3줄은 `<head>` 로 올라가지 않는다

콘텐츠 템플릿은 `layout.html:14` 의 `<!--@contents-->` 자리, 즉 **`<body>` 안**에 들어간다.

## R-5 (P1) — `unlazyDetailImages()` 가 `CAFE24.lazyload()` 를 아예 기동시키지 않는다

시스템 JS 번들 원문:

```js
EC$(function() {
    sAttribute = 'ec-data-src';
    if (EC$('img['+sAttribute+']').length > 0) {
        CAFE24.lazyload();
    }
});
```
`CAFE24.lazyload()` 는 IntersectionObserver **와 함께 MutationObserver 도 건다**
(`document.body.childNodes` 전부에 `{childList:true, subtree:true}` — 나중에 삽입되는 `img[ec-data-src]` 를 잡기 위한 것).

라이브 11번의 `ec-data-src` 는 **정확히 14개이고 전부 `#prdDetail` 안**(오프셋 199,167~)이다.
우리가 파싱 시점에 14개를 전부 승격하고 속성을 지우면 → 위 가드가 **0** 이 되어 `CAFE24.lazyload()` 가 **호출되지 않는다** →
MutationObserver 도 시작되지 않는다.

지금은 무해하다(연관상품 `#related` 가 7상품 전부에서 렌더되지 않아 후삽입 지연이미지가 0건이다 —

# (f) 대표님 배포 순서 체크리스트

## F-0. 가장 중요한 사실 — **지금 편집해도 판매는 안 멈춘다**

라이브에 적용된 스킨은 **skin4(바디랩 반응형)** 이다. 작업본(`젠제네틱스 v2 작업본`, skin_no=16 = skin10)은 **적용돼 있지 않다.**
(증명: 라이브 번들 `filename=` 페이로드가 전부 `sde_design/**skin4**/...` 다.)

→ **아래 ①~⑤ 를 저장하는 동안 라이브 쇼핑몰은 1초도 영향을 받지 않는다.**
위험은 마지막 **"디자인 적용"** 한 번뿐이다. 그러므로 규칙은 하나다:
**전부 저장하고 미리보기로 확인한 다음에 적용한다. 중간에 적용하지 않는다.**

⚠ 만약 실수로 **바디랩 반응형(라이브 대표디자인)** 을 편집하면 이 안전판이 사라지고 아래 "깨지는 조합"이 실제로 판매를 막는다.
편집 시작 전 편집기 상단의 디자인 이름이 **`젠제네틱스 v2 작업본`** 인지 반드시 확인한다.

### F-7 관련, 개발 §3 표의 사실 정정 2건 (경미하나 표가 틀렸다)

1. **`td.right strong.price` 는 COMMON 이 아니다.** 원문상 모바일만 `<strong id="X_price" class="price">` 이고

2. **`<td>` 의 의미가 UA 별로 다르다.** 모바일 = [옵션명+수량] [금액] [삭제] / 데스크톱 = [옵션명] [수량+삭제] [금액].
   `nth-child` 로 잡으면 반드시 깨진다. **우리 CSS 는 `nth-child` 를 쓰지 않는다 ✔** (스킨은 쓴다 — 스킨 문제)
3. 스킨 자체 버그 하나 기록: `body:not(#userStyle) #totalProducts .eProductQuantityUpClass:before/:after` 가
   선택자 목록에서 빠져 있다(`eAddProduct…` 가 중복 기재돼 있다). 모바일 행은 `p:not(.product)` 계열 규칙이 덮어 무해하다. **우리 책임 아님.**
