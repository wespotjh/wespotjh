# 0. 먼저 — `.fixed` 가 아닌 상태는 언제 생기며, 그때 발화하는가

## 0-1. 스킨 원문 (사용자 JS 번들 `optimizer_user.php`)

```js
function mobileLayerOn() {                                   // @39,164
  if ($('.jsMobileLayer').hasClass('fixed')) {
      $('.jsMobileLayer, .jsMobileLayerBG').addClass('on');   // ← 시트 열기
      if ($window.outerWidth() <= 768) $('.jsMobileLayer').stop(true,true).animate({bottom: 0});
  } else {
      $('.buy-btn-wrap').find('.btnSubmit.gFull.sizeL').trigger('click');   // ← @39,491 인라인 버튼 발화
      $('html, body').stop(true,true).animate({scrollTop: $('.buy-btn-wrap').position().top - ($(window).outerHeight()/2)});
  }
}
$('.jsLayerBtn').on('click', mobileLayerOn);                 // @51,985 — 하단바 「구매하기」
```

```js
function checkScroll(){                                      // @45,912
  if ($window.outerWidth() < 1024) {
      var infoPos = $('.infoArea').offset().top;
      var infoHeight = $('.infoArea').outerHeight();
      top = infoPos + infoHeight;                            // ← 임계값 = .infoArea 하단
  }
  if ($document.scrollTop() > top) { … jsFixLayer.addClass('fixed'); … }
  else { … jsFixLayer.removeClass('fixed'); FixLayerClose(); … }
}
checkScroll();  $(window).on('scroll', function(){ checkScroll(); scrollTab(); });   // @50,982
```

**⇒ `.fixed` 가 아닌 상태 = `scrollTop ≤ .infoArea 하단`** (모바일 폭 <1024 기준). 즉 **페이지 최상단~상품정보 영역을 다 지나기 전까지.** 초기값은 `top = jsFixLayer.offset().top + height + 500`(@31,395)이지만 `checkScroll()` 이 로드 직후 1회 호출되며 위 값으로 덮인다. **개발이 말한 "`scrollTop > .infoArea 하단`" 이 맞다.**

## 0-2. 숨은 인라인 버튼이 `trigger('click')` 으로 발화하는가 — **한다 (실측)**

jQuery **3.6.0**(라이브 번들 버전과 동일, `jQuery JavaScript Library v3.6.0`) 로 최소 재현:

```
{"jq":"3.6.0","hiddenBefore":"none","firedHidden":1,"posTopHidden":0,"offsetTopHidden":0,
 "hiddenAfter":"block","firedVisible":2,"posTopVisible":8}
```

- 부모가 `display:none` 인 상태에서 `$('.buy-btn-wrap').find('.btnSubmit.gFull.sizeL').trigger('click')` → **인라인 `onclick` 이 1회 발화**(`firedHidden:1`). jQuery `trigger` 는 바인딩 핸들러 실행 후 네이티브 `elem.click()` 을 부르고, 네이티브 클릭은 가시성과 무관하다.
- DOM 도 그대로다 — 우리 CSS 는 `display` 만 끈다. `onclick="{$action_buy}"`·`onclick="{$action_basket}"` 두 개 모두 살아 있다(`product/detail.html:497-499`).

## 0-3. ★ 조건 — 그 다음 줄의 스크롤이 「맨 위로」가 된다 (P3)

같은 실측에서 **숨은 상태의 `$('.buy-btn-wrap').position().top === 0`**(`offset().top` 도 0). 그래서 `animate({scrollTop: 0 - innerHeight/2})` = 음수 → **0으로 잘려 페이지가 맨 위로 간다.**
- 원래 의도는 "인라인 구매 버튼 자리로 데려다 준다"였는데, 그 블록을 숨겼으니 데려다줄 자리가 없다.
- **영향:** 최상단에서 누르면 이미 0이라 눈에 안 띈다. `.infoArea` 하단 직전(예: y=300)에서 누르면 **화면이 맨 위로 튄다.** 구매 동작 자체는 이미 발화한 뒤라 **기능 손실은 없다.**
- 코드 수정 없이 닫으려면 임계 구간이 짧다는 점을 안내하는 것으로 충분하다고 본다 → 배포표 ④ 문구에 **"맨 위에서는 시트가 열리는 대신 바로 구매 흐름으로 넘어간다(정상)"** 로 적었다. 완전 제거를 원하면 JS 가 필요하므로 **13차 선택 사항**으로 남긴다.

# 1. 준비해 둔 3항목 — 답

## ① 하단바에서 부를 수 있는 것 / 없는 것

| 대상 | 위임 방식 | 하단바(행 밖)에서 호출 |
|---|---|:--:|
| 인라인 `onclick="{$action_buy}"` / `{$action_basket}` | 요소 자체 클릭 — 컨텍스트 없음 | **가능** (B안이 쓰는 경로, §0-2) |
| `mobileLayerOn()` | `$('.jsMobileLayer')`·`$('.buy-btn-wrap')` 를 **문서 전체**에서 찾는다 | **가능** |
| 수량 ± `a.eProductQuantityUpClass/DownClass`, `a.eAddProductQuantityUpClass/DownClass` | 핸들러가 `document.getElementById($(this).data('target'))` 로 대상을 **id 로** 찾는다 | **가능** (단 그 `data-target` id 를 가진 요소가 있어야 함) |
| **삭제 `.option_box_del`** | 핸들러가 `oSelf.closest('.option_product')` / `oSelf.parents('tr,li').last()` 로 **자기 조상 행**을 지운다 | **불가** — 행 밖 복제본을 누르면 지울 행을 못 찾는다 |
| **추가상품 삭제 `.option_add_box_del`** | 위와 동일 + `oSelf.attr('id')` 에서 옵션 id 를 잘라 쓴다 | **불가** (id 까지 복제하면 중복 id 가 되어 더 위험) |
| `#totalProducts a.delete` 래퍼 | `EC$(this).find('.option_box_del').click()` — 자기 안을 찾는다 | **불가**(자식이 없으면 무동작) |

**규칙:** *요소를 눌러 자기 자신 또는 `data-target` id 로 대상을 지정하는 핸들러* 는 하단바에서 불러도 되고, *`closest()`/`parents()` 로 조상을 거슬러 대상을 찾는 핸들러* 는 **행 안에서만** 성립한다. B안은 앞쪽만 쓴다 ✔.

## ② 시트가 숨은 상태에서 `select`/`input` 값 읽기·`click()`

| 되는 것 | 안 되는 것 |
|---|---|
| `.value` 읽기·쓰기, `select.value = …` + `dispatchEvent('change')` | `.focus()` (display:none 요소는 포커스 불가) |
| `element.click()` · jQuery `.trigger('click')` — **인라인 onclick 포함**(실측 `firedHidden:1`) | `offset()`·`position()`·`outerHeight()` = **0** (실측) → 스크롤·위치 계산 전부 무의미 |
| `querySelector` 로 찾기, 클래스·속성 조작 | `:visible` 셀렉터 매칭, `scrollIntoView`, `slideDown/animate` 의 높이 계산 |

우리 CSS 가 숨기는 것은 **`#fixedActionButton` 하나**이고 그 안에 `select`·`input` 은 없다(옵션 select 는 `.opt-content` 쪽, 수량 input 은 `#totalProducts` 행). 그래서 값 읽기 문제는 발생하지 않고, **걸린 것은 §0-3 의 위치 계산 0 하나뿐**이다.

## ③ `body.eMobilePopup` · `html.scroll-disabled` + 시트 열닫

- 우리 규칙은 `.mobile-layer:not(.on)` 과 `.zg-detail.zg-sheet-open` — **body/html 클래스에 의존하지 않고, 붙이지도 않는다.** `detail-ui.js` 는 `.mobile-layer` 의 class 변화를 MutationObserver 로 보고 `.zg-detail` 에 `zg-sheet-open` 만 토글한다(사용자 번들 @27,082) → **body 오염 0**(칼륨 1차 이래 규칙 유지).
- 시트 자체는 `position:fixed` 오버레이라 열닫이 문서 흐름 높이를 바꾸지 않는다. 인라인 블록의 `display` 토글도 **시트 내부**에서 일어나므로 본문 스크롤 위치에 영향이 없다.
- 스크롤을 움직이는 것은 스킨 자신의 두 곳뿐이다: `mobileLayerOn()` 의 not-fixed 분기(§0-3), `.mobile-layer.fixed .opt-content` 애니메이션(@66,171). **우리 CSS 가 새로 만드는 스크롤 이동은 없다.**
- `body.eMobilePopup{overflow:hidden;position:fixed}` 가 붙은 상태(검색 오버레이·팝업)에서 시트를 여는 조합은 **실기 항목**으로 남긴다 — 픽스처로 클래스를 주입해 확인할 수는 있으나 실제 UI 경로(검색창 열고 그 위에서 구매)가 대표님 폰과 다를 수 있다.
