## 3. 남아 있던 질문 3건 — 판정

### 3-1. `.zg-a11y-hide` 두 규칙 공존 — **싸우지 않는다. 이대로가 맞다. 합치지 마라.**

computed style 로 **속성별 소유권**을 확인했다. 겹치는 속성은 4개뿐이고 각각 승자가 하나로 확정된다.

| 속성 | `:103` 범용 유틸 (0,2,0) | `:449` select (0,4,1) | `:462` 구체도 보정 (0,4,2) | **실제 승자 (computed)** |
|---|---|---|---|---|
| `position` | `absolute` | — | — | **`absolute`** (유일 선언) |
| `margin` | `-1px` | — | — | **`-1px`** (유일 선언) |
| `clip-path` | `inset(50%)` | — | — | **`inset(50%)`** (유일 선언) |
| `white-space` | `nowrap` | — | — | **`nowrap`** (유일 선언) |
| **`width`** | `1px` | `100%` | **`1px`** | **`22px`** ← `:462` 승 (§3-2) |
| **`height`** | `1px` | `44px` | **`1px`** | **`2px`** ← `:462` 승 |
| **`padding`** | `0` | **`0 10px`** | — | **`10px 10px`** ← `:449` 승 |
| **`border`** | `0` | **`1px`** | — | **`1px`** ← `:449` 승 |

- **순환·왕복 없음.** 범용 유틸이 “보이지 않게 하는 4속성”을 공급하고, 구체도 보정이 “박스를 접는 2속성”만 덮는다.
  역할이 정확히 갈려 있다. 이것은 **범용 유틸 + 요소별 구체도 보정**이라는 정석 패턴이다.
- **합치면 안 되는 이유:** `:103` 은 `zg-` 네임스페이스의 **재사용 유틸**이다.
  구체도를 (0,4,2)로 올려 합치면 select 전용이 되어 재사용성이 사라지고,
  반대로 `:449` 안으로 접어 넣으면 “보이지 않게 한다”는 의도가 select 스타일 속에 묻힌다.
- `overflow` 는 `:103` 이 `hidden` 을 선언했으나 computed 는 `visible` 이다(스킨에 짐).
  **무해하다** — `clip-path` 가 페인팅과 히트 영역을 이미 비우고 박스가 22×2px 이라 넘칠 내용 자체가 없다.

### 3-2. select 박스 **22px** — **의도된 결과이고 남은 문제가 아니다**

```
선언   : width: 1px  (`:462`)  +  box-sizing: border-box  (`:449`)
제약   : border-box 는 padding+border 아래로 줄어들 수 없다
내역   : padding 10 + 10  +  border 1 + 1  =  22px   ← 이것이 22의 전부
높이   : height 1px + border 1 + 1 = 2px
```

`width:1px` 은 **선언대로 적용됐고**, 물리적으로 더 줄어들 수 없어 22px 에서 멈춘 것이다.

**무해함을 4가지로 확인:**

| 확인 | 실측 |
|---|---|
| 뷰포트 밖으로 나가는가 | `left 35 / right 57` — **안쪽.** 320px 에서도 `scrollW 320 = clientW 320` ✅ |
| 클릭을 가로채는가 | `elementFromPoint(박스 정중앙)` = **`null`** — `clip-path:inset(50%)` 가 히트 영역까지 비운다 ✅ |
| 카페24 옵션 검증이 포커스를 잡는가 | `display:block` · `visibility:visible` · `select.focus()` → `document.activeElement === select` **성공** ✅ |
| 눈에 보이는가 | `clip-path:inset(50%)` — 안 보인다 ✅ |

**8종 복제 시 회귀 판단 근거 (요청하신 것):**
> **22px = 2×padding(10px) + 2×border(1px).** 두 값은 `detail.css:449` 의 우리 선언에서만 나오고 **상품과 무관하다.**
> 따라서 **9종 전부 22px 이어야 정상**이다. 22 가 아닌 값이 나오면 `:449` 의 `padding: 0 10px` 또는 `border: 1px` 가 바뀐 것이고,
> 그때만 회귀로 본다. **자연폭·옵션 개수·상품 종류는 이 값에 영향을 주지 않는다.**

정확히 1×1 로 만들려면 `:462` 에 `padding:0; border-width:0` 을 더하면 된다. **권고하지 않는다** —
관측 가능한 차이가 0인데 포커스·검증 경로가 걸린 요소를 더 건드릴 이유가 없다.

## 4. 개발이 남긴 불안 — `min(100%, 640px)` 의 `640` 상수 검증

**개발 주장:** *“어느 쪽으로 틀려도 화질 회귀는 재발하지 않는다 — 더 넓은 원본 → 확대 없음, 더 좁은 원본 → 예약만 커짐.”*

**판정: 절반만 맞다. 앞쪽은 맞고 뒤쪽은 틀렸다.**

원본 폭 4종(400 / 640 / 1080 / 2000px) × 뷰포트 4종으로 실렌더했다.

| 원본 폭 | 390px | 768px | 1023px | 1280px | 판정 |
|---|---|---|---|---|---|
| **400px** | 0.97x ✅ | **1.60x ❌** | **1.60x ❌** | 1.00x ✅ | **확대 발생** |
| **640px** (현재 9종) | 0.61x ✅ | 1.00x ✅ | 1.00x ✅ | 1.00x ✅ | 안전 |

- **더 넓은 원본 → 확대 없음: 맞다** (1080·2000 전부 1.00x 이하) ✅
- **더 좁은 원본 → 예약만 커진다: 틀리다.** 400px 원본은 768·1023px 뷰포트에서
  `min(768, 640) = 640px` 로 강제돼 **+60% 확대**된다. **H-1 과 똑같은 실패 모드가 임계값만 바뀐 채 재발한다.** ❌

### 그래서 8종 전개 게이트를 이렇게 바꾼다

> **상품당 IHDR 1회 확인은 필요하다(개발 말대로).**
> 다만 판정 기준은 “값이 640인가”가 아니라 **“그 상품의 상세 이미지 최소 원본 폭 ≥ 640px 인가”** 다.
> - **전부 ≥ 640px** → 현재 코드 그대로 안전 (현재 6개 상품 101장 전부 639~640px — 639px 은 640으로 +0.16% 늘지만 육안 식별 불가)
> - **하나라도 < 640px** → 그 상품은 `min-width` 를 **그 상품의 최소 원본 폭**으로 낮추거나 빼야 한다

**상수를 아예 없애는 대안도 실렌더로 확인해 뒀다(8종 라운드 검토용, 이번엔 바꾸지 않는다):**

```css
@media (max-width: 1023px) {
  .zg-detail #prdDetail .zg-fold img { min-width: 0; min-height: 60vw; }
}
```
폭을 건드리지 않고 **높이로만 자리를 예약**하므로 **확대가 원천적으로 불가능**하다.
실측: 400/640/1080px 원본 × 390/768/1023px 뷰포트 **9조합 전부 확대 없음**, 스크롤 전 요청 3~6장(14장 아님), 최종 14/14.
