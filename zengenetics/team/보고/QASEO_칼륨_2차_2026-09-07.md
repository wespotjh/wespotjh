## 2. 접기가 남아 있어도 색인이 되는가 (오케스트레이터 질의 4)

`overflow:hidden` + `max-height` 는 **그대로 남아 있다**(`detail.css:893`, 데스크톱 `:1134` 2200px).
그럼에도 색인이 되는 이유는 **차단 지점이 달랐기 때문**이다.

| | 1차(반려) | 2차(현재) |
|---|---|---|
| 클리핑 | `overflow:hidden` | `overflow:hidden` (동일) |
| 이미지 `src` | **1×1 placeholder 로 고착** | **실제 URL 14/14** |
| 이미지 `alt` | 0장 | **14장** |
| 차단 원인 | IO 교차 사각형이 조상 클립과 교집합 → 영구 미교차 | **IO 를 아예 우회** — 속성 제거로 로더 관할 밖 |

**클리핑이 색인에 영향을 주지 않는 근거:**
1. `overflow:hidden` 은 **시각적 클리핑일 뿐** — 요소는 DOM 에도, 레이아웃에도, 접근성 트리에도 남는다.
   색인에서 실제로 불리해지는 것은 `display:none`·`visibility:hidden`·JS 지연삽입이며, 개발은 셋 다 쓰지 않았다.
2. `alt` 는 **속성**이다. 시각 클리핑과 무관하게 파싱된다.
3. 구글은 2018 모바일 퍼스트 색인 이후 **탭·아코디언 등 상호작용 뒤 콘텐츠를 감점 없이 색인**한다.
   접기(K-09)는 그 표준 패턴이며, 텍스트가 DOM 에 남는 형태로 구현됐다.
4. 이미지 색인은 렌더 시점 **`src` 속성 값**으로 발견되고, 실제 픽셀 취득은 Googlebot-Image 의 별도 요청이다.
   `loading="lazy"` 로 브라우저가 안 받아도 **URL 발견에는 지장이 없다.** (`ec-data-src` 는 구글이 모르는 사설 속성이라 발견 불가였다 — 이것이 1차 반려의 본질)

**상세 본문 추출 텍스트: 0자 → 518자**

| 구분 | 1차 | 2차 |
|---|---|---|
| 폴드 밖 가시 텍스트 | 0자 | **121자** (`Product detail` / `상세 정보` / `상세 정보 모두 보기` / 칩 3개 / 각주 2줄) |
| 폴드 안 `alt` 텍스트 | 0자 | **397자** (14장) |

## 5. `alt` 내용 판정 ✅

**14장 전부 서로 다른 문자열이다. 중복 alt 아니다.**

```
젠제네틱스 포타슘 칼륨 (20ea) 상세 이미지 1
…
젠제네틱스 포타슘 칼륨 (20ea) 상세 이미지 14
```

| 검증 | 결과 |
|---|---|
| 생성 규칙 | `nm + ' 상세 이미지 ' + (i+1)` — **인덱스가 붙어 14장 전부 유일** ✅ |
| `nm` 출처 | `document.querySelector('.prd-name').textContent` |
| 라이브에서 `.prd-name` 개수 | **정확히 1개**(오프셋 163,527) → 오탐 없음 ✅ |
| 실제 textContent | `젠제네틱스 포타슘 칼륨 (20ea)` — `<span class="icon">` 안의 아이콘은 텍스트가 없어 오염 없음 ✅ |
| 사실성 | `{$name}` 에서 읽은 값 + 순번뿐. **문구를 창작하지 않았다** ✅ (사실성 원칙 준수) |
| 기존 `alt` 보호 | `if (!img.getAttribute('alt'))` — 이미 있으면 덮지 않는다 ✅ |
| 9종 복제 안전성 | 상품명을 런타임에 읽으므로 **8종 복제 시 자동으로 상품별 alt** 가 된다 ✅ |

**한계(정직하게 명시):** 순번 alt 는 "무엇이 그려져 있는가"를 말하지 않는다. 스크린리더 사용자에게
「상세 이미지 7」은 정보가 아니다. **다만 alt 0개 + `src` 없음(색인 불가) 상태에서 출발했으므로
명확한 개선**이고, 존재하지 않는 내용을 지어내는 것보다 옳다.
→ **P2 이월:** 이미지별 실제 내용 alt 는 NNEditor 원본에 넣는 것이 정도다(관리자 소관, 대표님·기획 판단).
