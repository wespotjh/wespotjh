## 2. ★ `content` 로 넣은 글자를 스크린리더가 읽는가 — **읽는다(주요 조합). 다만 보장은 아니다**

**근거:** W3C **Accessible Name and Description Computation 1.2 §4.3.2 Step 2F** 가 이름 계산에 *"CSS `::before`/`::after` 로 생성된 텍스트"* 를 **포함하도록 규정**한다. 이에 따라 Chrome/Edge·Firefox·Safari 가 생성 콘텐츠를 접근성 트리의 텍스트로 노출하고, NVDA·JAWS·VoiceOver 가 읽기 모드에서 낭독한다. 즉 **현행 주요 조합에서는 「추가 (상품명)」으로 읽힌다.**

**그러나 보장은 아니다.** ⑴ 스펙이 규정하는 것은 *이름 계산*이고, 여기 `p.product` 는 이름 계산 대상 컨트롤이 아니라 **읽기 모드 텍스트**라 구현체 재량이 남는다 ⑵ CSS 가 로드되지 않거나 사용자 스타일시트·리더 모드·고대비 모드가 걸리면 **글자 자체가 사라진다** ⑶ 텍스트 복사·번역·검색에 잡히지 않는다.

### 이번 변경이 접근성을 후퇴시켰는가 — **아니다** ✅
지운 두 신호(배경 톤 `--zg-bg-2`, 좌측 레일 `inset 3px`)는 **둘 다 순수 시각 신호**다. 스크린리더 사용자에게는 **원래부터 없던 정보**이므로 이번 삭제로 잃은 것이 없다. 비시각 경로의 유일한 단서는 이전에도 `::before` 하나였다.
→ **회귀 아님. 반려 사유 아님.**

### 다만 위험이 올라갔다 → **P1 권고 (실텍스트 이중화, 2~3줄)**
이제 **모든 사용자에게** 「추가」 칩이 유일한 구분자다. `::before` 가 사라지는 조건(CSS 미적용·리더 모드)에서는 **본품과 추가상품이 완전히 동일하게 보이고 읽힌다** — 결제 직전 목록에서 이것은 오해를 만든다.

**대체안 — 이미 있는 유틸을 쓴다** (`detail.css:103-111 .zg-a11y-hide`, 클립 방식이라 렌더 트리·접근성 트리에 남는다):
```js
/* detail-ui.js readRow()/refresh() 의 tr.add_product 처리부에 1회만 */
var p = row.querySelector('td .product');
if (p && !p.querySelector('.zg-add-flag')) {
  var f = document.createElement('span');
  f.className = 'zg-add-flag zg-a11y-hide';
  f.textContent = '추가 구성 상품, ';
  p.insertBefore(f, p.firstChild);
}
```
- **DOM 실텍스트**라 낭독이 보장되고, CSS 가 죽어도(클립이 안 걸려도) 글자가 남아 오히려 안전하다.
- 시각 결과 변화 **0** — 칩은 `::before` 가 계속 그린다. 대표님 요청(흰 배경 + 「추가」 태그 유지)과 충돌 없음.
- `.zg-add-flag` 중복 삽입 가드 포함. **CSS 추가 0줄**(기존 유틸 재사용).

> 대안으로 `::before` 를 지우고 실텍스트 `<span>` 에 칩 스타일을 주는 방법도 있으나, 그러면 CSS 셀렉터를 새로 짜야 하고 카페24가 행을 복제할 때마다 JS 삽입에 의존하게 된다. **현행 `::before` 유지 + 숨김 텍스트 추가**가 변경량이 가장 작다.
