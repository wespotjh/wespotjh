# 라이브 대조 감사 — zengenetics.co.kr vs 저장소 스킨 코드

**일시** 2026-09-06 · **지시** 대표님: *"우리 홈페이지 들어오면 저 코딩이랑 좀 다를 수 있어.
처음에 저렇게 작업했었고 지금은 저거 안 보이게 해뒀거든. 우리가 수정을 좀 많이 했어."*
**방법** curl 로 라이브 전 페이지 + 정적파일 53종 직접 수집 후 저장소 사본과 바이트 대조
(헤드리스 브라우저는 프록시가 차단 — `ERR_CONNECTION_RESET`. curl 은 통과)

---

## 결론 3줄

1. **우리가 확보한 스킨 코드는 최신이 맞다.** 정적파일 53종 전부 라이브와 **바이트 단위 일치**.
2. **다만 혜택가 카드는 라이브에서 꺼져 있다.** 코드는 살아 있는데 관리자 설정이 빠져서 안 그려진다.
   → 어제 내가 갈아입힌 `price.css` 는 **지금 화면에 안 나오는 영역**이다.
3. **상품·가격·라인업은 저장소 프로토타입과 다르다.** 단품 3종이 아니라 **10종**이고 가격도 바뀌었다.

---

## 1. 정적파일 대조 — 53/53 일치

`cafe24-skin/` 의 CSS·JS 53개를 zengenetics.co.kr 에서 같은 경로로 받아 md5 비교.

| 결과 | 개수 |
|---|---|
| 라이브와 완전 일치 | **53** |
| 다름 | 1 — `ds/css/price.css` (**내가 어제 고친 것**. 라이브는 아직 옛 버전) |
| 404 | 0 |

`ds/js/price-config.js`·`ds/js/detail.js` 도 라이브 번들(`optimizer_user.php`)에서 원문을 뽑아
대조했고 **한 글자도 다르지 않다.** 쿠폰 20,100원·색 `#ff0000` 도 라이브에 그대로 살아 있다.

템플릿(HTML)도 대조했다. `product/detail.html` 은 표지 221개 중 **207개가 라이브에 그대로**
있고, 빠진 14개는 전부 "렌더될 조건이 아닌 블록"(옵션 선택 UI, 상품문의 작성폼)이다.
`footer.html`·`detail_tab.html`·`review.html`·`banner_manager.html` 은 **표지 100% 일치**.

> 즉 **대표님이 주신 템플릿과 우리가 긁은 파일은 지금 라이브 그대로다.** 여기는 문제 없다.

## 2. ⚠️ 혜택가 카드(.ds_benefit)는 지금 라이브에서 안 나온다

라이브 상세페이지에 껍데기는 그대로 있다:
```html
<div class="ds_benefit" style="display:none;">   <!-- 여기서 끝. JS가 채우지 않음 -->
```

**안 나오는 이유** — `ds/js/detail.js` 가 시작하자마자 빠져나간다.

```js
customOption3 = document.querySelector('.spec li.custom_option3') || document.querySelector('tr.custom_option3_css');
...
if (checkNoPricesDisplayY()) return;   // ← 여기서 return
```

`detail.js` 는 **`tr.custom_option3_css` / `tr.custom_option4_css` 안의 값이 `Y` 인지**를 보고
카드를 그린다. 그런데 라이브 상세페이지에는

- `detail-spec` **표 자체가 렌더되지 않는다** (관리자 상세정보 표시항목이 비어 있음)
- 가격줄에 남아 있는 건 `custom_option1_css`(값 1) · `custom_option2_css`(값 14) 둘뿐
- **`custom_option3` / `custom_option4` 는 어디에도 없다**

→ 판정 함수가 "표시할 가격 없음"으로 보고 **즉시 return** → 카드가 영영 안 그려진다.
대표님이 *"지금은 저거 안 보이게 해뒀거든"* 하신 게 이 상태다. 코드를 지운 게 아니라
**관리자 표시항목에서 3·4번을 빼서 꺼둔 것.**

### 그래서 대표님 결정이 필요하다

| 안 | 내용 | 결과 |
|---|---|---|
| **A. 되살린다** | 관리자 → 상품 상세정보 표시항목에 `custom_option3`·`custom_option4` 를 다시 넣고 값 `Y` | 어제 만든 새 디자인이 바로 나옴. 쿠폰 20,100원 문제도 같이 정리해야 함 |
| **B. 안 쓴다** | 혜택가 카드는 버리고, 우리 상품페이지 디자인의 가격 영역으로 대체 | 어제 `price.css` 작업은 보류(파일은 저장소에 남김). 이식 1호를 장바구니로 옮김 |

**어느 쪽이든 새 `price.css` 는 라이브에 안 올렸다.** 저장소에만 있다.

## 7. 확인 못 한 것 (정직하게 남김)

- **알파리뷰 실제 평점·리뷰 수** — JS로 나중에 불러오는 값이라 curl 로는 안 잡힌다.
  프로토타입의 `평점 5.0·리뷰 27`(비타민B), `4.8·54`(마그네슘)이 지금도 맞는지는 확인 못 했다.
  대표님이 화면에서 보이는 숫자를 알려주시면 그 값으로 맞춘다.
- **라이브 화면 스크린샷** — 프록시가 헤드리스 브라우저를 막아 실제 그림은 못 찍었다.
  구조·값은 HTML 원문에서 전부 확인했다.
- **관리자 설정 화면** — 계정이 없어 표시항목 설정을 직접 보진 못했다. 위 판정은 렌더 결과로부터의 역추론이다.
