## c-3. ★ **처방이 틀렸다 — `og:*` 는 JS 로 설정할 수 없다**

설계서 R-4 대응: *"페이지 최상단 인라인 `<script>` 에서 `document.title` · `meta[description]` · **OG 태그**를 설정한다."*

- `document.title` — 구글은 렌더 후 반영한다. **네이버 Yeti 는 JS 를 실행하지 않는다.**
  이 몰은 `wcslog.js`(네이버 애널리틱스)와 `incentoSEOScriptV1.js` 를 깔아 둔 상태다 → **네이버 유입을 신경 쓰는 몰이다.**
- **`og:title`/`og:description`/`og:image` 를 JS 로 바꾸는 것은 카카오톡·페이스북·인스타 크롤러에서 100% 무효다.**
  이 크롤러들은 원본 HTML 만 읽는다.
- 그런데 이 페이지의 **용도가 「인스타 프로필 · 광고 랜딩」**(설계서 C-3)이다.
  → **카카오톡으로 공유하면 카드가 `젠제네틱스 공식몰 / 단일 성분, 빠른 흡수 Zengenetics / 몰 공용 share-image` 로 뜬다.**
  실측: `/about.html` 의 `og:title` = `젠제네틱스 공식몰`, `og:image` = `/web/upload/share-image-1-….jpg`

**요구:** R-4 를 다음으로 다시 써라.
> **`<title>`·`og:*` 는 서버가 몰 기본값으로 고정한다. 우회로가 없다.**
> `document.title`·`meta[description]` 은 JS 로 설정한다(구글 렌더 크롤러에만 유효).
> **`og:*` 는 JS 로 설정하지 않는다 — 무효인 코드를 남기면 다음 사람이 「돼 있다」고 오해한다.**
> **SNS 공유 카드가 몰 기본값으로 나간다는 사실을 대표님 결정 항목으로 올린다**(광고 랜딩으로 쓸 것인가).

**이 항목은 문가온(SEO) 소관과 겹친다.** 장부 **E-2(홈 `<title>` P0)** 와 같은 뿌리이므로 **문가온에게 이관하고, 설계서는 「해결 못 함」을 명시만** 하면 된다.

## c-4. 덤 — 아직 안 닫힌 것 하나

전 페이지에 **`<meta name="description">` 2개 · `<meta name="keywords">` 2개**가 남아 있다(홈·상품·about 전부).
`<title>` 2개는 복구됐는데 description/keywords 는 그대로다. **문가온 소관 · 장부 이월 대상.**

# (d) 폰트 · 이미지 업로드 가능성

## d-1. 폰트 — **서빙은 증명됐다. 업로드는 미증명. 그리고 경로 형식에 함정이 있다**

| 질문 | 답 |
|---|---|
| 카페24가 스킨의 `.woff2` 를 서빙하는가 | **한다.** `/moa/fonts/pretendard/PretendardVariable.subset.91.woff2` → **200 · 37,948 B** |
| MIME 이 `font/woff2` 인가 | **아니다 — `application/octet-stream`** |
| 그런데 `x-content-type-options: nosniff` 가 있는데 괜찮은가 | **괜찮다.** `nosniff` 는 script·style 목적지에 적용되고 **font 는 대상이 아니다.** 무엇보다 **지금 라이브에서 Pretendard 가 그 MIME 으로 정상 렌더되고 있다 — 존재 증명** ✅ |
| **편집기 [파일 업로드]가 `.woff2` 를 받는가** | ❌ **증명 못 했다.** `/moa/fonts/` 는 **구매한 바디랩 스킨에 처음부터 들어 있던 파일**이지 편집기 업로드의 증거가 아니다. **`/about.html` 200 과 정확히 같은 논리 함정** |

### ★ 그리고 설계서가 놓친 것 — **`@font-face` 의 `url()` 은 반드시 루트 절대경로여야 한다**

`ds/css/brand-story.css` 는 **`optimizer_user.php` 번들 안으로 들어간다.**
번들의 실제 URL 은 **`/ind-script/optimizer_user.php?filename=…`** 이므로,
CSS 안에 `url(bs-serif-400.woff2)` 같은 **상대경로를 쓰면 `/ind-script/bs-serif-400.woff2` 로 해석돼 404 가 난다.**

증거 — 스킨은 이 규칙을 이미 지키고 있다:
- 사용자 CSS 번들 207,864 B 의 `url()` **29개 중 상대경로 0개** (루트절대 19 · 프로토콜절대 10)
- 번들 안 **`@font-face` 0개** — Pretendard 의 `@font-face` 는 **`moa/layout/fonts.html` 의 인라인 `<style>`** 에 있고 `url(/moa/fonts/…)` 루트절대다

**요구:** 설계서에 한 줄 명시하라 —
> `brand-story.css` 안의 모든 `url()` 은 **루트 절대경로**로 쓴다. 예: `src: url(/ds/css/bs-serif-400.woff2) format('woff2')`.

### 폰트를 어디에 둘 것인가
설계서는 `ds/image/` 를 제안했다. **`ds/css/` 를 권한다** — 새 폴더 0개인 것은 같고,
업로더가 폴더 성격으로 확장자를 거르는 경우 **이미지 폴더가 `.woff2` 를 거절할 확률이 더 높다.**
(어느 쪽이든 `url()` 은 루트절대이므로 코드 차이는 경로 문자열 하나뿐이다.)

### 판정 요약
**설계서의 폰트 처방(1.23 MB → 47 KB) 자체는 옳고 근거도 실측이다.** 막힐 수 있는 곳은 **업로드 단계 하나**이고,
폴백(Google Fonts `<link>` 1줄)이 **코드 한 줄 차이**라 위험이 잘 격리돼 있다.
→ **①에서 이미지 15장을 올릴 때 폰트 2개를 같이 올려 한 번에 판정하라.** 별도 왕복 0회.

## d-2. 이미지 — **`ds/image/` 평면 유지. 홈과 다르게 판정한다**

홈에서 나는 `/web/upload/` 를 권했다. **여기서는 그러지 않는다.** 조건이 다르다:

| | 홈 | **브랜드 스토리** |
|---|---|---|
| 장수 | **86** | **15** |
| 새 폴더 (설계 원안) | **5개** ← 반려 사유였다 | **0개** ← 이미 옳다 |
| 적용 전 검증 불가의 무게 | 86장을 못 본 채 적용 | 15장. **적용 후 30초 확인으로 충분** |
| `/web/upload/` 의 부작용 | 적음 | **NNEditor 가 639~640px 축소본을 따로 만든다**(칼륨 자기정정 101장 확인). 이 페이지 커버는 **1400~1920px** 이라 축소본이 섞이면 화질이 무너진다 |
| 버전관리 | — | 스킨에 두면 git ↔ 전달본 ↔ md5 체계 안에 들어온다 |

**⇒ 설계서 판정 유지.** `ds/image/` 평면 `bs-*.webp` 15개, 새 폴더 0개. 파일명 규칙도 적절하다.
설계서가 차선으로 `/web/upload/` 를 두면서 **"PC 원본 경로가 실제로 200 인지 개발이 먼저 확인한 뒤에"** 라고 단서를 단 것도 옳다.

**지도 1장 PNG→무손실 WebP(353,920 → 198,392 B, −44%)** 도 타당하다 — 알파 보존 + 국경선·글자 무손실.
**14장 재압축 안 함(재인코딩 시 오히려 커짐)** 도 옳다.

## f-1. ★ 번들 순서 — `brand-story.html` 의 `@css` 는 **번들 1번**이 된다

칼륨·홈에서 확정한 규칙: **① 콘텐츠 페이지의 직접 선언(줄 순서) → ② 레이아웃 → ③ import.**

`brand-story.html` 은 **`@css` 를 자기가 처음으로 선언하는 페이지**다(다른 콘텐츠 `@css` 가 없다).
→ `ds/css/brand-story.css` 는 **사용자 CSS 번들 1번** = `layout/basic/css/*` 17개, `moa/css/*` 전부보다 **앞**.
→ **동률 싸움에서 전부 진다.**

`.zgbs` 래퍼(+1 class)가 대부분을 커버하지만, 스킨의 **맨몸 요소 셀렉터**(`li` 71 · `img` 42 · `h2` 15 · `h3` 13 · `ul` 13 · `p` 10)와 붙었을 때
`.zgbs h2`(0,1,1) vs `h2`(0,0,1) → **우리가 이긴다** ✅. 문제는 스킨 쪽이 `.foo h2`(0,1,1) 같은 동률일 때다.
→ **요구: `.zgbs` 접두를 예외 없이 전 셀렉터에 적용**(설계서 §4-2-1 이 이미 그렇게 썼다. **「예외 없이」를 명시적 검수 항목으로**).
→ 그리고 **`!important` 164개는 우리가 이길 수 없다.** `.spec` 개명처럼 **충돌 클래스는 이기려 하지 말고 회피**하는 설계서 방침이 옳다.

## f-2. ★ **안2(게시판) 기각 근거가 틀렸다 — 판정은 유지, 근거는 교체하라**

설계서 §1-3: *"게시판 본문은 카페24가 `<img>` 를 `ec-data-src` 로 바꾼다(**이벤트 페이지 실측 6장**)."*

**그 실측은 「이벤트」에서 얻은 것이고, 「게시판」에는 적용되지 않는다.** 내가 직접 쟀다:

| 페이지 | `ec-data-src` |
|---|--:|
| 이벤트 `/event/detail.html?product_no=93` | **6** |
| 상품 상세 `?product_no=11` | **14** |
| **게시판 `/board/gallery/list.html?board_no=8` (복용법)** | **0** |

**게시판은 이미지 함정이 없다. 게다가 고유 `<title>` 을 갖는다** —
`젠제네틱스 복용법 총정리 | 붓기부스터·퍼포먼스부스터·칼륨·마그네슘·비타…` (§c-1 표).
즉 **설계서가 가장 무겁게 든 기각 사유가 안2 에는 성립하지 않고, 오히려 안2 만 §(c)의 `<title>` 문제를 해결한다.**

**그래도 안1 이 옳다.** 남는 기각 사유가 여전히 결정적이기 때문이다:
1. **URL** — 게시판 글은 `?board_no=8&no=NN`. 브랜드 페이지 주소로 못 쓴다
2. **껍데기** — 제목·작성자·목록/이전글·댓글을 지울 수 없다
3. **통제권** — `<style>`/`<script>` 가 관리자 에디터 필터에 달려 있다. 우리가 못 본다
4. **버전관리** — git ↔ 전달본 ↔ md5 체계 밖. **되돌릴 수 없다**

**요구: §1-3 안2 문단을 위 4가지로 다시 쓰고, 「이벤트 6장」을 게시판 근거로 쓰지 마라.**
그리고 **`<title>` 을 포기한다는 트레이드오프를 §1-3 에 명시하라** — 지금은 그 대가가 문서 어디에도 없다.
